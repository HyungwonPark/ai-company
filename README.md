# ai-company

사용자는 PM과 목표·계획을 정하고, 여러 코딩 에이전트가 구현·검사·독립 검수·수정을 이어서 수행하는 작업 시스템을 구축합니다. 에이전트의 실행 조건·역할·격리를 관리하는 하네스와 작업 완료까지 이어지는 루프를 함께 만듭니다.

**현재 위치: 기본 구조와 화면·작업 흐름 구현을 갖추고, 실제 모델을 연결한 전체 흐름 검증 중입니다. 지금은 Claude 검수의 사후 정산·수동 재개 결함을 보완하는 단계입니다.**

기준일: **2026-09-28 KST**. 아래 구현 상태는 개발 후보와 검증 기록을 기준으로 하며, 모든 변경이 main에 병합되거나 운영에 적용됐다는 뜻은 아닙니다. 이 README 갱신은 [문서 PR #23](https://github.com/HyungwonPark/ai-company/pull/23)에서 관리합니다.

## 현재 보존하는 상태

- PR #35의 실제 Claude 최종 판정은 미완료입니다. 서버 보고상 변경 파일 13개는 읽었지만 완료 인정 0개·남은 13개입니다.
- 이번 Claude 예약·계정 UNKNOWN과 과거 E2의 `hold_unknown`은 별개 사건입니다. 시간 경과만으로 해제하지 않습니다.
- 두 worker 중지, 기존 quota 타이머, 원본 기록·기존 서비스와 PR #10 pending을 유지합니다.
- **이번 PR 검수는 수동 1회 재개 방식**입니다. 검수 전용 자동 재개 타이머는 설치·활성화하지 않습니다. 제품의 일반 한도 대기·이관 기능과 구분합니다.
- 과거에 성공한 실제 모델 호출·검수 이력은 보존합니다. 현재 후보의 미완료를 프로젝트 전체가 실제 모델을 한 번도 사용하지 않았다는 뜻으로 해석하지 않습니다.

운영 상태·비공개 실행 원문은 서버 제출 보고이며, Work가 현재 서버를 직접 조회한 결과는 아닙니다.

## 토큰 절약과 작업 단위

**앞으로는 작은 수정마다 지시를 끊지 않고, 같은 목표에 속한 관련 작업을 조금 더 넓게 묶어 한 번에 마무리합니다.** Work PM은 완료 조건과 승인 범위를 함께 제시하고, 서버 Codex는 그 범위 안에서 조사·구현·검사·지적 수정·문서화·패키징까지 이어서 처리합니다.

- 기본 개발 설정은 **GPT-6 Sol / High**입니다. 단순 문서·문구는 Medium 또는 사용 가능한 Luna, 어려운 정산·권한·복구 구간만 Extra High를 사용합니다.
- 파일 한 개나 수정 한 줄마다 중간 승인을 요청하지 않습니다. 같은 원인·완료 조건의 결함과 인접 경계를 모아서 처리하고, 새 운영 승인은 검토 가능한 적용·복구안까지 준비한 뒤 한 번에 요청합니다.
- 개발 중에는 관련 검사부터 수행하고, 안정화한 최종 후보에서 필수 전체 검사·CI·독립 검수를 수행합니다. 코드나 위험이 바뀌지 않은 검사를 반복하지 않습니다.
- 최신 목표·기준 SHA·미해결 항목·완료 조건만 먼저 읽습니다. 과거 긴 보고서와 정상 로그 전문은 필요할 때만 조회하며, 원문은 삭제하지 않습니다.
- 서로 무관한 기능을 한꺼번에 추가하지 않습니다. 토큰 절약 때문에 필수 Claude 검수·정산·중복 방지·운영 승인 조건을 생략하지 않습니다.
- 한 번의 지시가 모델 호출 한 번을 뜻하지는 않습니다. 절약률을 측정하지 않았으며, 이 문서만으로 실제 서버 모델 설정이 바뀌지는 않습니다.

세부 규칙은 [서버 Codex 개발 효율 공통 지침](docs/work-reviews/server-codex-efficiency-policy.md)에 모읍니다.
