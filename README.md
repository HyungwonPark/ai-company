# ai-company

사용자는 PM과 목표·계획을 정하고, 여러 코딩 에이전트가 구현·검사·독립 검수·수정을 이어서 수행하는 작업 시스템을 구축합니다. 에이전트의 실행 조건·역할·격리를 관리하는 하네스와 작업 완료까지 이어지는 루프를 함께 만듭니다.

**현재 위치: 기본 구조와 화면·작업 흐름 구현을 갖추고, 실제 모델을 연결한 전체 흐름 검증 중입니다. PR #37의 R37-1~3 해결과 비운영 보완을 수용했고, 서버는 승인된 한정 설치 완료를 보고했습니다. 현 timeout의 종료·전체 사용량은 여전히 미확정이며, 다음 과제는 복구 절차의 비운영 설계입니다. 실제 Claude 검수는 미완료입니다.**

기준일: **2026-09-29 KST**. 아래 구현 상태는 개발 후보와 검증 기록을 기준으로 하며, 모든 변경이 main에 병합되거나 운영에 적용됐다는 뜻은 아닙니다. 이 README 갱신은 [문서 PR #23](https://github.com/HyungwonPark/ai-company/pull/23)에서 관리합니다.

## 지금 진행할 작업

수용한 비운영 [PR #37](https://github.com/HyungwonPark/ai-company/pull/37) 후보는 `e659fc66cadfb5af77f85327314671b46a0383e0`입니다. 제품 실제 Claude 검수 대상 PR #35 `1d54d3a0ea5a21c7c2dc588f824c6567231829b4`와 기존 설치 후보 PR #36 `7ab7681`을 구분합니다.

- **R37-1~3 해결:** 중간 설정 실패·충돌의 우회와 선언/응답 연결 문제를 차단하고, 정상 Workflow 완료를 원문 종류와 일치할 때만 재확인합니다. 기존 합성 재현으로 해결을 확인했습니다.
- **검증과 적용:** 관련 검사 56개·최종 HEAD CI 3개 성공, 패키지 SHA-256·내부 네 파일 소스 일치를 확인했습니다. 서버는 세 파일·전환 기록 교체와 설치 검증 통과를 보고했으며 적용 후 해시는 수용 기록과 일치합니다. 모델·tick·새 예약은 0건입니다. Work가 서버를 직접 조회한 결과는 아닙니다.
- **다음 묶음:** 기존 기록에서 추가 종료 증거를 찾지 못한 결과를 확정하고, 일반 timeout의 종료 확인·비용 정산·계정 복구·같은 HEAD의 후속 시도를 분리한 비운영 복구안을 준비합니다. 새로운 출처 없는 동일 검색을 반복하지 않습니다. 현재 코드는 quota 전용 재개만 지원합니다.
- **현 예약:** UNKNOWN·미정산과 실제 완료 인정 0/13, 주 호출 관측 비용 USD 4.46·총사용량 미확정을 유지합니다. 설치만으로 정산·계정 해제·재호출이 허용되지 않습니다.

[PR #37 설치 완료 보고·timeout 복구 설계](docs/work-reviews/pr37-applied-timeout-recovery-2026-09-29.md)를 현재 지침으로 적용합니다. [수용·한정 적용안](docs/work-reviews/pr37-acceptance-e659fc6-2026-09-29.md)과 [이전 보완 3건 재현](docs/work-reviews/pr37-review-0f023b7-2026-09-29.md)은 당시 근거로 보존합니다.

## 현재 보존하는 상태

- PR #35의 실제 Claude 최종 판정은 미완료입니다. 서버 보고상 변경 파일 13개는 읽었지만 완료 인정 0개·남은 13개입니다.
- 직전 예약의 정산은 보존하며, 이번 timeout의 새 예약과 연결 계정 UNKNOWN은 별도로 복구해야 합니다. 과거 E2의 `hold_unknown`도 유지하며 시간 경과만으로 해제하지 않습니다.
- 두 worker 중지, 기존 quota 타이머, 원본 기록·기존 서비스와 PR #10 pending을 유지합니다.
- **이번 PR 검수는 수동 1회 재개 방식**입니다. 검수 전용 자동 재개 타이머는 설치·활성화하지 않습니다. 제품의 일반 한도 대기·이관 기능과 구분합니다.
- 과거에 성공한 실제 모델 호출·검수 이력은 보존합니다. 현재 후보의 미완료를 프로젝트 전체가 실제 모델을 한 번도 사용하지 않았다는 뜻으로 해석하지 않습니다.

운영 상태·비공개 실행 원문은 서버 제출 보고이며, Work가 현재 서버를 직접 조회한 결과는 아닙니다.

## 후속 설계: 작업 특성에 따른 역할 선택

사용자 동의에 따라 **작은 작업은 개발 역할 한 개로 수행하고, 독립 산출물이 있는 작업만 병렬화**하는 방향을 확정했습니다. 개발 역할 수와 필수 독립 검수는 구분합니다. 현재 제품 후보는 최소 2개 독립 역할을 요구하므로 **제품 반영은 아직 미완료**입니다.

현재 PR #35 검수의 timeout 복구 절차를 먼저 마무리하고, 수용된 제품 기준에서 별도 후속 PR로 계획 계약·PM 지시·단일 역할 실행·기록 호환을 함께 보완합니다. 기존 고정 후보·패키지와 운영 승인·수동 재개 조건은 유지합니다.

완료 작업당 사용량·소요 시간·재검수·사용자 복구 개입을 기존 기록으로 측정합니다. 상세 범위와 수용 기준은 [역할 선택·후속 구현 지침](docs/work-reviews/adaptive-orchestration-policy-2026-09-28.md)에 있습니다.

## CLI 세션과 프로젝트 연속성

**같은 작업에서는 기존 개발 세션을 활용하고, 목표·완료 조건·코드·증거·공식 상태는 세션 밖에 보존합니다.** 단순 재시작 후 resume는 기존 대화를 복원하므로 그 자체가 토큰 절약은 아닙니다. 작업이 끝나고 다음 목표가 달라질 때 짧은 인계 후 새 개발 대화를 고려합니다. 요약·캐시·재조사 비용까지 측정하기 전 절약률을 단정하지 않습니다.

서버는 기존 화면·로그로 개발 설정과 마지막 요청 사용량을 확인하고 비공개 인계를 준비했다고 보고했습니다. 현재 개발 대화는 유지합니다. 현재 남은 문맥·계정 한도는 미확인이며 실제 검수의 별도 수동 요청 조건을 유지합니다. 제품 실행 세션·예약·UNKNOWN은 개발 대화 정리와 구분합니다. [세션 유지·전환 및 서버 작업 명세](docs/work-reviews/cli-session-lifecycle-policy-2026-09-28.md)를 적용합니다.

## 토큰 절약과 작업 단위

**앞으로는 작은 수정마다 지시를 끊지 않고, 같은 목표에 속한 관련 작업을 조금 더 넓게 묶어 한 번에 마무리합니다.** Work PM은 완료 조건과 승인 범위를 함께 제시하고, 서버 Codex는 그 범위 안에서 조사·구현·검사·지적 수정·문서화·패키징까지 이어서 처리합니다.

- 기본 개발 설정은 **GPT-6 Sol / High**입니다. 단순 문서·문구는 Medium 또는 사용 가능한 Luna, 어려운 정산·권한·복구 구간만 Extra High를 사용합니다.
- 파일 한 개나 수정 한 줄마다 중간 승인을 요청하지 않습니다. 같은 원인·완료 조건의 결함과 인접 경계를 모아서 처리하고, 새 운영 승인은 검토 가능한 적용·복구안까지 준비한 뒤 한 번에 요청합니다.
- 개발 중에는 관련 검사부터 수행하고, 안정화한 최종 후보에서 필수 전체 검사·CI·독립 검수를 수행합니다. 코드나 위험이 바뀌지 않은 검사를 반복하지 않습니다.
- 최신 목표·기준 SHA·미해결 항목·완료 조건만 먼저 읽습니다. 과거 긴 보고서와 정상 로그 전문은 필요할 때만 조회하며, 원문은 삭제하지 않습니다.
- 서로 무관한 기능을 한꺼번에 추가하지 않습니다. 토큰 절약 때문에 필수 Claude 검수·정산·중복 방지·운영 승인 조건을 생략하지 않습니다.
- 한 번의 지시가 모델 호출 한 번을 뜻하지는 않습니다. 절약률을 측정하지 않았으며, 이 문서만으로 실제 서버 모델 설정이 바뀌지는 않습니다.

세부 규칙은 [서버 Codex 개발 효율 공통 지침](docs/work-reviews/server-codex-efficiency-policy.md)에 모읍니다.
