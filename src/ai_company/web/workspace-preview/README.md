# 작업실 미리보기

PR #14의 프로젝트 스킬과 설계 문서를 적용한 **예시 전용** 구조 비교입니다. PR #13의 운영 화면·API를 교체하지 않습니다.

| 시안 | 중심 | 공통 조작 |
|---|---|---|
| A 작업실 · 추천 | PM 질문과 답변, 옆의 팀·결정 요약 | 프로젝트 → PM → 명세 → 계획 → 진행/승인/보고 |
| B 작업대 | 역할별 행, 현재 일과 산출물 전달 | 같은 데이터·같은 조작 |
| C 결정함 | 요청 목록과 읽는 문서 | 같은 데이터·같은 조작 |

Light/Black은 각 시안에서 전환합니다. 상단 `상태`에서 빈 목록·PM 대기·응답 유실·연결 끊김·장문·번역 대기·읽기 권한·잘못된 링크를 확인할 수 있습니다.

## 열기

CI의 `workspace-preview` 산출물에서 내려받은 `AI-Company-preview.html`을 브라우저로 엽니다. 별도 서버·로그인·설치가 필요 없고 외부 리소스를 요청하지 않습니다. GitHub 산출물은 보관 기한 30일이므로 이후에는 아래 명령으로 같은 소스에서 생성합니다.

```bash
python3 scripts/package_workspace_preview.py /tmp/AI-Company-preview.html
```

소스 상태로 보려면 저장소 루트에서 `python3 -m http.server 8790 --bind 127.0.0.1 --directory src/ai_company/web`를 실행한 뒤 `http://127.0.0.1:8790/workspace-preview/`를 엽니다. 이 서버는 파일만 제공하며 관리 API를 연결하지 않습니다.

## 눌러보기

1. `프로젝트` → `새 프로젝트`에서 이름·자연어 목표 → `PM과 시작`.
2. 예시 제안에서 역할·파일·검사·예산 확인 → `명세 저장`. 실행 0건.
3. `새 계획 요청` → `계획 검토` → 확인 항목 선택 → `계획 확정`. 예시 실행 1건.
4. `진행`에서 고정한 명세와 예정된 역할 확인. 실제 모델 호출이나 작업은 시작되지 않습니다.
5. 처음의 `역할 상태 확인` 프로젝트에서는 이전 예시 실행의 전달물·한도 대기·별도 후보를 읽습니다. `승인`에서 선택해도 미리보기의 선택 영수증만 추가되며 원본 `pending`은 유지합니다.

시안 전환은 같은 상태를 유지합니다. `예시 초기화`는 이 탭의 예시 상태만 지웁니다. 일반 새로고침은 작성 중 입력·초점·미확정 요청을 보관합니다. 응답 유실 시 입력을 변경했더라도 `저장 결과 확인`으로 처음 보낸 요청을 먼저 해결합니다.

## 경계

- 데이터의 프로젝트·모델·커밋·전달·검수·한도·digest는 모두 설명용입니다. 운영 조회 결과가 아닙니다.
- `model.js`는 UI 의미와 복구를 시험하는 임시 모델입니다. 실제 `PlanConfirmationInput`/`DecisionInput`의 전송 어댑터나 서버 보안 구현이 아닙니다.
- 실제 연결에서는 `base_harness_version`, 명세·계획·승인 digest, 읽기용 번역 참조, 세션/CSRF, 서버의 적격성·예산·출처 검증을 기존 API 그대로 사용해야 합니다. 미리보기의 `reviewed` 등은 화면 확인용이며 서버 권한이 아닙니다.
- 입력은 이 탭의 `sessionStorage`에만 보관합니다. 저장 기능을 제공하지 않는 브라우저에서는 화면 내 상태만 유지됩니다. 새 탭·새 세션에는 이어지지 않으므로 민감한 실데이터를 입력하지 마세요.
- 운영 배포·병합·실제 마스터 계획 확정·APK 기기 검증·서명키 외부 복원은 수행하지 않습니다.
