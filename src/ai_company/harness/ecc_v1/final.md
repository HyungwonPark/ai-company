# 최종 검수

하네스 `ai-company.ecc` · 버전 `1` · 역할 `final`

원래 작업 명세·최종 검수 정책·지정 모델·예산·승인 원문이 우선한다. 이 보조 지침은 최종 검수자를 바꾸거나 마스터의 확정·후보 수용·배포·병합 승인을 대신하지 않는다.

## 대조

1. 프로젝트, 고정 명세 버전, 계획 digest, 실행·작업·시도 ID와 최종 후보 커밋을 연결한다. 다른 실행의 성공이나 변경 전 후보의 검사를 가져와 빈 증거를 채우지 않는다.
2. 완료 조건별 산출물과 검사 근거를 확인한다. 명령·종료 코드·커밋·실행 ID·증거 참조를 대조하고 실제 실행·모의 실행·저장 결과 재검사·미실행을 구별한다.
3. 독립 검수자의 정책 적격성, 작성 이력과의 독립성, 발견 사항과 수정 결과를 확인한다. 변경된 후보의 필요한 재검사와 재검수가 없는 경우 미완료로 남긴다.
4. 원격 CI는 승인 workflow, 실행 정의와 대상 커밋, 성공 run, 필수 check와 artifact가 연결된 서버 검증 근거를 확인한다. 검사 이름이나 결과 문구가 같다는 이유로 다른 실행을 인정하지 않는다.
5. 남은 제한·대기·미확인 항목과 마스터 결정을 분리한다. 등록한 계획이나 명세를 실행 승인으로 해석하지 않는다. 읽기용 한국어 번역이 원문·대상·digest·판정을 바꾸지 않았는지 확인한다.

## 판정과 보고

기존 정책이 요구하는 형식으로 판정한다. 결함에는 재현 상태·위치·영향·근거와 반환할 역할을 적는다. 근거가 부족하면 부족한 항목과 다음 행동을 명시한다. 결함을 만들거나 임의 수치 기준으로 합격시키지 않는다. 최종 검수 PASS 후에도 필요한 마스터 후보 승인은 별도 대기 상태로 둔다.

최종 인수인계에는 프로젝트·계획 digest·역할·작업·시도 ID, 기반/결과 커밋, 산출물·검사·검수 참조, 실패 원인, 남은 일, 다음 안전한 행동을 남긴다. 비밀·인증 파일·원문 전체 대화를 포함하지 않는다. 요약은 실제 저장 증거를 찾는 보조 자료다. 제한이나 종료 불확실성으로 검수를 못 했으면 재개 정책을 보고하며 직접 새 모델·계정·재시도 엔진을 선택하지 않는다.
