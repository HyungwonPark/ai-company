## 교체와 복구

사용자 승인에 따라 준비된 archive·이미지·Compose·unit·카탈로그 해시와 실제 가동 설정을 대조했다. 기존 PM 요청은 완료, 실행 두 건은 차단·승인 대기였고 새로 재개할 작업이나 active 모델 자식 프로세스는 없었다. 새 release와 카탈로그를 별도 경로에 설치하고 설치된 Python 패키지 파일을 고정 archive와 대조했다.

PM/조정기를 정상 종료하고 자식 프로세스 부재를 확인한 뒤 웹을 정지했다. 이 구간에는 새 웹 요청을 받지 않았다. 변경 전 Compose·automation unit과 감사용 DB 사본을 비공개로 보존한 뒤, 웹 컨테이너와 automation unit만 교체했다. 번역 unit·환경변수·전역 release symlink·Caddy·타이머는 변경하지 않았다. 새 웹 접속과 worker heartbeat를 확인하고 기존 모든 DB 행을 대조했다. 복구는 발생하지 않았다.

비공개 작업 기록은 이 작업트리의 `.ai-company/project-execution-activation-20260916/`에 있다. 감사용 DB 사본은 **복원에 쓰지 않는다**. 실패 시 [고정 복구 조건](project-execution-specs-2026-09-16.md#복구-조건)을 따른다. 새 명세에 연결된 요청·계획·실행이 있으면 구 웹·구 automation을 단순 재시작하지 않고 자동 실행을 멈추되 현재 호환 관리·보고·승인 화면과 원장을 보존한다.

## 마스터가 할 일

현재 새 검증 프로젝트를 대신 생성하지 않았다. APK 0.1.1은 웹을 여는 기존 앱을 사용하며 APK를 다시 빌드하거나 서명키를 변경하지 않았다.

1. APK를 완전히 닫았다가 온라인으로 열어 **hyungwon.cloud**에 접속한다. 로그인이 나오면 **edward**와 기존 비밀번호를 입력한다. 프로젝트 선택 영역의 **전체**를 누르거나 브라우저에서 https://hyungwon.cloud/#projects 를 열고 **새 프로젝트 +**를 누른다.
2. 이름 예시 **역할 상태 확인**. 목표 예시: **“역할 상태를 진행·대기·차단·완료·알 수 없음으로 집계하는 기능을 만들어 주세요. 개발과 테스트를 두 역할로 나눠 병렬로 진행하고, 빈 입력·알 수 없는 상태·입력 보존을 확인해 주세요. 기존 pilot 범위와 예산을 유지하세요.”** **PM과 시작**을 누른다. 이 버튼은 개발 실행이나 계획 확정이 아니다.
3. 매니저에서 실제 PM 제안을 기다리고 역할·완료 조건을 읽는다. **실행 범위 확인** 또는 프로젝트 선택 영역의 **설정**에서 **실행** 상세를 펼쳐 기존 pilot 범위·모델·예산을 확인한 뒤 **명세 저장**을 누른다. 명세 저장만으로 개발을 시작하지 않는다.
4. **PM에게 새 계획 요청**을 누르고 새 PM 계획이 도착하면 **계획 검토·확정**을 연다. 역할·허용 범위·완료 조건·명세 버전을 읽고 확인 항목을 체크한 뒤 **이 계획 확정**을 직접 누른다.
5. 확정 후 **프로젝트 이름 또는 링크**를 서버 Codex에 전달한다. 서버는 확정 이벤트·계획 digest·명세 버전·실행 ID 하나를 기준으로 병렬 개발→격리 검사→원격 CI→독립 검수→Astra 최종 검수→보고·승인 요청을 대조한다. 새 후보 승인도 **pending**으로 둔다.

입력/클릭을 기다리는 동안 같은 운영 사전 점검을 반복하거나 새로운 개발 목표를 추가하지 않는다. 사용자 확인 뒤 발생하는 새 실행 상태만 대조한다. 서명키의 외부 보관·복원은 별도 마스터 확인 항목이며 아직 완료되지 않았다.
