# 순서형 사용성 독립 검수

검수자: 별도 `usability_review` 에이전트. 제품 구현 파일을 수정하지 않고 PM 실행 지시 U1~U3, 실제 제품 함수, 독립 회귀 시나리오, 격리 Chrome 결과와 캡처를 대조했다. `ai-company-frontend`와 `code-review-skill`을 적용했다. 스킬 사용 자체를 통과 근거로 세지 않았다.

## 검수 과정에서 반환한 문제

- 공통 상태 배지가 이미 한국어인 worker 상태를 미확인으로 덮는 문제: 원래 한국어 표시를 유지하도록 수정했다.
- 과거 실행에 연결된 PM 보고가 현재 계획 집계와 다르다는 이유로 없는 것으로 표시될 수 있던 문제: 정확한 실행의 보고 문서와 참조를 대조하도록 수정했다. 다른 프로젝트·실행·계획 해시의 문서와 참조를 거부하는 독립 검사를 추가했다.
- 본문 건너뛰기가 `#main` 경로를 프로젝트 목록으로 해석해 선택 실행을 바꾸던 경계: 이동 이벤트에서 주소를 보존하고 본문에만 초점을 옮기도록 수정했다. 초기 Chrome 키보드 캡처에서도 프로젝트 목록으로 이동한 모습이 확인된다.
- 알 수 없는 상태 문자열에 RUNNING/WAITING 등이 포함되면 알려진 상태색을 부여하던 경계: 등록된 상태에만 시각 분류를 적용했다.
- 접힌 시스템 집계에서 별도의 통합·worker 차단 근거가 누락된 문제: compact 모드에서도 해당 근거와 원래 집계 digest를 보존했다. 실제 함수의 최초 실패와 수정 후 성공을 기록했다.

## 독립 검사 범위

- 원래 상태·기한·digest를 바꾸지 않고 만료 전/정확 경계/만료 후, 이미 처리한 요청, 알 수 없는 상태를 실제 표시 함수로 검사했다. 서버가 `approved`도 기한 경과 시 `expired`로 투영하는 기존 계약과 대조했다.
- 실제 임시 API의 프로젝트·실행·승인 자료로 진행 → 결과 → 해당 실행 요청 없음 → 프로젝트 전체 요청 → 연결된 과거 실행 → 결과 → 뒤로 가기를 검사한다. 읽기 과정에서 업무 POST가 발생하지 않아야 한다.
- 결과 요약, 0건 포함 역할 집계, 펼칠 수 있는 원문, 시스템 집계와 PM 보고 출처를 검사한다.
- 같은 원본 fixture·폭·테마·접힘 상태로 `dec455e` ZIP과 새 패키지를 비교한다. 예시의 만료 기한을 연장하지 않는다.
- 실제 Chrome에서 Light/Black × 320/390/1440, 장문·빈 상태·오류·대기·미확인·반려, 키보드, Chrome CDP 200% pinch 확대를 검사한다. 물리 Android 확대 검증으로 보고하지 않는다.
- 별도의 Chrome 시계만 API fixture의 원래 기한 전후로 이동한다. 확인 대화상자를 연 상태에서 자동으로 제출이 비활성화되고, 목록과 상세가 만료로 일치하며, 새로고침 후에도 상태가 유지되는지 검사한다. 실제 승인 결정은 제출하지 않는다.
