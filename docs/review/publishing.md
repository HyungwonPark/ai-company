# 작업 현황 페이지의 고정 주소와 갱신 명세

기준일: 2026-09-29 KST · 사용자 요청에 따른 문서 정리·페이지 제안  
**Git 원본은 준비하며 도메인 페이지는 아직 배포하지 않았습니다.** 사용자는 매뉴얼형 정리에 동의했고 `hyungwon.cloud/review` 경로 사용을 제안했습니다. 이 문서는 그 방식의 구현·배포 준비 범위를 구체화합니다.

## 링크의 역할

| 용도 | 제안 주소 또는 실제 원천 | 갱신 방식 |
| --- | --- | --- |
| 매일 확인할 현황 | `https://hyungwon.cloud/review` | 주소 고정, 최신 게시 내용 갱신 |
| 운영·개발 매뉴얼 | `https://hyungwon.cloud/review/manual` | 주소 고정, 절차 변경 시 갱신 |
| 해당 시점의 근거 | GitHub의 전체 커밋 SHA + 파일 경로 | 기존 링크와 내용을 보존 |
| 과거 기록 찾기 | 현황 페이지의 기록 영역 | 고정 기록 링크를 추가 |

처음에는 별도의 과거 페이지 저장소를 만들지 않고 Git의 고정 링크로 충분히 보존합니다. 이후 같은 사이트에서 과거 HTML까지 볼 필요가 생기면 `/review/history/<문서 커밋>`에 당시 산출물을 보존합니다. 없는 주소를 이미 동작하는 링크처럼 표시하지 않습니다.

페이지 도입 전의 실제 고정 진입점은 [Git 현황](https://github.com/HyungwonPark/ai-company/blob/docs/work-review-handoff/docs/review/index.md)과 [Git 매뉴얼](https://github.com/HyungwonPark/ai-company/blob/docs/work-review-handoff/docs/review/manual.md)입니다. 이 브랜치의 최신 내용을 표시하므로 당시 승인·검수 근거에는 커밋 고정 링크를 사용합니다. 문서 브랜치를 이동하거나 정리하기 전에는 이 진입점의 안내도 유지·이관합니다.

GitHub 공식 문서는 브랜치 링크의 내용은 갱신될 수 있고, 커밋 ID를 넣은 링크는 해당 버전을 가리킨다고 설명합니다. 근거: [GitHub 공식 문서 — 파일 영구 링크](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files), A급 공식 출처.

## 원본과 화면

- 변하는 현황은 `docs/review/index.md` 한 곳에 작성합니다. README와 기존 목록은 이 페이지로 연결하고 상태 문단을 중복 관리하지 않습니다.
- 절차·역할은 `docs/review/manual.md`, 공개 가능한 상세 근거는 기존 `docs/work-reviews/`에 둡니다.
- 이 Markdown 원본에서 HTML을 생성합니다. 별도의 HTML 본문을 사람이 이중 갱신하지 않습니다.
- 화면에는 문서 기준일, 마지막 반영한 관측/보고 시각, 문서 커밋, 실제 대상 코드 커밋을 구분해 표시합니다. 빌드·배포 시각이 서버 관측 시각을 갱신하지 않습니다.
- 직접 검증·서버 보고·미확인을 표시하고 마지막 반영 기준의 정적 문서임을 알립니다. 기록 조회가 모델·tick·장부 변경을 일으키지 않게 합니다.
- 기능별로 구현·자동 검사·실제 검수·설치를 별도 표시합니다. 근거 없는 전체 완료율은 만들지 않습니다.

첨부 AI-COP 매뉴얼의 고정 목차·표·상태 표시·주의사항 배치를 참고하되 해당 원문·접근 정보는 복제하지 않습니다. 현재 요약을 먼저 두고 긴 변경 이력은 뒤로 보냅니다. 모바일에서도 목차에 접근할 수 있게 하며 상태는 색상과 글자로 함께 표시합니다.

## 작업마다 갱신하는 절차

1. 작업 결과를 확인하고 기존 공식 원천을 대조합니다. 모델에게 매번 과거 문서 전체를 다시 요약시키지 않고 변경된 상태와 근거를 갱신합니다.
2. 당시 기록은 고정 파일·커밋으로 보존하고 현황 원본의 관련 행·다음 행동·보고 시각만 수정합니다. 절차가 바뀐 경우에만 매뉴얼도 수정합니다.
3. 링크·문서 표시·공개 범위를 확인해 한 문서 커밋으로 제출합니다. 여러 세션이 갱신하면 최신 원격 기준에서 차이를 합치고 과거 상태로 덮어쓰지 않습니다.
4. 지정한 문서 커밋으로 정적 HTML과 배포 메타데이터를 생성합니다. 외부 JS 실행이나 모델 호출 없이 재현 가능한 빌드로 준비합니다.
5. 승인된 게시 경로에서 검증된 산출물 전체를 교체합니다. 기존 버전을 보존해 실패하면 이전 산출물로 되돌립니다. 생성·검증 실패 시 현재 게시본을 유지합니다.
6. 최종 주소에서 실제 표시된 문서 커밋·내용을 대조한 뒤 게시 완료로 보고합니다. Git 커밋 완료와 페이지 게시 완료를 분리합니다.

작업 보고는 **늘 같은 현황 링크 + 해당 작업의 고정 근거 링크**면 충분합니다. 브랜치 링크의 내용을 나중에 읽고 과거에 승인한 범위를 추정하지 않습니다.

## 서버의 비운영 준비 묶음

기존 timeout 복구 작업의 상태·소유권·기준 후보를 보존합니다. 이 문서 페이지는 별도 문서 변경으로 준비하며 현재 검수기 패키지를 변경하지 않습니다.

1. `hyungwon.cloud`의 현재 라우팅·정적 파일 제공·로그인·권한·기존 메뉴 구조를 읽기 점검합니다. 서버·프록시 종류나 현재 경로의 미사용 여부를 추정하지 않습니다.
2. 기존 웹 배포 방식에 맞는 최소 정적 페이지 후보를 준비합니다. 첫 버전은 읽기 전용 현황·매뉴얼·근거 링크이며 CMS·새 DB·실시간 수집·승인/실행 버튼을 추가하지 않습니다.
3. 저장소의 관련 화면 지침을 읽고 데스크톱·모바일에서 목차·표·링크·상태 표시를 확인합니다. 하위 경로의 직접 접속·새로고침, 자산 경로와 기존 작업실 라우트 충돌을 검증합니다.
4. 기존 인증·권한이 페이지와 HTML/정적 자산에 실제로 적용되는지 확인합니다. 현재 인증이 없거나 노출 범위가 다르면 공개 가능한 요약만 포함한 후보로 두고 사실을 보고합니다. 토큰·운영 장부·비공개 기록을 브라우저나 정적 자산에 넣지 않습니다.
5. 초기 게시할 정확한 문서 커밋·산출물 해시·변경할 경로/설정·백업·복구·확인 방법을 제출합니다. 실제 서비스 변경은 해당 범위의 기존 승인이 있는지 대조하고, 없으면 준비된 적용안만 최종 판단 대상으로 올립니다.

초기에는 검토한 문서 커밋을 지정해 게시하는 방식으로 시작합니다. 반복 게시 자동화는 공개용 문서 경로·게시 대상·검증·복구 범위가 정해진 뒤 연결합니다. PR #23의 모든 초안 push를 무조건 운영에 게시하도록 만들지 않습니다. 제품 코드의 병합·배포 흐름과 문서 게시 흐름을 분리합니다.

## 완료 조건

| 항목 | 확인 기준 |
| --- | --- |
| 고정 주소 | 최신 게시 후에도 같은 주소로 새 내용 확인 |
| 근거 보존 | 과거 작업 링크는 당시 후보·판정 그대로 확인 |
| 상태 정확성 | 보고 시각·확인 종류·검수/설치 구분이 원본과 일치 |
| 접근 범위 | 경로·하위 파일의 인증·공개 범위 확인, 비공개 값 제외 |
| 기존 서비스 | 기존 작업실 경로·로그인·정적 자산의 회귀 없음 |
| 복구 | 이전 게시본으로 되돌리고 문서 커밋 대조 가능 |
| 실행 경계 | 페이지 보기·갱신으로 모델·tick·새 예약·장부 변경 없음 |

정적 사이트 배포 자동화가 아직 없는데 매 작업 자동 갱신된다고 안내하지 않습니다. 준비·게시·검증 상태를 나눠 보고합니다.
