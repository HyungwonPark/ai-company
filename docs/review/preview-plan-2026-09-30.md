## 화면과 범위

현황을 먼저 읽고 필요할 때 매뉴얼·고정 근거로 이동합니다. 문서형 본문과 목차를 사용하며 제목은 현황·매뉴얼·목차·버전으로 짧게 표시합니다. Light·Black 선택, 본문 바로가기, 같은 페이지 목차, 직접 접속·새로고침·뒤로가기를 제공합니다. Markdown은 한 곳에서 작성하고 두 정적 HTML과 다운로드용 미리보기를 생성합니다. Mermaid는 외부 실행 도구 없이 접힌 도식 원문으로 보존합니다. SVG 그림을 생성했다고 표시하지 않습니다.

원본 문서의 기준일·서버 보고 시각·버전·근거 종류를 유지합니다. HTML 생성 시각으로 서버 보고 시각을 바꾸지 않습니다. 설치 기준 코드와 문서 커밋을 별도로 표시합니다. 문서에 담긴 2026-09-29 상태를 실시간 서버 조회로 표시하지 않습니다.

## 접근과 운영 대조

2026-09-30 읽기 점검에서 기존 `/review`와 `/review/manual`은 404였습니다. 기존 웹은 정적 HTML·JS를 비로그인 상태로 제공하고 관리 API는 비밀번호 로그인을 사용합니다. 새 경로도 기존 인증에 자동 연결되지 않습니다. 이번 후보는 **공개 Git에 이미 게시된 두 문서만 공개 제공**합니다. 장부·원문 로그·계정·토큰·비밀번호·서명키·승인 원문은 생성기에 입력하지 않습니다.

기존 Caddy가 두 도메인을 분기합니다. 이미 Caddy에 연결된 데이터 저장소 안의 독립 문서 디렉터리를 활용하면 새 볼륨·컨테이너 교체 없이 정적 산출물과 Caddy 경로만 추가할 수 있습니다. 실제 서버 경로·기존 전체 Caddyfile·해시는 비공개 적용안에 보존합니다. 공개 패키지에는 두 문서에 한정한 일반 경로 조각만 포함합니다.

운영의 서비스워커는 고정된 앱 셸 목록만 처리하며 `/review`와 `/review/manual`은 목록에 없습니다. 실제 운영 버전 `2087eccae3f946bc6d676904462a9b2acabd8521`의 서비스워커 원문을 임시 서버에 연결해 새 문서 경로를 가로채지 않는지 검사합니다. 이것은 실기기·실제 공개 페이지 게시 검증과 구분합니다.

생성기는 지정한 Git 커밋의 두 원본만 읽습니다. 현재 작업 공간의 수정 내용이나 운영 DB를 읽지 않습니다. Markdown 도구는 이미 서버에 있는 `markdown-it-py 3.0.0`을 별도 문서 검사 의존성으로 고정합니다. 운영 제품의 의존성은 바꾸지 않습니다. ZIP은 같은 입력·생성기로 재현 가능합니다. 존재하는 출력 디렉터리를 덮어쓰지 않습니다.

초안 push 전체를 자동으로 운영에 게시하지 않습니다. 후속 게시 범위가 승인되면 문서 커밋을 명시해 생성·검증한 뒤 같은 두 경로의 산출물만 교체할 수 있도록 범위를 정합니다.

## 적용·실패·복구

1. 지정한 문서 커밋, 생성기·스타일·산출물 해시, 현재 Caddyfile·마운트·서비스 상태를 다시 대조합니다. 준비 상태와 다르면 적용 전에 중단합니다.
2. 기존 Caddyfile과 현재 문서 디렉터리 연결값을 백업합니다. 첫 게시 전에는 기존 문서가 없다는 사실도 기록합니다. 패키지는 심볼릭 링크 없이 두 HTML만 새 불변 버전 디렉터리에 풀어 해시를 확인합니다.
3. 같은 파일시스템에서 문서 `current` 연결을 원자 교체합니다. 다른 데이터 저장소 경로를 정적 루트로 사용하지 않습니다. 공개 route 조각을 `hyungwon.cloud`의 기존 기본 프록시 처리 앞에 추가하고 검증합니다.
4. 기존 Caddy의 설정을 무중단 재적용합니다. 웹·worker·DB·장부·검수기는 교체하지 않습니다. 타이머 일정도 바꾸지 않습니다.
5. HTTPS의 두 문서·전체 커밋 표시·시각·헤더·잘못된 하위 경로 거부·기존 로그인·앱 셸·Android 인증서 경로·커플 서비스 응답을 대조합니다. 파일 내용과 문서 커밋이 다르거나 기존 경로 회귀가 있으면 실패입니다.
6. 실패하면 이전 문서 연결과 Caddyfile을 복구·검증한 뒤 재적용합니다. 첫 게시 실패는 새 경로만 제거합니다. 현재 DB·장부를 과거 상태로 덮어쓰지 않습니다. 이 후보에서 운영 복구를 실제 수행했다고 표시하지 않습니다.

최초 운영 승인 대상은 **공개 문서 2개 게시와 기존 Caddy의 문서 경로 추가·설정 재적용 1건**입니다. 문서 페이지의 인증을 필수로 바꾸려면 별도의 접근 계약·구현이 필요하며 현재 후보가 비공개 페이지라고 안내하지 않습니다.
