- 첫 화면에서 프로젝트를 검색하거나 새로 만든다. 이름·목표만 입력하면 PM 요청이 저장되며, 실제 PM 답변은 나중에 표시된다. 실행 가능한 범위가 검증용 두 파일이라는 안내를 생성 전에 읽을 수 있다.

- 진행 화면은 역할 유지와 담당 이관, 실제 전달물과 상세 원장을 연결한다. 요청 모델·추론과 실제 관측을 분리한다. Light·Black 및 모바일의 매니저·진행·승인·기록을 유지한다.

## 독립 검수

서버·프런트·독립 검수를 파일 소유권에 따라 병렬로 진행했다. 독립 검수자는 구현을 쓰지 않고 반례·화면 검사를 추가했다. 발견한 다음 오류를 수정했다.

1. 계획 상태가 실제 실행 상태처럼 표시되던 문제.
2. 같은 커밋의 다른 승인만으로 검수가 끝났다고 안내하던 문제.
3. PM 요청 내부의 `WAITING_CAPACITY/QUOTA`를 응답 작성 중으로 표시하던 문제.
4. 생성 성공 뒤 저장된 의도가 지워지지 않아 다음 생성을 막던 문제.
5. 추가 전달 버튼과 기존 선택자의 충돌, 테마별 확대 검사에서 같은 DOM을 다시 2배 확대하던 검사 오염.

첫 후보 `7b789b8`의 [UI 실패](https://github.com/HyungwonPark/ai-company/actions/runs/35066989278)는 보존했다. 이관의 새 문구와 원장 상세까지 검사하고, 테마마다 새 DOM과 동일한 원래 글자 크기·정확한 2배 확대를 대조하도록 수정했다. 단순히 실패 검사를 제거하거나 CSS로 감추지 않았다.

최종 후보 `28404b2`는 별도 검수자가 코드·원격 로그·두 테마의 대표 화면·전달 상세·200% 확대를 직접 확인해 **검수한 UX·기능 범위에서 통과, 미해결 필수 결함 없음**으로 판정했다. 최종 독립 검수는 서버 Codex의 별도 검수 맥락이다. 제품 안의 실제 개발 실행에서 수행되는 Astra Ultra 최종 검수 호출과 동일하다고 주장하지 않는다.
