# 세 가지 디자인 예시 화면 검증

로그인과 작업 화면을 비교할 수 있는 별도 예시 페이지를 제공한다.

- 접속: https://hyungwon.cloud/design-preview/index.html
- 적용 소스: `8d77da7c20524216359c6d9f5a267edaeadb5784`
- A 편집형: 밝은 단색, 큰 글자, 상단 메뉴와 선을 활용한 배치.
- B 작업 도구형: 어두운 화면, 왼쪽 메뉴, 구획이 분명한 작업 영역.
- C 브랜드형: 코발트색과 큰 워드마크, 밝은 작업 영역.

상단에서 디자인·로그인·작업 화면·모바일 보기를 전환한다. 로그인 버튼은 비밀번호 입력 없이 예시 작업 화면으로 이동한다. 역할별 진행, PM 대화, 보고서, 승인 화면은 예시 데이터로 구성했다. 예시 대화 입력은 현재 화면에만 표시하며 새로고침하면 사라진다.

## 검증

- [Console UI 실행](https://github.com/HyungwonPark/ai-company/actions/runs/34912789596): 기존 인증·관리 화면 회귀와 새 예시 화면 검사가 통과했다.
- [Python·Android CI 실행](https://github.com/HyungwonPark/ai-company/actions/runs/34912789602): 통과했다.
- 새 브라우저 검사는 A/B/C 로그인→작업 화면, PM 입력의 HTML 이스케이프, 보고서·승인 예시, 320~1440px 배치와 모바일 전환을 확인했다. 예시 페이지에서 `/api/` 요청과 브라우저 오류가 없었다.
- 원격 브라우저 캡처로 세 가지 데스크톱 로그인·작업 화면과 모바일 화면을 확인했다. 캡처는 위 Console UI 실행의 `console-screenshots` 아티팩트에 있다.
- 공개 HTML·CSS·JavaScript·폰트의 응답이 200이며 적용 소스와 바이트 단위로 같았다.
- `deploy/console/verify_public.py`가 통과했다. 관리 API는 미인증 요청에 401을 반환하고 HTTP는 HTTPS로 이동한다. 기존 커플 앱의 로그인 이동도 유지했다.

## 적용과 보존

이미지 `sha256:ddb2145c5557e4170c537b825b591d36c318544a28f140c93f59fc89ea31f528`로 관리 화면 컨테이너만 교체했다. 컨테이너는 `healthy`, 재시작 수 0이며 외부로 공개한 API 포트가 없다.

교체 전후 기존 `/`, `/app.js`, `/styles.css`의 응답 내용과 사용자 계정 레코드 해시가 같았다. 기존 커플 앱·Caddy·DB·백업 컨테이너의 ID·PID·시작 시각·재시작 수가 같았다. 이전 Compose 설정을 보관하고 실패 시 해당 관리 화면 이미지와 설정만 복구하도록 적용했다. 도메인 연결의 복구 스크립트에는 새 컨테이너 소유권을 반영했다.

예시 페이지는 실제 계정·작업·승인 API나 영속 저장소를 사용하지 않는다. PR #10 후보 승인, 운영 큐·타이머, 기존 격리 설정을 변경하지 않았다. 이 검증은 디자인 예시 검증이며 실제 마스터의 목표 입력·계획 확정 검증을 대신하지 않는다.
