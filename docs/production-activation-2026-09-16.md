## 마스터 확인 필요

현재 적용된 화면의 조작 순서다. 후속 미적용 화면의 버튼이나 생성하지 않은 프로젝트를 안내하지 않는다.

1. 기존 APK 0.1.1을 온라인으로 열거나 **https://hyungwon.cloud**에 접속한다. `edward`와 본인이 변경한 비밀번호를 사용한다. 오래된 화면이면 앱을 완전히 닫고 다시 연다. 비밀번호는 재발급하지 않았다.
2. 하단 **프로젝트** 메뉴에서 **새 프로젝트 +**를 누른다. 목록이 비어 있는 경우의 버튼은 **프로젝트 만들기 +**다.
3. 이름 예시 **역할 상태 확인**을 새로 입력한다. 이 이름의 프로젝트를 서버가 미리 만든 것은 아니다.
4. 목표 예시: **“작업 상태별 개수를 세는 작은 기능을 만들고, 개발과 검사를 두 역할로 나눠 빈 입력과 알 수 없는 상태까지 확인해 주세요.”** **PM과 시작**을 누르면 새 프로젝트와 PM 요청이 저장된다. 이 버튼은 계획 확정이나 개발 시작이 아니다.
5. 매니저에서 실제 PM 응답을 기다린다. 질문이면 답하고, 제안이면 역할·담당·완료 조건을 읽는다. **계획 검토·확정**을 열어 검토 확인을 마친 뒤 **이 계획 확정**을 직접 누른다. 후보 수용·배포·병합 승인이 아니다.
6. 서버에서 해당 목표 revision·계획 digest·직접 확정 이벤트·실행 ID 한 건을 대조한다. 실제 병렬 개발·검사·원격 CI·독립 검수·Astra 최종 검수·보고·새 후보 승인 요청은 그 실행에 연결해 확인한다. 아직 이 직접 조작 검증은 수행하지 않았다.

**현재 자동 개발은 `src/ai_company/pilot_status.py`와 `tests/test_pilot_status.py`, 기존 CI 요청 메타데이터로 제한된다.** 일반 프로젝트 자유 실행은 지원 완료가 아니다. 함수 계약·경로·하네스를 기본 입력으로 강요하지 않지만 서버의 허용 범위는 유지한다.

## 문제로 차단

남은 두 번역은 전체 품질 PASS를 받지 못했다. 읽기 전용으로 원문과 새 저장 결과를 대조한 결과, 현재 보호검사는 **‘아닙니다’라는 부정 표현과 ‘미결’이라는 pending 표현을 인식하지 못했다.** 조건 자체가 사라진 번역으로 단정할 근거는 없으며, 보호검사 오탐으로 한국어 표시가 미반영된 상태다. 한 문서의 Authorization→‘인증’에는 용어 검토 여지도 있다.

새 호출이나 예산 재설정은 하지 않는다. 보호 규칙을 완화해 기존 실패를 소급 PASS로 바꾸지 않았다. 추가 개선은 파서 버전·긍정/부정 반례·저장 결과만 재검사하는 범위를 고정한 후속 변경안이 필요하다.
