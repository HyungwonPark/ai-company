# 통합 작업실 첫 구현: 역할 그래프

PR #16 통합 명세의 **P0/P1 후보**다. PR #15의 A/B/C 비교를 다시 만들지 않고 A의 대화 우선, B의 진행 관계, C의 문서 읽기를 기존 제품 조회 API에 연결한다. 전체 통합 목표 완료, 운영 적용, 실제 모델 작업 완주, APK 실기기 검증을 뜻하지 않는다.

## 사용자 과제와 선택

같은 한국어 목표와 두 독립 역할을 사용한다. 개발은 역할 상태 집계, 검사는 독립 테스트를 맡는다. 이전 작업실은 프로젝트 전체의 현재 역할·최근 작업을 함께 표시했다. 후보는 사용자가 **계획 또는 실행을 먼저 선택**하고, 그 범위의 역할·전달선·보고·승인을 읽는다.

- 대화: 기존 자연어 입력과 PM 제안·계획 상세를 유지하며 대화 영역을 먼저 배치했다. 명세 저장과 직접 확정은 기존 API를 사용한다.
- 진행: 역할은 같은 행에 배치하고 저장된 관계를 선으로 연결한다. 위치로 의존 관계나 실제 동시 실행을 추론하지 않는다. 예정 관계는 점선, 저장된 관계는 실선이다.
- 승인: 목록에서 대상을 선택해 문서를 읽는다. 실행에서 온 링크는 해당 실행의 승인만 표시하고, 공통 탐색으로 이동하면 실행 필터를 해제한다.

이 방향은 통합 명세의 추천 후보를 구현한 것이다. 사용자 직접 조작이나 디자인 최종 수락을 대신 기록하지 않았다.

## 접속과 예시의 출처

- 실제 조회 API 후보: 별도 시험 서버에서 `/?workspace=integrated#progress?project=<실제 생성된 프로젝트 ID>`로 접속한다. 기존 비밀번호 로그인·변경·Host/Origin·CSRF 정책을 사용한다. 운영 서버에 이 후보가 적용됐다는 안내가 아니다.
- 내려받는 미리보기: CI의 `workspace-preview` artifact 안 `AI-Company-graph.html`. 압축을 풀어 파일을 열면 대화·진행·승인을 읽고 노드·선·목록·테마를 조작할 수 있다. 로그인·모델·운영 API 연결은 없다.
- 예시는 `tests/ui/run_workspace_graph.py`가 임시 SQLite에 기록한 자료를 실제 `ManagementStore.overview()`로 읽어 내보낸 것이다. 실제 PM·개발자·검수 모델이나 원격 작업 CI 결과가 아니다. 저장된 역할·전달물의 표현과 출처 결속을 시험한다.
- 기존 PR #15의 오프라인 비교 시안은 `AI-Company-preview.html`로 함께 보존한다.

## 연결 계약

`overview.workspace_graph`는 기존 조회 결과에 추가되는 읽기 전용 projection이다. DB 마이그레이션, 실행 배정, 하네스 변경, 모델 호출을 수행하지 않는다.

각 snapshot과 노드·선은 프로젝트 ID·계획 ID/digest·실행 ID에 결속된다. 실행의 현재 담당 작업은 `run.roles`의 고정 task ID를 사용하며 나중에 기록된 과거 task로 바꾸지 않는다. 계획 digest가 불일치하면 해당 계획의 PM 요청과 현재 역할 설명을 가져오지 않는다. 일치하는 고정 실행 명세로만 역할을 복구하고, 근거가 없으면 확인 불가와 경고를 표시한다.

보고는 해당 실행에 포함된 flow task의 보고 ID, 승인은 `run.approval_id`와 일치하는 항목만 연결한다. 번역 원문·승인 대상·digest·POST 권한은 변경하지 않는다. 명세 등록은 실행 승인이 아니고, 그래프 조작은 위치·선택만 바꾼다.

모델은 요청 설정과 기존 검증기가 확인한 CLI 관측을 나누어 표시한다. 상세의 원본 참조에는 허용 목록으로 걸러낸 설정 근거를 제공한다. CLI 관측을 서버 내부 모델의 독립 증명으로 확장하지 않는다. 비공개 clone 경로·계정 자격 증명·원시 CLI 출력은 그래프에 넣지 않는다.

조회 순서와 관측 시각으로 늦은 응답을 거부하고 중복 ID를 제거한다. fingerprint는 단순 조회 시각 변화와 실제 사실 변화를 구별한다. 노드 좌표·확대·선택·모바일 상세 스크롤과 펼친 근거를 같은 snapshot에 보존한다. 이 상태는 현재 페이지의 읽기 상태이며 로그인 세션이나 실행 기록을 바꾸지 않는다. 브라우저 전체를 닫았다 여는 경우까지 좌표를 영속 저장하지 않는다.

## 검수에서 발견하고 수정한 경계

1. 신규 노드가 기존 노드 좌표와 겹침: 기존 배치를 유지하며 빈 공간에 추가한다.
2. 계획 digest 불일치에서 다른 PM 작업·현재 역할 설명을 가져옴: 고정 원문 결속을 확인하지 못하면 제외한다.
3. 실행별 보고에서 공통 승인으로 이동할 때 이전 실행 필터가 남음: 탐색 대상 URL의 조건을 먼저 반영한다.
4. 기존 CSP가 인라인 좌표 스타일을 거부함: CSP를 완화하지 않고 DOM 스타일 속성으로 배치한다.
5. 오프라인 이전 응답이 연결 상태를 다시 켬: 이전 조회 세대와 브라우저 연결 상태를 대조한다.
6. 빈 프로젝트에 제안되지 않은 기본 PM 노드가 보임: 계획·역할·작업이 없으면 빈 상태를 표시한다.
7. 노드 이동 후 다음 조작이 무시됨: 포인터 이동 종료 시 억제 상태를 해제한다.
8. 모바일 상세 읽던 위치가 갱신마다 초기화됨: 스크롤·펼친 근거·초점을 같은 선택에 보존한다. 상세로 초점을 옮기고 Escape/닫기로 선택 노드에 돌아온다.
9. 조회 시각 변경만으로 기존 화면을 계속 재생성함: 사실 fingerprint로 변경 여부를 판단한다.
10. 이동 직후 이전 응답의 화면 갱신이 새 주소를 덮어씀: 처리 중인 URL과 상태가 일치할 때만 주소를 정규화한다. 동기식 이전 화면 갱신으로 회귀를 재현한다.
11. 첫 이관 기록이 추가되면 원본 근거의 숫자 인덱스가 바뀜: 원본·이관·기록 기준의 의미별 키로 열림과 초점을 보존한다.
12. 오프라인 미리보기에서 전체 승인 탐색을 확정 전 계획으로 잘못 한정함: 명시적인 실행 필터만 사용하며 없는 실행은 빈 결과로 표시한다.

## 후속 적용과 복구

이번 지시는 운영 배포 승인이 아니다. 현재 웹·worker·커플 앱·Caddy·타이머·큐·사용량·승인 기록을 변경하지 않았고, 병합하지 않았다.

P1만 적용할 경우 변경 대상은 **웹 이미지 한 개**다. 같은 Python 관리 서버에 읽기 projection과 정적 자산을 포함한다. worker, 번역, 카탈로그, 모델 후보, 예산, 볼륨, 네트워크와 API 공개 포트는 변경 대상이 아니다. 기존 운영 옵션·비밀번호·데이터 위치를 그대로 사용하고 candidate query가 있을 때만 새 구성을 표시한다. 기본 화면을 통합 후보로 바꾸는 것은 이 후보의 동작에 포함하지 않았다.

후속 적용 전에 이 문서에 고정한 코드로 `deploy/console/Dockerfile`을 빌드하고 이미지 digest를 기록해야 한다. 현재 웹 이미지 digest와 Compose 설정을 비공개로 보존하고, 별도 임시 데이터의 같은 이미지에서 로그인·조회·자산·CSP·기존 회귀를 검사한 후 구체적인 교체 범위를 대조한다. 이 문서는 이미지가 빌드되거나 운영 교체가 승인됐다는 증거가 아니다.

실패하면 새 후보 진입을 중단하고 변경한 웹 이미지만 이전 digest로 복구한다. DB를 과거 사본으로 덮어쓰지 않는다. 이번 projection에는 쓰기 형식·DB 스키마 변화가 없으므로 복구를 위해 worker나 실행 이력을 되돌릴 이유가 없다. 기존 PR #13의 실행·승인 계약을 그대로 사용한다. 추가 운영 변경이 필요해지면 그 변경만 별도 구체화한다.

## 남은 작업

- P2-A: Archify 고정 계획/보고 그림과 receipt. 고정 소스 조사에서 [공식 고정 스키마](https://github.com/tt-a1i/archify/blob/72c750bb070d95171dbb2244e5b62b1b7da69c12/archify/schemas/README.md)의 locale은 en/zh-CN만 지원하고, [SVG 내보내기](https://github.com/tt-a1i/archify/blob/72c750bb070d95171dbb2244e5b62b1b7da69c12/viewer/README.md)는 별도 검증이 필요함을 확인했다. 한국어·서버 생성 연결은 아직 미구현이다.
- P2-B: 선정한 ECC 지침을 프로젝트 하네스에 고정하고 실제 역할 전달·검사·인수인계에 결속하는 구현.
- P2-C: 기존 계정 현황, 공식 로그인과 같은 worker 실행 경로의 제한된 확인. 인증·적격·가용을 구분해야 한다.
- 운영 적용과 실제 APK에서 새 목표 입력·계획 확정은 별도 단계다. 사용자 대신 프로젝트를 만들거나 계획을 확정하지 않는다.
- 서명키 외부 보관·복원 확인은 기존 사용자 확인 항목으로 남아 있다.

P1의 완료로 위 항목이나 전체 상시 운영 목표를 완료 처리하지 않는다. PR #10의 후보 승인도 변경하지 않는다.
