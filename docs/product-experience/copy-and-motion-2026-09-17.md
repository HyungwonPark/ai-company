# 작업실 문구와 그래프 조작 기준

기준: PR #17 `ef2dce207bebbfbd0d5afc4829d6483cf5441fbf`. 기존 통합 작업실의 정보 구조를 유지하며, 문구와 조작 중 흔들림을 다듬는 후속 변경이다.

## 문구

사용자가 필요한 것은 현재 상황, 처리 방법, 자신이 결정할 일이다. 설명을 대화체로 늘이거나 당연한 장점을 덧붙이지 않는다. 질문은 실제 선택이 필요할 때만 한다.

| 기존 | 변경 | 이유 |
| --- | --- | --- |
| 처음 보는 상태는 어떻게 셀까요? | 정의되지 않은 상태 처리 | 값의 분류 문제를 구체적으로 지칭한다. |
| …‘알 수 없음’으로 모으는 방법을 제안해요. 이렇게 하면 누락 없이 전체 역할 수를 확인할 수 있습니다. | 진행·대기·차단·완료 외의 상태는 ‘알 수 없음’으로 집계하겠습니다. | 처리 방침을 한 문장으로 전달한다. |
| 좋아요. 알 수 없음으로 모으고 빈 입력도 확인해 주세요. | 그 기준을 계획에 반영하고, 빈 입력도 검사해 주세요. | 추천 답변의 범위를 계획 수정으로 한정한다. |
| 개발과 검사를 나눠 진행할게요 | 개발과 검사를 두 역할로 나눕니다 | 역할 배치를 설명한다. |
| 두 역할이 같은 계약으로 독립 진행합니다. | 개발과 검사는 같은 입력·출력 기준으로 진행합니다. | 사용자에게 필요한 의미를 풀어 쓴다. |
| 현재 일 / 관측 설정 | 담당 업무 / 실행에서 확인된 설정 | 무엇을 표시하는지 구체적으로 쓴다. |

이번 변경 대상은 합성 미리보기, 고정 안내 문구, 앞으로 만들 PM 계획의 생성 지침이다. 기존 대화·계획·보고·승인 원문, 번역 결과, digest를 고쳐 쓰거나 화면에서 일괄 치환하지 않는다. 사용자가 직접 쓴 말의 문체도 바꾸지 않는다.

PM은 짧은 합니다/습니다 문장을 사용하고, 작업·결과·결정 사항을 바로 말한다. 일반적인 칭찬, 수사적 질문, 당연한 이점의 반복 설명을 피한다. 불확실성과 승인 조건, 경로·명령·식별자는 정확히 보존한다. 이 지침만으로 실제 모델 응답의 문체까지 검증했다고 보지 않는다.

## 그래프 조작

| 상황 | 동작 기준 |
| --- | --- |
| 클릭 중 작은 손떨림 | 포인터 시작점에서 4px 미만이면 노드·화면 좌표를 바꾸지 않고 클릭으로 처리한다. |
| 실제 끌기 | 시작점 기준 전체 이동량을 반영한다. 해당 끌기에서 발생한 클릭만 억제하며 다음 클릭은 정상 처리한다. |
| 연결된 노드의 위아래 위치 교차 | 전달 방향에 따른 연결점을 유지해 선 끝이 반대편으로 뛰지 않는다. |
| 화면 폭 700px 경계 통과 | 큰 화면과 작은 화면의 배치·확대·이동을 각각 기억한다. 처음 전환할 때는 확대 비율을 유지하면서 그래프가 화면 밖으로 밀리지 않게 위치를 보정한다. |
| 끄는 중 서버 자료 갱신 | 현재 조작을 유지하고 최신 유효 응답을 보관한다. 손을 놓으면 반영한다. 늦은 응답·다른 실행의 자료를 섞지 않는다. |
| 화면 이동·접속 만료·연결 끊김·포인터 취소 | 조작과 보관 응답을 정리한다. 실행 대상이 바뀐 응답도 DOM 생성 전에 처리한다. 로그인 전환이나 오류 안내를 조작 종료까지 미루지 않는다. |
| 모바일 탭 직후 자료 갱신 | 열린 상세의 제목에 초점을 유지한다. 사용자가 노드로 돌아가려면 상세 닫기나 Escape를 사용한다. |
| 화면 밖 노드로 초점 이동 | 그래프의 이동은 하나의 좌표 상태로 관리한다. 브라우저의 숨은 스크롤과 그래프 이동이 중첩되지 않게 한다. 제거된 화면이나 너비 0인 화면으로 위치를 계산하지 않는다. |
| Tab / Shift+Tab 탐색 | 화면 밖 노드·선에 키보드 초점이 들어오면 해당 대상을 보이게 이동한다. 갱신 후 프로그램이 복원하는 초점은 화면 위치를 바꾸지 않는다. |

움직임을 꾸미기 위한 자동 재배치나 반복 애니메이션은 추가하지 않는다. 그래프 이동은 화면 배치만 바꾸며 역할·의존 관계·실행 순서·승인 범위를 변경하지 않는다.

## 검증과 범위

- 문구 변경은 상태 의미와 계획 확정 조건을 보존하는지 독립 검토한다.
- Node 검사로 연결선의 연속성, 화면 폭별 배치와 기존 실행·응답 순서 분리를 확인한다.
- 브라우저 회귀에서 클릭과 끌기, 다음 클릭, 화면 폭 왕복, 조작 도중 자료 갱신을 확인한다. 기존 Light·Black·모바일·키보드·동일 실행의 보고/승인 검사를 유지한다.
- 검증은 임시 데이터와 조회 API, 오프라인 예시를 사용한다. 실제 모델 호출·운영 데이터 변경·APK 실기기 검증은 포함하지 않는다.
- 이 작업 환경에는 Chromium 실행 파일이 없어 브라우저 검사는 원격 Console UI에서 수행한다. 실제 실행 결과와 다운로드 파일은 후속 PR 본문에서 고정 커밋에 연결한다.

운영 적용·병합·worker 변경은 이번 변경에 포함하지 않는다. PR #10 pending과 기존 서비스·큐·타이머·승인 계약을 보존한다.
