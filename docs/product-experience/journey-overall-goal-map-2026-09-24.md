# 순서형 작업실 — 전체 목표 대응표

기록일: 2026-09-24 KST. 범위: 저장소의 기존 검증·적용 기록과 이번 비운영 후보의 연결 범위 대조.

[야간 통합 지시](https://github.com/HyungwonPark/ai-company/blob/1d3b25ec41f9558a19a8d8a55fdb1f6682cc960a/docs/work-reviews/overnight-journey-integration-2026-09-24.md)의 누락 점검표다. 전체 목표는 **마스터가 목표와 팀을 정하고, 역할별 작업·검수·보고·필요한 결정을 같은 실행의 근거로 확인하는 시스템**이다. 순서형은 화면 탐색 방식이며 독립 작업을 직렬화하는 정책이 아니다.

이 표는 과거의 성공을 보존하되 새 후보나 현재 운영의 성공으로 재사용하지 않는다. 작성 시점에는 C·D·E의 통합 검증과 후보 고정이 진행 중이다. **동일 후보의 최종 커밋·검사·CI·독립 검수·미리보기 결과는 [이번 통합 검증 기록](journey-integration-validation-2026-09-24.md), 이미지와 적용·복구 범위는 [후속 적용안](journey-integration-rollout-2026-09-24.md)에 고정한다.** 두 문서는 함께 제출할 기록이며, 이 표의 작성만으로 구현·검증·배포를 완료 처리하지 않는다.

## 상태를 읽는 기준

- **과거 확인:** 링크한 문서의 관측 당시 사실이다. 이번에 운영 API·DB·프로세스·계정을 다시 조회하지 않았다.
- **이번 후보:** 이번 코드가 연결·보존할 기능과 시험 범위다. 개별 구현이나 이전 CI만으로 통합 PASS를 만들지 않는다.
- **현재 미확인:** 최신 상태를 관측하지 않았거나 해당 검증을 수행하지 않은 항목이다. 실패와 구별한다.
- **직접 확인:** APK의 실제 입력·계획 확정과 서명키 외부 보관·복원처럼 사용자가 수행할 항목이다. 임시 DB의 가상 사용자 시험으로 대체하지 않는다.
- **이번 제외:** 운영 변경·추가 모델 연결처럼 이번 작업이 허용하지 않은 범위다. 관련 문서가 있다는 이유로 자동 실행하지 않는다.

## 한국어 보호 복구의 남은 두 건

1. [5594744 적용 때의 제한된 복구](../production-activation-2026-09-16.md#제한된-번역-복구)는 원래 실패 6건을 보존했다. 저장 결과 재검사 2건은 추가 호출 없이 성공했고, 남은 예산에서 각각 한 번 재시도한 4건은 2건 성공·2건 실패였다. 추가 호출은 당시 합계 4회이며 재예약하지 않았다.
2. [후속 저장 출력 재검사](../translation-saved-recheck-2026-09-16.md)는 추가 모델 호출 없이 원문·출력을 대조했다. ‘아닙니다’·‘미결’ 오탐을 제한적으로 처리한 **복사본 결과는 1건 통과·1건 거부**다. 거부된 문서는 승인 권한을 로그인 인증으로 혼동하게 하는 실제 오역이 있어 실패를 유지했다.
3. 재검사 기능이 제품 코드에 포함된 것과 운영의 표시 링크를 변경한 것은 다르다. [pilot 적용 기록](../project-execution-activation-2026-09-16.md)은 재검사 표가 비어 있었고 번역 기록·표시는 변경하지 않았다고 명시한다. 이후 [2087ecc 적용](pr21-deployment-2026-09-17.md)도 번역 worker와 기존 기록을 유지했다. **운영 두 건이 복구됐다는 후속 증거는 이 대조에서 확인하지 않았다.**
4. 이번 작업은 저장 원문·실패·사용량·공유 한도·표시 연결을 수정하지 않는다. 재검사 적용은 호환 worker·고정 제안·현재 원문/출력/선택을 대조하는 별도 경계다. 구버전 번역 worker를 먼저 시작하거나 DB를 과거 사본으로 덮어쓰는 복구는 허용하지 않는다.

## 운영 기준과 이번 금지 범위

저장소에서 확인한 마지막 실제 배포 기록은 **2026-09-17의 제품 `2087eccae3f946bc6d676904462a9b2acabd8521`**, 웹 이미지 **`sha256:181b99ab1f87f5c46023a79ac7265ff5fe95d81decd826a8386cc185480df7aa`**다. 당시 웹 healthy, PM·조정기 단일 소유권, 번역 worker 유지, 파생 표 `management_diagrams`·`guidance_deliveries` 추가와 기존 행 보존을 확인했다. 이는 오늘의 실시간 서비스 상태 조회가 아니다.

이번 후보는 이 기준의 UI를 바꾸는 **비운영 검토 대상**이다. 기존 허용 범위인 `src/ai_company/pilot_status.py`, `tests/test_pilot_status.py`와 기존 CI 요청 메타데이터, 검사·계정·공유 한도·예산·Astra 최종 검수 정책을 확대하지 않는다.

이번에 하지 않는 일은 운영 웹/worker/DB/프록시 교체, 공개 포트·도메인 변경, timer·queue 쓰기, 전역 격리 해제, 운영 API의 새 프로젝트·계획·모델 실행·후보 결정, 병합, PR #10 pending 변경, 추가 계정·유료 API·모델 로그인, ECC 활성화, 서명키 사용·내보내기·외부 백업이다. 임시 시험 DB의 확정·결정은 허용된 API 계약 검사이며 운영 승인으로 이전하지 않는다.

과거 문서의 “현재”와 “미적용”이 충돌하면 문서 상단의 후속 적용 안내와 실제 적용 기록을 우선한다. 특히 초기 bwrap 차단은 [승인된 격리 복구](../runtime-validation-2026-09-14.md), Claude 준비안은 [5594744 실제 적용](../production-activation-2026-09-16.md), PR #13 준비안은 [pilot 적용](../project-execution-activation-2026-09-16.md), PR #19/21 준비안은 [2087ecc 배포](pr21-deployment-2026-09-17.md)로 이어진다. 이전 실패·미검증 사실 자체는 삭제하지 않는다.
