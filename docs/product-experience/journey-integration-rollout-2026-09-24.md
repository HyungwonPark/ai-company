# 순서형 제품 후보 적용·복구안

2026-09-24 KST. **비운영 준비 문서이며 운영 적용·병합 승인이 아니다.**

기준은 PR #23 `1d3b25e`의 야간 명세와 PR #24 `7522748`의 연결 계획이다. 후보와 이미지·검증 근거는 [통합 검증 기록](journey-integration-validation-2026-09-24.md)에 고정한다. 아래 절차는 승인을 받은 이후의 적용안이다. 이번 개발에서는 운영 상태·인증 세션·DB를 변경하지 않는다.

## 변경 범위

| 대상 | 필요한 적용 | 근거 |
| --- | --- | --- |
| 웹 | 기존 웹 컨테이너 **1개**의 이미지 교체 | 기본 순서형 탐색, PM·계획·명세 동선, 실행에 연결된 보고/승인, G1~G3 및 공개 shell v9 |
| PM·조정기 | 교체 불필요 | 서버·실행 엔진·worker 코드는 기존 기준과 동일 |
| 번역 worker | 교체 불필요 | 번역 원문·저장 결과·보호 규칙 및 예산 유지 |
| DB | 새 마이그레이션 없음 | 기존 실행·승인 API와 기존 테이블 사용. 기존 두 파생 테이블을 다시 추가하는 배포가 아님 |
| 카탈로그·설정·모델·예산 | 변경 없음 | pilot 두 파일, 공유 한도·재시도·동시 실행·최종 검수 정책 유지 |
| Caddy·도메인·인증서 연결·포트 | 변경 없음 | 같은 HTTPS origin과 전용 내부 연결, 공개 API 포트 없음 |
| APK | 새 빌드·서명 불필요로 판단 | 기존 0.1.1(2)의 시작 주소 `/`, 같은 package/origin/인증 계약. 실제 기기 갱신은 미검증 |
| ECC·추가 모델·서명키 | 작업 범위 밖 | 활성화·로그인·서명·내보내기·복원하지 않음 |

`2087ecc`의 [2026-09-17 적용 기록](pr21-deployment-2026-09-17.md)을 직전 배포의 역사적 근거로 사용한다. 현재 가동 버전을 새로 조회했다는 뜻은 아니다. 해당 기록의 웹 이미지 `sha256:181b99ab1f87f5c46023a79ac7265ff5fe95d81decd826a8386cc185480df7aa`는 보존할 복구 후보다. 적용 직전 실제 이미지가 다르면 그 실제 버전과 변경점을 먼저 대조한다.

## 승인 이후 순서

1. 검증 기록의 코드·이미지·정적 자원 manifest와 실제 현재 웹 이미지·서비스 정의·읽기 전용 카탈로그를 대조한다. API/worker/DB 코드가 직전 기준과 같음을 다시 확인한다. 후속 변경이나 새 계약이 발견되면 차이를 검토하고 덮어쓰지 않는다.
2. 현재 Compose 설정·이미지 ID·기존 정적 자원 해시와 SQLite 온라인 백업을 비공개 보관한다. 온라인 백업은 감사·문제 분석 자료이며 DB/WAL의 임의 복사나 과거 기록 복원 수단으로 쓰지 않는다. 원문·비밀번호·운영 DB를 GitHub 산출물에 넣지 않는다.
3. 현재 요청이 끝날 시간을 주고 기존 Compose에서 웹 서비스의 이미지 ID만 바꾼다. 기존 서비스명으로 `docker compose ... up -d --no-deps <웹서비스>`를 사용하며 전체 `down`·프록시 재적용·worker 재시작을 하지 않는다. 자세한 실제 경로와 서비스명은 비공개 적용 기록을 따른다. 읽기 전용 루트, capability 제거, 자원 제한, 내부 네트워크, 기존 상태/카탈로그 mount를 유지한다.
4. 60초 안에 healthy와 재시작 반복 없음, HTTPS 루트·로그인·정적 파일 해시를 확인한다. 익명 private API 거부, Host·Origin·CSRF·Secure/HttpOnly/SameSite 쿠키 보호와 기존 로그인 경로를 검증한다. 검증을 위해 비밀번호를 재설정하거나 마스터 대신 새 계획·결정을 만들지 않는다.
5. 기존 계정의 읽기 화면에서 목록·없는 대상·선택한 실행→계획/진행/결과/승인의 ID 일치를 확인한다. 읽기 탐색 이후 실행·승인·사용량 추가가 없어야 한다. 정상 worker가 만든 새 기록은 UI 탐색이 만든 기록과 구분한다. PR #10 pending, 기존 큐·타이머·커플 서비스가 이번 교체의 영향을 받지 않았는지 확인한다.
6. 기존 탭에서는 처리 중인 입력과 기록을 보존한다. 공개 shell만 network-first로 갱신하고 새 worker가 대기하는 동안 오래된 탭을 강제 종료하지 않는다. API·POST를 캐시하거나 재전송하지 않는다. 이후 사용자가 앱/탭을 닫고 다시 열어 새 화면을 확인한다. 앱 데이터 초기화·전체 캐시 삭제·자동 skipWaiting으로 갱신을 강제하지 않는다.

## 실패 판정과 복구

이미지/정적 자원 불일치, 60초 내 unhealthy·재시작 반복, 로그인/권한 경계 회귀, 다른 실행의 기록 노출, 확정/결정 중복, 파생 그림 기능 회귀, 기존 원장의 예상 밖 변화 중 하나라도 확인되면 필수 검증 실패다.

1. 새 후보의 추가 적용을 중지하고 현재 실패 로그·버전·DB 기록을 보존한다. 웹 변경이 요청을 잘못 만들 수 있다면 해당 웹의 새 입력을 중단한다. worker·타이머까지 임의로 바꾸지 않는다.
2. 적용 직전 보관한 설정과 현재 설정의 차이가 이번 이미지 교체뿐인지 확인한 뒤 **웹 이미지 1개만** 직전 실제 ID로 돌려 같은 서비스만 재생성한다. 다른 사람이 만든 후속 설정을 덮어쓰지 않는다.
3. DB·실행·사용량·승인·번역 기록은 과거 백업으로 덮어쓰지 않는다. 이번 후보가 기존 API로 만든 정상 요청/계획/결정도 보존한다. 예기치 않은 계약 변화가 있으면 호환성을 검토하고 무조건 구버전을 재시작하지 않는다.
4. 복구 웹의 건강·인증·읽기·같은 실행 연결을 확인한다. 격리 브라우저의 v8→v9→v8 시험은 참고 근거이며 실제 도메인/기기 복구 결과를 대신하지 않는다. 오래된 탭을 닫고 다시 열었을 때 복구 파일이 제공되는지도 사용자 확인으로 남긴다.

## APK 확인 안내 — 적용 승인 이후

기존 앱 ID는 `cloud.hyungwon.aicompany`, 버전은 `0.1.1`(2), 주소는 `https://hyungwon.cloud/`다. [기존 설치 파일·서명 검증 기록](pr21-mobile-release-2026-09-17.md#기존-apk-다운로드와-확인)을 보존한다. 이번에는 APK 다운로드나 서명키 조작을 새로 수행하지 않는다.

1. AI Company 아이콘으로 열고 필요하면 기존 `edward` 계정으로 로그인한다.
2. 목록에 **실제로 있는 프로젝트**를 선택하고 `진행`에서 실행을 고른다. 새 프로젝트가 이미 생겼다고 가정하지 않는다.
3. 역할과 전달선을 눌러 담당·대기 이유·출발/도착·전달물을 확인한다. `대상 정보`의 실행 ID를 기준으로 `결과`와 `승인`을 왕복한다. 확인만 하는 동안 후보 결정을 누르지 않는다.
4. Android 뒤로가기, Light·Black, 앱 완전 종료 후 아이콘 재실행을 확인한다. 테마·로그인 정책·선택한 실행 및 갱신 화면 결과를 기기/Chrome/앱 버전과 함께 기록한다.
5. 새 검증 실행은 별도 사용자 직접 조작이다. `프로젝트 → 새 프로젝트`에서 이름과 자연어 목표를 입력하고 PM 제안→명세 확인·저장→새 계획 요청→직접 계획 확정을 진행한다. 현재 자동 실행은 기존 `pilot_status.py`와 해당 독립 테스트 두 파일에 한정된다. 계획 확정은 후보 수용·배포·병합 승인이 아니다.

실기기 조작·초보 사용자 관찰·실제 도메인 서비스워커 갱신, 서명키 외부 보관/복원은 미실시로 남긴다. 이 비운영 단계에서는 위 행동을 대신 수행하지 않는다.
