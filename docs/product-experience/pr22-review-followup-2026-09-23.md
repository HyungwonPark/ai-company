# PR #22 · R1~R5 보완

## 참조와 범위

- 문서 기준: PR #23의 [`a446a5146f8cbb06a4f7575e64a17cf530c5ef49`](https://github.com/HyungwonPark/ai-company/tree/a446a5146f8cbb06a4f7575e64a17cf530c5ef49/docs/work-reviews). README → PR #22 검수 → 전체 작업실 재설계 → 그래프 UI 검수 명세 순서로 읽었다. 문서 전용 브랜치를 병합하지 않고 고정 원문을 참조했다.
- 수정 전 코드: `3c3c1988a5b04dcfcd7d5aacbd39fbb836bb4d95`. 원 검수 대상 `b31fb87` 이후 차이는 공개 ZIP·해시·안내뿐이며 시안 JS·HTML·CSS는 같았다.
- 대상: PR #22의 **별도 예시 시안**과 검사·배포하지 않는 다운로드 묶음. 제품 API·DB·worker·모델 호출·운영 승인·서비스·PR #10 상태를 변경하지 않는다.
- 기존 순서형·한눈형은 같은 데이터와 조작으로 비교한다. 순서형 추천은 디자인 확정이나 초보 사용자 검수 합격을 뜻하지 않는다.

## 원문과의 대조

| 항목 | 수정 전 확인 | 보완 내용 |
|---|---|---|
| R1 초기화 | 고정 이전 JS를 Node VM에서 실행하자 `sharedDraft:true`, `resetCleared:false`. 새 상태의 입력이 기본 객체를 오염시켰다. | 새 상태를 독립 생성하고, 저장 상태의 중첩 입력도 별도 복원한다. 새 탭 입력·답변·일반 새로고침 보존과 명시적 초기화를 구분한다. |
| R2 결정 | 대상 ID는 있으나 판단 값이 없었다. | 수용·수정 요청·보류를 구분하고 의견·다음 행동을 표시한다. 승인별 별도 예시 결정에 프로젝트·계획·실행·후보·digest를 연결한다. 원 요청의 pending은 유지한다. |
| R3 발견 | 기본 현재 실행에서 이전 pending을 발견할 수 없었다. | 프로젝트 목록과 승인 진입점에 확인할 일을 표시하고, 요청을 누르면 정확한 이전 실행으로 이동한다. 다른 실행에 승인 원본을 붙이지 않는다. |
| R4 전체 체험 | 새 프로젝트는 확정 후 시작 대기에 멈췄다. | 고정 예시 목표를 명시적으로 선택하면 같은 프로젝트의 PM 대화·계획 수정·확정·병렬 진행·대기·이관·검수·결정을 체험한다. 각 진행 버튼은 모의임을 표시한다. 임의 목표에 고정 계획을 맞춤 계획으로 표시하지 않는다. |
| R5 행동 | 명세 저장 → 새 계획 요청 → 계획 검토라는 내부 순서를 사용자가 알아야 했다. | 내용 정리 → 계획 확인 → 이 계획으로 시작으로 안내한다. 저장·계획 생성·확정 사건은 각각 남기고 준비·실패·재시도·수정 후 재검토 상태를 구분한다. |

수정 요청 의견은 제품 화면의 필수 조건이다. 제품 API 자체는 빈 의견을 허용한다. API의 `approve/reject/request_changes` 중 이번 시안은 수용과 수정 요청을 체험하며, **보류는 API 결정이 아닌 로컬 예시 선택**이다. 제품의 수정 요청은 실행을 `blocked`로 만들므로 시안도 자동 수정 재실행을 약속하지 않는다. 수용은 배포·병합 승인이 아니다.

## 그래프 명세 적용 경계

이번 시안의 업무·팀·기록 분리와 같은 실행의 결과·승인 연결은 재설계 원문의 방향을 따른다. CSS로 표현한 세 업무의 관계를 기존 제품 그래프의 G1~G3 개선 완료로 세지 않는다. 중앙 배치·전체 보기·복잡한 반환선·드래그·갱신 중 도움말 유지의 제품 수정은 이번 변경에 포함하지 않는다.

기존 제품 렌더러·관계 데이터·1px 왕복 검사와 원격 회귀를 보존한다. 기존 그래프 검수 통과나 이번 시안 브라우저 성공을 미완료 G1~G3의 합격으로 확대하지 않는다.

## 검증 방법

- `tests/ui/task_workspace.cjs`: 기존 두 구조 × 두 테마 × 320/390/1440px 화면·업무·팀·기록·키보드·확대·실행 분리 회귀.
- `tests/ui/task_workspace_independent.cjs`: 구현자와 별도로 작성한 키보드·포커스·실제 포인터/터치·후보 결정 검수.
- `tests/ui/task_workspace_review.cjs`: 저장값 없는 R1 초기화와 R2~R5의 같은 프로젝트 전체 흐름을 동일한 12개 조합에서 검사한다. 요청은 예시 정적 파일로 가로채며 외부 호출·API 쓰기는 실패시킨다.
- 브라우저는 `chromiumSandbox:true`로 실행한다. 로컬에는 실행 가능한 Playwright 브라우저가 없어 원격 Console UI의 기존 Chrome 환경을 사용한다. 이 환경 차이를 해결하려고 전역 제한을 변경하지 않는다.

## 수정 중 재현과 독립 검수

- 로컬 JS 상태 검사: 기본 중첩 객체 분리, 초기화, 일반 새로고침, 손상된 저장값 복구, 이전 확정·결정 원문 보관을 확인했다. 이전 확정 표시는 `legacyPreview`로 보존하며 새 실행 승인으로 바꾸지 않는다.
- 구현자와 다른 검수자는 실제 JS를 Node VM에 읽어 오프라인 변경 차단, 실행 전 확정 조건, 중복 확정 후 실행 1건, 같은 후보 결속을 확인했다. 이는 브라우저 검사와 별개다.
- 독립 검수에서 신규 완료 실행에 한도·실패 배너가 붙는 모순을 찾아 완료 기준으로 수정했다. 기존 이전 실행과 신규 완료 실행 모두 보존하는 회귀를 추가했다.
- 첫 화면 CI [`35876703965`](https://github.com/HyungwonPark/ai-company/actions/runs/35876703965)의 실제 브라우저에서 잘못 닫힌 HTML `option` 때문에 수용 선택을 할 수 없는 문제가 확인됐다. JS 문법 검사만으로 발견되지 않았으며 HTML을 수정했다. 추가된 `specVersion`을 독립 검사에서도 정확히 대조하도록 보완했다.
- 모바일 후보 창은 선택·의견을 먼저 보여 주고 기술 ID·digest는 **대상 근거**에서 펼쳐 확인한다. 검사는 실제 클릭·터치로 펼친 값과 저장 결속을 대조한 뒤 다시 접는다.

## 항목별 실행 결과

행동 검사 후보는 `12d44d2d9d43c57e291a4fa770b4891ed05b6fb2`다. [화면 CI](https://github.com/HyungwonPark/ai-company/actions/runs/35878376283)의 기존 시안·독립 시안·R1~R5 세 단계가 성공했고, 같은 커밋의 [Python CI](https://github.com/HyungwonPark/ai-company/actions/runs/35878376451)도 성공했다. UI 작업 전체와 개별 검사 단계는 구분한다. 새 검수 스크립트는 12개 조합을 끝까지 실행해야 성공한다.

| 항목 | 판정 | 실제 확인한 내용 |
|---|---|---|
| R1 | PASS | 저장값 없는 시작, 이름·목표·답변의 새로고침 보존, 명시적 초기화 후 빈 입력·확정·결정·사건 목록 |
| R2 | PASS | 수용·수정 요청·보류의 별도 선택, 빈/공백 수정 의견 거부, 일곱 대상 ID·digest와 명세 버전 대조, 원래 pending 유지, 선택별 다음 행동 |
| R3 | PASS | 기본 목록의 이전 승인 발견, 직접 이동, 현재 실행과 과거 실행의 요청 분리, 신규 프로젝트 결정 후 과거 결정 보존 |
| R4 | PASS | 같은 신규 프로젝트에서 대화·계획 수정·직접 확정·병렬 진행·한도 대기·같은 업무 이관·검사·검수·전달물·결정까지 완료 |
| R5 | PASS | 명세 저장과 계획 요청 사건 분리, 준비 실패·재시도, 수정 후 이전 검토 무효화, 버전 재고정, 직접 확정 전 실행 0건·이후 1건 |

위 PASS는 **예시 브라우저 조작**이다. 실제 운영 PM·모델·원격 후보 검수 성공이 아니다. 기존 시안 회귀는 두 배치 × 두 테마 × 320/390/1440px, 키보드·포커스·200% 텍스트·빈 화면·오프라인·긴 한국어를 확인한다. 독립 모바일 검사는 320px Light/mouse와 390px Black/touch에서 실제 좌표 조작 71회를 수행했다. 외부 요청·페이지 오류는 0건이었다.

독립 검수자는 320px Light·390px Black 후보 창과 390px Light·1440px Black 진행 캡처를 직접 읽었다. 업무명과 역할·모델이 구분되고 긴 기술 근거는 펼칠 때 읽을 수 있다. 320px 후보 창은 세로 스크롤이 필요하다. 선택한 승인 숫자의 대비 문제는 발견 후 `06d7872ab869e904da214ae6cde5653c11fefe32`에서 CSS 한 줄로 보완했다. 후속 캡처에서 준비 완료 뒤에도 이전 준비 알림이 남는 문제를 추가로 발견했다. `cb4cca353efd46cd6f4f56b01816c27a884c4e95`에서 준비 완료·실패·내용 수정 시 알림을 함께 갱신하고 R5의 브라우저 문구 검사를 추가했다. 이 커밋이 최종 시안 소스다. 최종 게시 커밋의 재검사와 대비 보완 캡처 판정은 [PR #22의 검사·검증 안내](https://github.com/HyungwonPark/ai-company/pull/22)에 연결한다.
