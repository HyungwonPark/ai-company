# 다음 화면 작업: 역할·업무 그래프

상태: 사용자 요청을 반영한 구현 명세 · 2026-09-16 · v1.0

## 우선순위

사용자는 역할과 업무가 오가는 관계를 노드와 선으로 보고 싶다고 명확히 요청했다. 다음 프런트엔드 산출물은 **진행 화면의 그래프 보기**다. 기존 매니저 작업실·팀 작업대·결정함 세 방향 중 하나를 다시 고르도록 기다리지 않는다. PM 대화와 승인함은 각각 유지하고 진행 화면을 그래프 중심으로 구체화한다.

PR #14의 스킬·문서는 그래프 구현 완료가 아니다. 서버 Codex가 별도 UI 작업 범위에서 아래 기능을 구현하고 검수 가능한 후보를 준비한다. 정확한 공개 적용 시점은 구현·검증 결과와 해당 후보의 운영 적용 범위가 정해진 뒤 확인한다. 서명키 외부 백업 완료를 화면 개발의 선행 조건으로 삼지 않는다.

## 첫 구현 범위

1. **진행 → 그래프 / 목록**을 제공한다. PC와 APK 모두 그래프를 열 수 있어야 한다. 모바일에서 그래프 기능 자체를 숨기지 않으며 목록은 동등한 대체 보기로 둔다.
2. 노드는 역할·작업을 식별하고 역할명, 담당 모델, 현재 일, 상태를 간결히 표시한다. PM 아래 독립 역할을 병렬 배치하고 결과 합류·검수·수정 반환을 구별한다. 단계·번역·문서는 종류를 표시해 실행 에이전트와 혼동시키지 않는다.
3. 연결선은 전달 또는 의존 관계를 의미한다. 노드나 선을 선택하면 관련 관계를 강조하고 산출물·전달 사유·대기 원인·요청/관측 모델·근거를 상세로 연다. 화면 위치로 인과관계를 추정하지 않는다.
4. 확대·축소·이동·전체 맞춤을 제공한다. 같은 노드의 위치와 선택을 데이터 갱신마다 초기화하지 않는다. 모바일의 터치와 페이지 스크롤이 충돌하지 않게 확인하고 키보드·목록 경로로도 상세에 접근한다.
5. **계획과 실제 실행을 분리**한다. 확정 전 역할·의존은 예정, 기록된 전달은 실제로 표시한다. 그래프가 비어 있으면 원인과 다음 행동을 안내한다.
6. 첫 버전은 기존 overview와 5초 갱신을 재사용한다. 서버 cursor, 중복·늦은 응답 방지, 새 이벤트의 일회성 표시를 보존한다. SSE 도입을 첫 그래프의 필수 선행 작업으로 만들지 않는다.
7. 최근 12건 제한을 전체 관계로 오해하지 않게 표시한다. 현재 관계 요약과 과거 전달 이력을 구분하고, 화면에 없는 전달을 존재하지 않는다고 표시하지 않는다.
8. 이관은 역할을 유지하면서 담당이 바뀌는 사실로 표시한다. 공유 계정 한도와 고정된 최종 검수자가 대기 중이면 그대로 알린다. 개발 대체자가 있다는 이유로 최종 검수까지 끝날 수 있다고 꾸미지 않는다.

첫 버전은 관찰 화면이다. 노드 위치 이동은 표시만 바꾸며 실행 순서·모델·권한·계획을 변경하지 않는다. 선 연결로 계획을 편집하는 기능은 이후 PM 계획 검토·직접 확정과 연결할 별도 구현이다.

## LangGraph와 화면 그래프의 관계

[flow_graph.py](https://github.com/HyungwonPark/ai-company/blob/f93339134b011cf1359d90697980563add05c981/src/ai_company/flow_graph.py)는 LangGraph StateGraph로 단계와 판정에 따른 다음 상태를 계산한다. [dispatcher.py](https://github.com/HyungwonPark/ai-company/blob/f93339134b011cf1359d90697980563add05c981/src/ai_company/dispatcher.py)는 실제 실행 결과를 받아 graph.invoke와 SQLite 체크포인트를 사용한다.

현재 내부 그래프는 각 호출에서 START→현재 단계→END로 끝나고 다음 단계를 반환한다. 전체 프로젝트의 병렬 업무 관계가 그대로 들어 있는 그래프가 아니다. 내부 도식을 출력하는 것만으로 위 사용자 화면을 구현했다고 보고하지 않는다.

화면은 기존 협업 자료와 확정 계획의 역할·의존, 같은 실행의 작업·통합 상태·실제 이벤트를 사용한다. 먼저 기존 API가 제공하는 노드·전달·출처를 재사용하고 부족한 자료만 추가한다. 브라우저가 상태 판정이나 원장 기록의 주체가 되지 않게 한다.

## 구현 도구 선택

현재 웹은 HTML·CSS·순수 JavaScript이며 외부 스크립트 정책은 로컬 자산을 전제로 한다.

- 기존 SVG를 확장하는 방법은 새로운 프레임워크 없이 검토할 수 있다.
- 확대·이동·자동 배치가 필요하므로 [Cytoscape.js 공식 문서](https://js.cytoscape.org/)의 순수 JavaScript, JSON 그래프, 터치·배치 기능을 후보로 비교한다. 도입 시 버전·라이선스·크기·모바일 성능·접근성 대체 보기를 검증하고 고정 자산으로 패키지한다.
- [React Flow 공식 문서](https://reactflow.dev/learn)는 React 기반 구현의 후보다. 현재 제품에 React가 있으므로 즉시 사용할 수 있다고 가정하지 않는다. 그래프 하나를 위해 전체 화면을 재작성하는 선택은 비용과 이점부터 비교한다.
- 어느 도구도 LangGraph 사용의 필수 조건이 아니다.

## 다른 AI 연결 범위

후속 요청으로 [모델 연결·현황 화면](model-connections-2026-09-16.md)을 추가한다. 제공자별 로그인과 모델 사용 가능 여부를 공통 메뉴에서 관리하고, 그래프의 담당 모델·대기·이관 정보와 같은 근거를 사용한다. 기존 Codex·Claude 계정부터 연결하며 이 기능의 완성을 그래프 개발의 선행 조건으로 삼지 않는다.

LangGraph의 노드는 일반 함수이므로 CLI·API·로컬 모델 호출을 감쌀 수 있다. [공식 Graph API 설명](https://docs.langchain.com/oss/python/langgraph/graph-api), [공식 개요](https://docs.langchain.com/oss/python/langgraph/overview)를 따른다.

현재 ai-company의 제공자 계약과 실행기는 Codex·Claude CLI만 허용한다. Gemini·Bedrock·로컬 모델을 설정 한 줄로 바로 연결할 수 있다고 표시하지 않는다. 새 제공자에는 실행/중지·결과 정규화·한도/비용·재개/복구·역할 적격성 어댑터가 필요하며, 세션 재개 미지원은 미지원으로 표시한다. 제공자 추가는 이 그래프 화면 구현의 선행 조건이 아니다.
