# 프런트엔드 개편과 프로젝트 스킬

상태: 검토용 설계·스킬 초안 · 2026-09-16 · v1.0

후속 사용자 요청에 따라 다음 구현의 우선순위를 [진행 화면의 역할·업무 그래프](graph-workspace-2026-09-16.md)로 구체화했다. 아래 세 방향 비교는 초기 제안 기록이며, 그래프 방향 선택을 다시 기다리지 않는다.

[모델 연결·현황 화면](model-connections-2026-09-16.md)도 같은 후속 범위에 포함한다. 제공자별 공식 로그인, 기존 서버 인증 가져오기, 모델 검증·역할 배정을 구분한다. 그래프 개발은 로그인 연동 완료를 기다리지 않고 진행한다.

## 목적과 이번 범위

마스터가 느끼는 “같은 틀의 UI가 반복된다”는 문제를 화면 구성·읽는 순서·상호작용까지 바꾸어 검토한다. 외부 스킬을 설치하면 디자인이 자동으로 좋아진다고 보장하지 않는다.

이 변경은 프로젝트 공통 스킬과 Codex·Claude Code의 읽기 경로를 추가한다. 제품 화면·운영 서비스·하네스 실행 코드·CI 설정은 변경하지 않는다. PR #13 개발 완료, 기존 실사용 검증과 운영 적용 승인 범위는 별도로 유지한다.

- 코드 조사 기준: PR #13의 `74cfa3ad1b2cf51dcf9c1068ef8b396c70e3e5f8`.
- 시각 조사: 저장소의 PR12 모의 캡처 두 장. 현재 실기기·인증된 운영 화면을 직접 검사한 것은 아니다.
- 외부 참고: garden-skills `aaf9a82f5efd73e87cc0998edc398e75bfc35901`, web-design-engineer 1.3.0.
- 앞선 설계: [PR #12 고정 문서](https://github.com/HyungwonPark/ai-company/tree/6ead11f0388564059741389a0fbccc3c94f4a9b1/docs/product-experience). PR13 트리에는 그 문서와 AGENTS 읽기 경로가 포함되어 있지 않다. PR8은 그 문서를 대조해 일부 UX를 구현했다고 기록한다. 따라서 “아무 지침도 사용하지 않았다”고 해석하지 않는다.

## 가져올 내용과 조정할 내용

| garden-skills의 내용 | 프로젝트에 적용 |
|---|---|
| 기존 화면 감사, 확장/보존/구조 개편 구분 | 이번 요청은 화면 구조 개편. 작은 수정에는 큰 절차를 반복하지 않음 |
| 다른 계열의 시안, 초기 작동 시안 공개 | 같은 업무·한국어 내용으로 구조와 첫 행동이 다른 세 안을 비교 |
| 모든 내용의 카드화, 반복 헤더·장식 메타데이터 지적 | 카드 개수 제한보다 각 그룹·라벨이 돕는 사용자 행동을 검수 |
| 운영 화면의 과한 표어·여백·장식 경고 | PM 질문, 역할의 일, 실제 전달, 결정할 내용을 우선 |
| 제작 중 여러 승인 중단 | 이미 승인된 범위는 진행. 취향 선택은 구체적 시안으로 한 번에 좁힘 |
| 명시 요청일 때만 브라우저 검증 | 기존 프로젝트의 UI 검증·회귀 기준 유지 |
| Inline React/Babel·CDN, 특정 폰트/아이콘 규칙, 제목 비율·여백 비율 | 원본 환경·취향에 해당. 기존 제품 스택이나 한국어 모바일의 필수 기준으로 가져오지 않음 |

참고 자료는 저자의 실무 지침이다. 학술적인 효과 검증이나 우리 제품의 사용성 향상 증거는 아니다. 기존 브랜드 복제와 새로운 유행 템플릿으로의 교체를 목표로 하지 않는다.

## 이번에 비교할 세 방향

동일한 예시 프로젝트, 같은 PM 제안·팀·산출물·대기 상태와 핵심 사용자 과제를 넣어 배치·우선순위를 비교한다. 서로 다른 페이지 세 개를 만들거나 색상만 바꾼 것을 세 방향으로 세지 않는다. 예시 상태를 실제 운영 결과로 표시하지 않는다.

| 방향 | 첫 화면과 첫 행동 | 주요 구성 | 주의할 점 |
|---|---|---|---|
| A. 매니저 작업실 | PM이 지금 묻는 내용에 답하기 | 읽기 좋은 대화·짧은 보고 중심, 옆 또는 다음 영역에 팀 요약 | 진행과 승인 진입점이 대화 아래에 묻히지 않게 함 |
| B. 팀 작업대 | 누가 무엇을 하고 무엇을 넘겼는지 확인 | 역할별 병렬 행과 산출물, 선택한 전달의 상세 | 터미널처럼 과밀해지지 않게 하며 모바일에서는 같은 의미의 세로 목록 |
| C. 결정함 | 내 결정을 기다리는 항목 읽기 | 요청 목록과 읽는 문서, 변경·영향·검증·선택 | 결정이 없는 상태에서도 PM 대화와 진행을 바로 찾을 수 있게 함 |

초기 추천은 A를 기본 진입점으로, B를 진행 화면, C를 승인 화면의 표현으로 활용하는 것이다. 세 안은 제품 전체의 영구 양자택일이 아니다. 마스터가 PM과 주로 대화하고 팀은 병렬 작업하며 승인은 따로 본다는 목적을 따른 제안이다. 모든 화면을 동일한 배치로 통일할 필요는 없다.

시각적인 특징은 실제 한국어 글자 크기와 문장 흐름, 정보 밀도, 구분선·표면의 의미, 한 가지 절제된 강조색에서 정한다. Light와 Black은 동일한 정보 구조의 두 테마다. 장식용 3D·유리 효과·그라데이션·아바타를 개편의 대체물로 삼지 않는다.

명세 저장→새 계획 요청→계획 검토로 이어지는 현재 흐름도 조작 부담을 관찰한다. 통합 검토 화면은 설계할 수 있지만 명세 저장과 실행 승인 사건, 고정 버전, 직접 확정의 의미를 몰래 합치지 않는다. 서버 계약 변경이 필요하면 해당 변경을 별도 명세로 드러낸다.

## 스킬을 적용하는 방법과 강제의 한계

공통 본문은 [.agents/skills/ai-company-frontend/SKILL.md](../../.agents/skills/ai-company-frontend/SKILL.md)다.

| 연결 | 이 PR에서 준비하는 것 | 아직 보장하지 않는 것 |
|---|---|---|
| Codex | .agents/skills 아래 스킬 + 루트 AGENTS.md의 UI 작업 적용 지시 | 기존 실행 중인 서버 세션에 새 지침이 즉시 로딩됨 |
| Claude Code | .claude/skills의 짧은 진입 파일 + CLAUDE.md, 공통 본문 연결 | 현재 worker의 설정·작업 디렉터리에서도 자동 발견됨 |
| 검수 | 실제 화면·행동 근거와 독립 UX 검수를 완료 조건으로 지정 | 누락을 자동 거부하는 새 CI 검사 |
| 자동 배정 | UI 작업에 지침·선택 방향·검수 근거를 연결하도록 명시 | pilot 두 파일 제한이 UI 경로로 확대되거나 실행기가 수정됨 |

스킬 발견과 지침 준수는 완전히 같은 일이 아니다. `AGENTS.md`·`CLAUDE.md`는 작업 지침이고, 자동 차단은 별도 검사·배정기 구현이 있어야 한다. 미감 자체를 파일 존재나 작성자 점수로 자동 합격시킬 수 없다.

서버에서 새 UI 작업을 시작할 때 이 브랜치의 공통 본문을 실제 읽을 수 있는지 먼저 확인한다. Codex에서는 `$ai-company-frontend`, Claude Code에서는 `/ai-company-frontend`로 명시 호출할 수 있도록 각 프로젝트 경로를 준비했다. 실제 설치본의 발견·로딩은 서버에서 확인해야 하며 이 PR에서는 CLI 검증을 수행하지 않았다. 선택기에서 보이지 않으면 같은 파일을 명시적으로 읽어 작업하고, 이를 자동 로딩 성공으로 기록하지 않는다. 기존 worker를 이 확인 때문에 재시작하지 않는다.

자동 UI 업무에는 승인된 실행 명세의 UI 경로·검사·스킬 커밋/해시·선택 방향을 연결하고, 새 작업을 만들 때 그 버전을 고정하는 후속 연결이 필요하다. 이 설계 문서만으로 해당 기능이 이미 구현됐다고 보고하지 않는다.

## 완료 판단

시안 검토자는 다음 세 과제를 도움말 없이 수행하며 막힌 위치·불필요한 이동·잘못 이해한 상태를 기록한다. 동일한 데이터로 전후를 비교하되 자동 브라우저 성공을 실제 마스터 사용성 시험으로 바꾸어 적지 않는다.

1. 내가 하던 프로젝트를 찾아 PM의 현재 질문에 답할 위치 찾기.
2. 두 역할의 현재 일, 기다리는 이유, 실제 전달물을 찾아 설명하기.
3. 승인 요청이 무엇을 바꾸고 어떤 영향을 주는지 읽은 뒤 원문·근거와 선택 찾기.

구조 개편의 필수 결과는 추천/선택 방향, 핵심 화면의 Light·Black·모바일/데스크톱 캡처, 정상·빈 상태·대기·오류·긴 한국어, 실제 조작·포커스·중복 제출 관련 검증, 작성자와 별도 검수자의 구체적인 지적과 수정이다. 사용자 취향 선택과 제품 계획 확정, 후보 승인, 운영 적용은 서로 다른 결정이다.

PR #13 운영 적용·APK 직접 확인·서명키 외부 복원은 이 디자인 작업을 이유로 초기화하거나 완료 처리하지 않는다. 디자인 초안 검토는 독립적으로 진행할 수 있다.

## 서버 Codex에 전달할 지시

> 프런트엔드 작업에서는 이 PR의 ai-company-frontend 공통 스킬을 읽어 주세요. 최신 사용자 요청인 진행 그래프와 공통 모델 연결·현황 화면을 연결된 명세에 따라 구현 후보로 준비해 주세요. 초기 세 방향 선택을 다시 기다리지 마세요. 기존 운영 화면의 B형 틀을 고정하지 말고 사용자 과제와 정보 배치를 검토하되 이미 완료한 백엔드·격리·승인 계약은 보존하세요. PR13 실사용 검증과 독립적으로 진행하고, 제품에 반영했다고 보고하기 전 실제 렌더링·핵심 조작·독립 UX 검수 근거를 남겨 주세요. 이 지시는 운영 배포나 기존 pilot 실행 범위 확대 승인이 아닙니다.
