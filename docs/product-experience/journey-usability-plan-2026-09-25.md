## U1 — 승인·상태의 뜻과 범위

- 같은 관측 시각의 공통 표시 판단으로 목록·상세·건수·행동을 맞춘다. `pending` 원문, 기한, digest와 서버 판단은 변경하지 않는다.
- “결정할 요청”과 “조회된 요청”, “프로젝트 전체”와 “선택한 실행”을 구별한다. 범위가 다른 숫자를 억지로 일치시키지 않는다.
- 만료 요청의 승인·반려·수정 요청은 서버 정책과 맞게 표시·차단하고 다음 행동을 안내한다. 표시만 바꾸고 실제 요청 경계를 남겨 두지 않도록 대화상자와 제출 경계도 검수한다.
- 알려진 상태는 한국어를 먼저 보여 준다. 미확인 원문을 임의로 진행·완료로 분류하지 않으며 상세에서 근거를 확인하게 한다.
- 갱신 안내를 줄이되 R25-1b의 업무 쓰기 차단, 처리 중 요청 방어, 명시적 다시 불러오기와 주소·초안·멱등 키의 검증 범위를 보존한다. 모든 임시 입력이나 복구 성공을 보장하는 표현은 쓰지 않는다.

## U2 — 읽기와 조작

- 순서형 화면의 중요 상태·행동은 14px 이상, 핵심 본문은 16px 기준으로 조정한다. 큰 글자 자체를 접근성 검수 완료로 간주하지 않는다.
- 진행은 파랑·점선, 완료는 기존 녹색·실선, 대기와 확인 필요는 각 상태 글자와 테두리 강조로 구분한다. Light·Black의 기존 바탕·색 토큰은 유지하고 진행색만 제한적으로 보완한다.
- 본문 랜드마크의 `tabindex`와 건너뛰기 링크를 보존한다. 단계 이동 때 페이지 전체 외곽선 대신 `focus-visible` 표시를 좁게 제공하고, 개별 입력·버튼·링크의 키보드 초점은 유지한다.
- 의미 없는 빈 화면 장식은 줄이고 보고 없음의 의미를 짧게 설명한다. 모바일 머리글 간격과 건수 배지를 정리하며 프로젝트 전환·주요 탐색은 보존한다.
- CSS는 기준 제품의 기존 규칙을 보존한 순서형 범위 보완이다. 기존 그래프 배치 좌표·경로 계산·이동 동작을 스타일 변경으로 재정의하지 않는다.

## U3 — 진행·결과의 읽는 순서

- 통합 진행에서는 제목·실행 선택기를 한 번씩 표시한다. 독립 그래프의 자체 선택 기능은 유지한다.
- 결과는 결론 → 남은 일·차단 → 다음 행동 순으로 한 번씩 안내한다. 역할별 상세는 접어 두고 0건 그룹은 한 줄 집계로 남긴다.
- 선택 실행·snapshot·계획 해시·깊은 링크·뒤로가기와 그래프 카메라·선택·도움말 상태를 보존한다.
- 시스템 집계와 실제 PM 작성 보고를 분리한다. 실행에 연결된 문서라도 출처가 PM이 아니면 PM 보고로 세지 않는다. 없는 보고는 없다고 표시한다.
- 그래프의 조회 순서 같은 내부 정보는 상세로 옮긴다. 정렬이나 화면 위치를 실제 작업 순서로 해석하지 않는다.

## 같은 원인의 관련 경계 조사

`variant-analysis`의 알려진 결함 주변 경계 조사 방식으로 아래 연결점을 함께 대조한다. 표는 검사 범위와 보존 계약이며 최종 통과 판정이 아니다.

| 경계 | 확인할 문제 | 유지할 사실 |
| --- | --- | --- |
| 승인 목록·상세·상태 배지 | 상세만 만료로 보이거나 원문 pending을 결정 가능으로 표시하는 불일치 | 같은 관측 시각의 표시 상태, 원문 pending·기한은 그대로 |
| 승인 건수·탐색 배지·결과 행동 | 전체 건수와 결정 가능 건수 혼용, 다른 실행 요청으로의 연결 | 범위가 드러나는 문구와 정확한 실행·요청 링크 |
| 승인 대화상자·제출 | 목록에서 숨긴 만료 요청을 기존 버튼·열린 대화상자로 제출 | 표시 방어와 별개인 서버 검증·digest·멱등 키 |
| 한국어 상태 배지·미확인 상태 | 알려진 영문 코드 노출 또는 모르는 상태의 성공 오분류 | 읽기용 한국어와 원문 근거의 분리 |
| 결과 요약·보고 CTA | 완료된 개발 안내가 검수 단계까지 남거나 다음 행동 중복 | 실제 실행 상태에 따른 결론과 정확한 범위 |
| PM 보고 출처 | 연결된 시스템 문서를 PM 작성물로 합산 | 문서의 실제 출처·실행 연결·원문 보존 |
| 갱신 안내·혼합 모듈 | 안내 축약·새 DOM이 R25 쓰기 차단과 복구를 약화 | 기존 네 조합, 처리 중 방어, 주소·초안·멱등 키 |

## 검수 설계

1. 정확한 제품 함수 또는 임시 API에서 만료 전·정확 경계·만료 후, 갱신 전후, 다른 실행, 요청 없음, 완료·반려를 확인한다. 고정 fixture 기한을 늘리거나 원문을 변경해 검사를 통과시키지 않는다.
2. 인증된 격리 브라우저에서 같은 실행의 진행 → 승인 발견 → 대상·영향 확인 → 결과·근거 열람을 조작한다. 운영 DB·실제 마스터 승인·모델 호출을 사용하지 않는다.
3. Light/Black × 320/390/1440px에서 같은 데이터·폭·테마·펼침 상태로 전후 캡처를 만든다. 긴 이름·빈 화면·대기·차단·만료·갱신 필요의 줄바꿈과 중요 글자 크기·대비를 검사한다.
4. Tab·Shift+Tab·본문 건너뛰기·단계 이동 후 다음 Tab·확대를 확인한다. CSS 선언색 대비 계산은 보조 근거이며 실제 렌더 검사를 대신하지 않는다.
5. R25 혼합 모듈 네 조합, 업무 쓰기 차단, 초안·주소·멱등 키, 상태 분류, 정확한 실행 연결, 응답 경합, G1~G3의 영향 회귀를 유지한다.
6. 별도 검수자는 작성자의 캡처 설명만으로 합격시키지 않고 실제 화면·조작·원본을 대조한다. 작성자 자체 검사와 독립 검수의 수행자·방법을 구분한다.

적용 지침은 저장소 `ai-company-frontend`와 설치된 `web-design-guidelines`다. 색·크기·초점·터치·한국어·좁은 화면의 영향에 한정해 사용하며 스킬 적용 사실을 사용성 검증으로 보고하지 않는다.

## 후보·패키지와 승인 경계

이번 완료 조건은 **새 제품 후보의 구현, 관련 검사, 독립 검수, 원격 CI, 검토 가능한 초안 PR, 미리보기와 해시, 새 이미지 및 적용·복구안**이다. 문서 작성 시점에는 이 최종 근거가 모두 고정되지 않았으므로 검사·CI·이미지 완료를 주장하지 않는다. 후속 검증 기록은 제품·검사·게시 SHA와 근거를 구분해야 한다.

새 후보는 이전 `ffb62c3` 이미지나 해시를 재사용하지 않고 같은 소스로 새 이미지를 만들며 설치 소스·정적 자원 일치를 검증한다. 공개 ZIP은 로그인 없이 내려받아 검증하고, 원문과 관계없는 개인정보·인증 자료·내부 접속 정보는 포함하지 않는다.

운영 적용은 이번 권한에 포함되지 않는다. 후속 적용안은 **웹 컨테이너 한 개의 후보 교체**를 중심으로 현재 버전 대조, 정상 종료, 필수 접속·정적 자원·기록 보존 검사, 실패 시 직전 웹 이미지 복구를 구체화한다. API·DB·worker·카탈로그·모델·예산·재시도·공유 한도·서명키는 변경하지 않는다. DB를 과거 백업으로 되돌려 기록을 지우는 절차를 만들지 않는다.

실제 배포가 필요하면 고정 후보와 영향·복구안을 별도로 승인받아야 한다. 기존 승인을 다른 제품 해시로 확대 해석하지 않는다. 병합, PR #10 pending 변경, 커플 서비스·운영 타이머·큐 변경도 제외한다.

APK 직접 조작과 공개 도메인의 실제 갱신은 이번 격리 웹 검증과 구분한 미검증 항목이다. 이를 대신 완료 처리하거나, 이 확인을 기다린다는 이유로 가능한 비운영 개발을 멈추지 않는다.
