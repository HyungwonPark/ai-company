# 모델 연결: 로그인과 모델 현황

상태: 사용자 요청을 반영한 구현 명세 · 2026-09-16 · v1.0

## 사용자 경험과 우선순위

프로젝트 바깥의 공통 메뉴에 **모델**을 둔다. 제공자별로 계정을 연결하고, 어떤 모델을 어느 역할에 쓸 수 있는지 확인한다. 프로젝트의 매니저·진행·승인·기록 동선을 유지한다. 모바일에서는 공통 메뉴로 접근하고 프로젝트 하단 탭을 계속 늘리지 않는다.

기본 흐름은 **모델 → 연결 추가 → 제공자 선택 → 공식 로그인 → 연결 확인 → 실행 확인 → 역할 배정**이다. 기존 서버 계정은 먼저 상태를 가져오므로 정상 계정에 다시 로그인하도록 요구하지 않는다. 로그인과 실행 확인을 마쳐도 프로젝트는 마스터의 계획 확정 뒤에 실행된다.

[역할·업무 그래프](graph-workspace-2026-09-16.md)와 같은 후속 작업에 포함하되, 로그인 연동 완성을 그래프 개발의 선행 조건으로 만들지 않는다. 이 문서는 구현 지시이며 새 화면·로그인 기능의 구현이나 운영 적용 증거가 아니다.

## 첫 화면

| 영역 | 보여 줄 내용 | 가능한 행동 |
|---|---|---|
| 연결 | 제공자, 사용자 별칭, 마스킹한 계정, 로그인 상태, 마지막 확인 | 연결 추가, 상태 확인, 재로그인 |
| 모델 | 모델명, 요청 추론 설정, 관측된 설정과 확인 시각, 사용 가능한 역할 | 실행 확인, 역할 후보 선택 |
| 가용성 | 사용 가능·사용량 대기·확인 필요, 알려진 재개 시각, 영향받는 역할 | 대기 이유·이관 이력 보기 |
| 사용 중 | 연결을 쓰는 프로젝트·역할·진행 중인 작업 | 해당 프로젝트 그래프·상세로 이동 |

계정마다 다시 큰 카드를 반복하기보다 연결 목록과 선택 상세를 사용한다. 빈 상태에서는 연결 추가가 첫 행동이고, 기존 계정이 있으면 상태 가져오기가 첫 행동이다. APK에서 외부 브라우저로 로그인한 뒤 돌아왔을 때 선택과 로그인 진행 상태를 복구한다.

표시는 다음 세 축을 분리한다.

- **로그인:** 미연결 / 로그인 중 / 연결됨 / 다시 로그인 필요 / 확인 실패.
- **모델 검증:** 미검증 / 사용 가능 / 제한됨. 로그인되었다고 모든 모델과 effort를 사용 가능으로 표시하지 않는다.
- **실행 가용성:** 사용 가능 / 사용량 대기 / 사용 중지 / 확인 필요. 인증 실패를 사용량 대기로 처리하지 않는다.

남은 토큰이나 리셋 시각을 공식 응답에서 얻지 못하면 확인 불가로 표시한다. 마지막 관측 시각을 표시하고 오래된 값은 현재 값으로 꾸미지 않는다. 호출 사용량·구독 한도·누적 작업 예산은 서로 다른 수치다.

## 연결과 모델, 역할의 관계

한 계정 연결에 여러 모델 후보를 연결한다. Astra High와 Ultra는 모델의 추론 설정 차이이며 별도 로그인이나 독립 한도로 만들지 않는다. 역할은 계정이 아니라 검증된 모델 후보와 연결 버전을 선택한다.

첫 지원 범위는 **Codex 한 연결과 Claude Code 한 연결**이다. 같은 제공자에 여러 계정을 추가하는 기능은 현재 저장 구조와 실행 환경 선택을 확장한 뒤 제공한다. 미지원 상태에서 연결 행만 여러 개 만들어 같은 인증을 다른 계정인 것처럼 표시하지 않는다.

연결 관리 화면에서 고른 후보는 다음 계획의 제안에 반영한다. 기존 확정 계획·실행의 제공자, 연결, 모델·effort, 정책 버전은 그대로 고정한다. PM과 최종 검수자의 Astra Ultra 조건을 개발 대체 정책으로 변경하지 않는다. 필수 역할이나 모든 적격 후보가 대기 중이면 완료를 보장하지 않고 이유를 표시한다.

역할 후보 선택은 서버에 설치·검증된 카탈로그 범위 안에서만 한다. 웹 입력으로 새 모델·effort·권한·검증 근거를 등록하거나 허용 범위를 확대하지 않는다. 새 제공자와 후보의 등록은 서버 어댑터·정책 검증을 먼저 거친다.

## 공식 로그인 방식

확인한 공식 문서에 따른 시작점이며 설치된 CLI와 실제 worker 환경에서 지원을 확인해야 한다.

| 제공자 | 첫 연결 방식 | 확인할 사항 |
|---|---|---|
| OpenAI / Codex | 공식 CLI의 `codex login --device-auth`로 링크·일회용 코드를 안내 | 계정의 device-code 로그인 허용 여부, 제한 시간, 동일 worker 인증 환경의 상태 확인 |
| Anthropic / Claude Code | 공식 CLI의 `claude auth login`과 제공자가 여는 브라우저 인증 | 원격 환경의 콜백 또는 일회용 코드 입력 완료, 구독/Console 등 실제 인증 방식, `claude auth status` |
| 기타 AI | 제공자별 연결 어댑터를 구현한 뒤 표시 | 구독 로그인, API 키, 클라우드 자격 증명, 로컬 주소 중 실제 지원 방식 |

Codex의 device-code 방식과 Claude의 브라우저/코드 반환을 같은 프로토콜이라고 가정하지 않는다. Claude 원격 로그인 자동화가 설치본에서 확인되지 않으면 구체적인 안내와 미완료 상태를 유지한다. 비공식 OAuth 엔드포인트나 토큰 추출로 대체하지 않는다.

로그인은 공식 CLI 안에서 완료하고 실행도 그 CLI를 사용한다. 구독 인증 토큰을 추출해 직접 API에 보내거나 자체 OAuth 클라이언트를 흉내 내지 않는다. 다른 AI가 모두 구독 로그인만으로 연결된다고 약속하지 않는다. Bedrock 등 클라우드 연결도 별도 인증·실행 어댑터가 필요하다.

공식 문서: [OpenAI 인증](https://learn.chatgpt.com/docs/auth), [Claude 인증](https://code.claude.com/docs/en/authentication), [Claude CLI](https://code.claude.com/docs/en/cli-reference). 문서 지원은 이 제품의 연동 검증 완료를 의미하지 않는다.

## 서버 구현 계약

1. **기존 계정 가져오기:** 인증 파일을 이동·출력하거나 재로그인하지 않고 기존 worker의 인증 방식과 상태를 조회한다. API 키 등 우선순위 높은 설정이 로그인 계정보다 먼저 적용되는지 확인하여 실제 사용 연결을 표시한다. 조회 버튼과 화면 새로고침은 모델을 호출하지 않는다.
2. **연결 레코드:** connection_id, provider, 표시 별칭, 인증 방식, 서버 내부 인증 참조, 버전, 확인 시각, 상태, 공유 한도 식별자를 관리한다. 비밀 값은 관리 DB·API·Git·브라우저 저장소에 넣지 않고 공식 CLI의 지원 저장 방식과 서버 접근 제어를 사용한다.
3. **로그인 작업:** 마스터 세션에 묶인 제한 시간·취소·중복 방지 기능을 둔다. 허용된 CLI와 명령만 실행하며 웹에서 임의 실행 파일·환경·경로를 받지 않는다. 공식 HTTPS 로그인 주소만 안내하고 계정 비밀번호는 받지 않는다. 공식 흐름에 필요한 일회용 코드는 해당 마스터의 인증된 화면과 살아 있는 로그인 프로세스 사이에서만 취급하고 저장·로그에 남기지 않는다.
4. **인증 보존:** 정상 연결이 있는 상태에서 새 로그인으로 기존 공유 인증을 덮어쓰지 않는다. 지원되는 독립 인증 저장소와 실행 선택을 검증한 뒤 새 연결을 만들고, 기존 연결 교체는 사용 중인 작업과 재개 세션을 먼저 확인한다. 서버 전체 로그아웃을 기본 동작으로 쓰지 않는다.
5. **실행 환경 일치:** 연결 검사와 실제 worker가 같은 실행 파일·서비스 사용자·인증 컨텍스트를 사용해야 한다. 연결별 선택을 주 실행·재개·번역·자식 프로세스에 전달한다. 이전 연결의 세션을 새 계정으로 조용히 재개하지 않는다. 인증 격리 지원이 확인되지 않으면 다중 계정 기능을 열지 않는다.
6. **실행 확인:** 사용자가 실행 확인을 누르면 사용할 모델·목적·호출 한도를 보여 주고 그 범위의 작은 호출을 한다. 명시된 제한을 넘지 않는다. auth 상태, 실제 모델 호출, 관측 effort/기능 증거를 따로 기록하며 증거가 없는 설정은 미확인으로 둔다.
7. **한도·권한 유지:** 재로그인·연결 재등록·이름 변경으로 공유 한도와 누적 예산을 초기화하지 않는다. 계정 식별이 불명확하면 독립 한도로 단정하지 않는다. 연결 성공으로 후보 enabled·역할 적격성·프로젝트 승인·배포 권한을 자동 변경하지 않는다.
8. **사용 중지:** 첫 제공 동작은 새 작업 배정 중지다. 진행·예약 작업에 미칠 영향을 보여 주고, 인증 삭제/로그아웃은 별도 동작으로 다룬다. 로그인 취소·만료·서버 재시작은 로그인 프로세스와 상태를 정리하며 개발 작업을 종료하지 않는다.

실행 확인 호출도 기존 공유 한도·동시 실행 용량·예산 조정 경로를 사용한다. 호출 전 예약과 중복 요청 방지를 적용하고 cooldown 중에는 실행하지 않는다. 종료 여부가 불명확하면 기록을 대조하기 전 자동 재호출하지 않으며, 비용을 모르면 0으로 처리하지 않는다. 반복 클릭·서버 재시작으로 확인 예산이나 기존 작업의 한도를 우회할 수 없어야 한다.

관리 API는 기존 마스터 인증·권한과 요청 위조 방지를 적용한다. 제공자 로그인 작업과 마스터 로그인 세션을 혼용하지 않는다. 로그인 링크·코드를 공개 이벤트, 번역 큐, 에이전트 프롬프트, 원격 로그에 포함하지 않는다.

새 제공자 추가에는 인증 상태 외에 실행·취소·결과·한도·비용·재개 기능의 공통 계약과 정책 확장이 필요하다. 같은 제공자 재개와 다른 제공자로의 체크포인트 인수인계를 구별한다.

## 구현 순서와 수용 조건

1. 실제 기존 계정·모델 후보를 읽는 모델 목록과 상세를 먼저 제공한다. 그래프의 모델 표시는 같은 자료로 연결한다.
2. Codex·Claude 공식 로그인 연결을 구현하고 로컬 모의 검증 후 실제 설치본에서 마스터가 로그인하는 경로를 확인한다. 사용자 조작이 필요한 마지막 단계 전에 화면과 실행 경로를 준비한다.
3. 제한된 실행 확인과 프로젝트 역할 후보 연결을 추가한다. 기존 확정 실행을 수정하지 않는다.

검증할 사용자 과제는 “어떤 계정이 연결됐는가”, “이 역할이 왜 기다리는가”, “새 제공자를 어디서 연결하는가”, “로그인 후 어떤 모델이 실제 검증됐는가”다. Light·Black·모바일/PC에서 실제 화면·외부 로그인 복귀·키보드 동선을 확인한다.

인증 계정과 실행 계정 불일치, 로그인 취소/만료/중복, 재접속, CLI 미설치/지원 불가, 잘못된 인증, quota 대기, 요청/관측 모델 차이, 재로그인 중 작업 보존을 검증한다. 연결 재등록이 같은 계정의 대기 상태를 해제하지 않는지도 확인한다. 모의 인증 결과를 실제 로그인 성공으로 기록하지 않는다.

서버 Codex는 이 문서와 프런트엔드 스킬을 읽고 **그래프 화면과 모델 연결 화면의 구현 후보**를 준비한다. 기존 커플 서비스·큐·타이머, PR #10 pending, 마스터 직접 APK 계획 확정과 서명키 외부 복원 항목을 보존한다. 이 명세 추가는 운영 배포·자동 병합이나 pilot 허용 파일 확대가 아니다.
