# 역할 그래프 연결선 가독성 개선 명세

작성: 2026-09-17 · v1.1  
대상: HyungwonPark/ai-company · 서버 Codex 구현용  
상태: 코드·예시 화면 검토를 바탕으로 한 작업 명세. 이번 명세의 개선 사항은 아직 구현·검증되지 않았다.

## 1. 역할과 진행 방식

- **마스터:** 사용자 목표와 변경 범위를 결정하고 실제 계획 확정·운영 적용을 승인한다.
- **서버 Codex:** 현재 서버 작업 공간에서 구현, 재현, 테스트, 미리보기 제작, Git 기록을 수행한다.
- **이 대화의 검수자:** 명세와 수용 기준을 작성하고, 서버가 제출한 고정 커밋·화면·조작 증거를 검토한다. 구현 코드를 직접 수정하거나 서버 대신 배포하지 않는다.

진행 순서는 **명세 전달 → 서버 구현·검증 → 고정 후보 제출 → 검수 → 필요한 수정**이다. 검수 통과와 운영 배포 승인은 별개로 유지한다.

## 2. 이번 목표

마스터가 그래프에서 **누가 누구에게 무엇을 전달했는지** 화살표를 따라 읽을 수 있게 한다. 특히 같은 역할로 모이는 선, 같은 줄의 역할 간 연결, 수정 반환, 담당자 이관을 구분한다.

선의 색이나 굵기만 바꾸는 것으로 끝내지 않는다. 기본 배치의 연결점·경로·이름표·선택 동작을 함께 개선한다. 불필요한 반복 애니메이션은 추가하지 않는다.

## 3. 확인한 기준과 결함

검토 기준은 [PR #18](https://github.com/HyungwonPark/ai-company/pull/18)의 `53ee2df8a578b4424a9db714534e1bad12518cc3`이다. PR #17 위에 문구·그래프 조작 개선이 추가된 후보이며, 운영 적용 완료를 뜻하지 않는다.

작업 시작 시 서버의 현재 브랜치·변경 상태와 원격 PR HEAD를 다시 확인한다. 후속 변경이 있으면 보존하여 이어가고, 이 문서의 과거 SHA로 강제 되돌리지 않는다.

| 확인한 문제 | 코드·예시에서 확인한 원인 | 사용자에게 생기는 문제 |
|---|---|---|
| 여러 화살표가 같은 곳에 도착 | 대부분의 선이 출발 카드 하단 중앙과 도착 카드 상단 중앙을 공유 | 개발·검사의 결과 보고를 구분하기 어려움 |
| 자기 역할로 돌아오는 이관선이 숨음 | 같은 노드 사이의 이관에도 일반 하향 곡선을 사용 | 담당자가 바뀐 기록을 그래프에서 찾기 어려움 |
| 같은 줄의 역할 간 연결이 대각선으로 섞임 | 개발→검사 의존 관계도 하단→상단 곡선으로 연결 | 병렬 역할의 의존 관계와 아래 단계 전달이 혼동됨 |
| 반환·상향 보고의 경로가 부적절 | 수정 반환만 특수 처리하며 역할→PM 보고 등은 일반 경로 사용 | 이전 실행의 보고가 다른 카드·선과 섞일 수 있음 |
| 이름표 위치가 겹침 | 관계별 공간 대신 배열 순서의 홀짝으로 위치를 조금 변경 | ‘결과 보고’ 등의 글자가 가까이 몰려 선과 대응하기 어려움 |

최근 예시 실행에는 관계 9건이 있고, 자기 이관 2건·동일 행 의존 관계·두 역할의 검사 합류·독립 검수의 수정 반환이 포함된다. 이전 실행에는 역할→PM의 상향 보고도 있다. 이 사례들을 재현 기준으로 사용한다.

근거는 해당 커밋의 `workspace-graph-ui.js`, `workspace-graph.css`, `graph-preview/fixture.json`과 320px Black 캡처다. 운영 데이터 전체에서 발생하는 빈도를 조사한 결과는 아니다.

통합 후 최종 커밋에서 CI와 화면·조작 검수를 다시 수행한다. 기존 두 PR의 개별 성공 결과를 통합 후보의 결과로 대신하지 않는다.

## 4. 구현 요구사항

### 4.1 연결점과 경로

1. 같은 카드로 들어오거나 나가는 관계는 연결점을 분산해 화살촉이 한 점에 합쳐지지 않게 한다.
2. 같은 출발·도착 사이의 여러 기록도 각각 식별·선택할 수 있게 한다. 기록을 지워 겹침을 해결하지 않는다.
3. 같은 행의 역할 간 연결은 카드 본문을 가로지르지 않는 경로를 사용한다.
4. 수정 반환과 상향 보고는 일반 하향 전달과 구별되는 우회 경로를 확보한다. `revision_return` 외의 상향 관계도 처리한다.
5. 자기 이관은 해당 카드의 바깥에서 출발·도착을 구별할 수 있는 루프로 표시한다. 다른 역할로 업무가 옮겨진 것처럼 표현하지 않는다.
6. 기본 배치에서 선이 관계없는 카드 본문을 통과하지 않게 한다. 필요한 여백은 노드 배치·행 간격과 함께 조정한다.

직교선·둥근 모서리·곡선 중 구현자가 적합한 방식을 선택한다. 새 프레임워크나 그래프 엔진 도입은 이번 수정의 선행 조건이 아니다. 선택 이유와 남는 교차 사례를 짧게 기록한다.

### 4.2 이름표와 선택

1. 최근·이전 fixture와 별도 중복 관계 검증 사례의 기본 배치에서 관계 이름표가 다른 이름표·카드·화살촉과 겹치지 않게 한다. 배경을 둘 경우 실제 선의 방향을 가리지 않도록 한다. 이 기준은 임의 규모의 모든 그래프에 완전한 무겹침을 보장하라는 요구는 아니다.
2. 선 또는 이름표를 누르면 **그 관계의 정확한 edge ID**에 연결된 상세를 연다. 두 요소를 별도의 중복 Tab 정지점으로 만들 필요는 없다.
3. 선택한 선의 출발·도착 카드, 경로, 화살촉, 이름표를 함께 강조한다. 다른 선은 읽을 수 있는 수준으로 약하게 표시하고, 선택 해제 시 원래 표현으로 돌아온다.
4. 색상 외에도 화살촉·이름표·선택 표시로 방향과 관계를 구분한다. 예정 관계의 점선과 기록된 관계의 실선 의미를 보존한다.
5. 넓은 투명 클릭 영역이 인접한 선의 선택을 가로채지 않게 한다. 모바일에서는 이름표 등 확실하게 누를 수 있는 대상을 제공한다.
6. 그래프와 목록은 같은 관계와 원문 근거를 제공한다. 보기에서 일부 관계를 강조하더라도 데이터가 삭제되거나 조회 건수가 달라지지 않는다.

### 4.3 이동·확대·갱신

1. 노드를 조금 움직였을 때 연결점이 갑자기 반대편으로 넘어가거나 경로가 크게 뒤집히지 않아야 한다. 관계 ID와 안정적인 배치 기준으로 경로를 결정한다.
2. 최초 렌더, 마우스·터치 드래그, 키보드 이동이 같은 경로 계산을 사용한다. 이름표·배경·클릭 영역도 선과 함께 움직인다.
3. 서버 응답 배열의 순서만 바뀌거나 같은 응답이 다시 와도 기존 선의 배치를 불필요하게 바꾸지 않는다.
4. ‘맞춤’은 카드뿐 아니라 외곽 경로·화살촉·이름표를 포함한다. 전체 맞춤으로 글자가 작아질 수 있으므로 확대·이동 후 읽을 수 있어야 한다.
5. 320/390px에서 페이지 전체의 가로 넘침을 만들지 않는다. 필요한 탐색은 그래프 안의 이동·확대를 사용하며 모바일에서 선을 숨기지 않는다.
6. 기존 선택·확대·화면 크기별 위치 기억, 조작 중 응답 보류, 상세 읽기 위치, 키보드 초점 동작을 보존한다.

임의로 카드를 서로 겹치도록 이동한 모든 배치에서 교차가 0개일 것을 요구하지 않는다. **기본 배치의 가독성과 이동 후 관계 추적 가능성**을 검수한다. 해결하지 못한 배치는 숨기지 말고 증거와 함께 제출한다.

## 6. 수용 기준

| 항목 | 통과 조건 | 제출할 근거 |
|---|---|---|
| 합류 | 개발·검사의 보고선과 화살촉을 각각 따라가고 선택할 수 있음 | 기본 화면·각 선 선택 화면, 선택한 edge ID 대조 |
| 병렬 역할 | 동일 행 의존선이 카드 본문을 가로지르지 않으며 결과 보고와 구분됨 | 해당 구간 확대 화면 |
| 자기 이관 | 두 이관 루프가 카드 밖에서 보이고 각각의 상세를 열 수 있음 | 두 건의 실제 포인터 조작 결과 |
| 반환·상향 보고 | 수정 반환과 역할→PM 보고가 출발·도착 방향을 유지하고 클릭 가능 | 최근·이전 실행 각각의 화면·조작 결과 |
| 중복 관계 | 동일 노드 쌍에 여러 관계가 있어도 하나로 소실되지 않음 | 기존 또는 별도 합성 사례의 개별 선택·목록 대조 |
| 이름표 | 기본 배치에서 이름표가 겹치거나 카드 뒤에 숨지 않음 | Light·Black의 320/390/1440px 기본 화면 |
| 맞춤·탐색 | 외곽 선·화살촉·이름표까지 맞춤 범위에 포함되고 확대 후 탐색 가능 | 맞춤·확대·이동 조작 결과 |
| 안정성 | 위아래 교차 이동, 화면 폭 변경, 5초 갱신에도 점프·선택 손실·클릭 가로채기가 재발하지 않음 | 기존 회귀 및 변경된 위험에 대한 검사 |
| 권한·기록 | 화면 조회·조작이 실행·승인 쓰기를 발생시키지 않고 같은 실행의 상세를 유지함 | 기존 읽기 API·쓰기 경로 회귀 결과 |

캡처 수를 채우는 데 그치지 않고 반환·이관·합류가 실제로 보이는 구간을 포함한다. 작은 화면에서는 필요한 부분을 이동·확대한 캡처를 함께 제공한다. 색상·대비·글자 크기를 줄여 겹침을 감추지 않는다.

기존 브라우저의 ‘어느 선 하나라도 클릭 가능’ 검사만으로 완료 처리하지 않는다. 위 관계별로 물리적인 포인터 선택을 확인하고, 키보드 선택과 같은 edge ID로 연결되는지 대조한다. 테스트 횟수·개수 자체를 완료 목표로 삼지 않는다.

## 7. 서버 작업 순서와 제출물

1. 현재 변경 상태·PR HEAD를 확인하고 기존 작업을 보존한다. 이 명세는 `docs/product-experience/graph-edge-readability-2026-09-17.md`를 기준으로 읽는다. 아직 작업 분기에 없으면 해당 문서만 가져와 반영한다.
2. 같은 fixture로 수정 전 문제를 재현한다. 최근 실행과 역할→PM 보고가 있는 이전 실행을 모두 확인한다.
3. 이번 범위의 경로·이름표·선택 동작을 구현한다. 기존 동작 검사를 유지하고 확인한 결함에 필요한 검사를 보강한다.
