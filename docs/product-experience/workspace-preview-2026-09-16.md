# 작업실 구조 비교 · 2026-09-16

상태: 구조 비교·작동 미리보기·격리 브라우저·독립 검수 완료. 사용자 디자인 선택·운영 적용·실기기 검증은 아니다.

PR #14 `7cc52fe`의 `ai-company-frontend` 스킬을 명시적으로 읽고 적용했다. CLI 자동 발견이나 운영 worker 탑재를 검증했다고 보고하지 않는다. 기반은 PR #13 운영 적용 기록 `f933391`; 별도 `feat/frontend-workspace-redesign` 브랜치에서 작업한다.

## 사용자 과제와 설계 판단

같은 이름·목표·현재 PM 질문·두 역할의 진행/대기·전달물·이전 후보 승인 요청을 세 안에 사용한다. 현재 실행과 이전 후보의 실행 ID를 구별한다. 시안 전환만으로 데이터는 바뀌지 않으며 조작 결과는 예시 상태로만 남는다.

1. 하던 프로젝트를 찾아 PM 질문에 답한다.
2. 두 역할의 현재 일·대기 이유·전달물을 확인한다.
3. 후보 승인 대상·영향·원문·근거를 읽고 선택할 위치를 찾는다.

기존 모바일 캡처에서는 프로젝트 판단 전 반복 헤더/메타데이터가 약 480px를 사용했다. 이름과 다음 행동 중심의 평면 목록으로 바꾸고 세부 실행 상태는 프로젝트 안으로 옮긴다. PM 대화는 16px 본문, 현재 질문과 입력을 함께 배치한다. 전면 카드 격자 대신 문서·행·목록-본문을 선택한다. 색상은 Light/Black과 절제된 녹색 강조를 공유하지만 첫 화면·정보 순서·조작 위치를 바꾼다.

| 비교안 | 기본 진입과 구조 | 같은 업무를 보는 방식 |
|---|---|---|
| A 작업실 · 추천 | 프로젝트 탐색 + 대화 본문 + 간결한 팀 요약 | PM 질문에 먼저 답하고 실행 범위를 이어 검토 |
| B 작업대 | 병렬 역할 행 + 전달 기록 + 선택 상세 | 역할과 대기를 먼저 파악하고 PM/결정으로 이동 |
| C 결정함 | 요청 목록 + 읽는 문서 | PM 질문·대기·후보 요청을 목록에서 골라 원문·영향을 읽음 |

A를 추천하는 이유는 목표를 PM과 구체화하는 일이 시작점이기 때문이다. B의 병렬 행과 C의 읽기 중심 승인 문서는 각 화면의 표현으로 활용한다. 이는 제작자의 추천이며 사용자가 선택한 디자인으로 기록하지 않는다.

## 핵심 동선과 보존 경계

이름/자연어 목표 → PM 제안 → 명세 저장 → 새 계획 요청 → 직접 계획 검토·확정 → 역할 진행 → 후보 검토를 예시로 조작한다. 명세 저장은 실행을 만들지 않는다. 새 계획은 저장 명세 버전/해시에 묶이며 다른 프로젝트·변경된 명세·잘못된 승인 대상에는 선택을 기록하지 않는다. 요청 모델과 관측 근거, 원문과 읽기용 번역을 구별한다.

미리보기는 별도 `workspace-preview/`의 HTML/CSS/JavaScript이다. 운영 UI·서버 계약·큐·계정·예산은 수정하지 않는다. `/api/` 요청과 모델 호출은 없으며 이 페이지의 예시 영수증은 운영 승인으로 사용할 수 없다. 기존 제품 회귀를 유지하고 실제 운영 작업·APK 직접 확정 검증과 분리한다.

## 독립 검수와 수정

작성자와 별도 에이전트 `frontend_ux_reviewer`가 실제 캡처를 확인했다. 독립 검수자는 모델 검사를 직접 실행하고 별도의 `tests/ui/workspace_independent.cjs` 조작 검사를 작성했다. 그 검사를 원격의 샌드박스 유지 Chrome에서 실행했다. 검수자가 실제 마스터 APK를 조작한 것으로 표시하지 않는다.

| 검수 지적 | 수정·확인 |
|---|---|
| 새 실행의 보고에 이전 결과가 표시됨 | 새 실행은 실제 실행 전 보고로 분리. 이전 보고는 실행 ID와 출처 명시 |
| 빈 프로젝트에도 검사 대기·승인 요청이 있는 것처럼 안내 | 프로젝트별 phase와 요청 유무에서 다음 행동·요청 목록 도출 |
| 응답 유실 후 입력 변경·갱신으로 오래된 저장 키 재사용 | 원래 요청 본문과 키 보관, `저장 결과 확인`으로 해결. 복구 중 연결/권한 오류에도 원 요청 보존 |
| 초기화 직후 pagehide가 과거 예시 상태 복원 | 초기화 시 저장 중지, 다음 로드에서 새 예시 생성 |
| 320px 한국어 제목·버튼 문장이 단어 중간에 끊김 | 단어 단위 줄바꿈과 긴 식별값의 안전한 개행 적용 |
| C 모바일에서 진행·보고가 가로스크롤 밖으로 숨음 | 네 항목이 보이는 2×2 목록 |
| A 모바일의 긴 상단 탐색 | 중복 경로·탐색 제거, 첫 질문과 답변 앞 간격 축소 |
| 짧은 탭의 터치 너비가 44px 미만 | 보이는 버튼 최소 너비·높이 44px 검사 |

독립 시각 검수의 관찰: 390px 같은 예시에서 기존 PM 질문은 약 y=958, A 질문은 약 y=359에 있다. A 답변란은 약 y=644로 앞당겨져 844px 첫 화면에서 전송 버튼까지 찾을 수 있다. 이는 캡처의 위치 비교이며 실제 사용자의 과제 수행 시간·선호도 측정이 아니다. A 기본 진입 + B 진행 + C 승인 활용을 추천하며 **마스터가 확정한 디자인은 아니다.**

## 실행한 검증과 범위

- `tests/ui/workspace_model.cjs`: 동일 키 동시 요청, 응답 유실 복원, 프로젝트 분리, 오래된 계획 거부, 고정 실행의 명세 불변, 후보 대상 일치.
- `tests/ui/workspace_preview.cjs`: 세 구조 × Light/Black × 320/390/1440 렌더링, 같은 과제 비교, 횡스크롤 없음, 빈/대기/오류/오프라인/긴 한국어/번역 대기/읽기 권한/잘못된 링크, 입력·초점·선택 위치 복구, 키보드 생성·Esc 초점 복원, 200% 텍스트 스트레스, 보이는 버튼 44px, 계획 확정 전 0실행·확정 뒤 1실행, 오프라인 단일 파일 동작.
- `tests/ui/workspace_independent.cjs`: 별도 검수자가 작성한 네 묶음. 프로젝트 간 승인/전달 혼입 없음, 미확정 요청의 권한/연결 실패 후 복구, 명세 v2와 변경 digest 거부·실행 1건, 후보 digest 불일치 거부·원본 pending 보존.
- `tests/ui/workspace_baseline.cjs`: 같은 예시 데이터를 기존 제품 화면에 연결, 읽기만 수행.
- 기존 상태·관리 UI 회귀 및 원격 Python CI도 유지한다. 기존 제품 `app.js`, 관리 API·worker·DB는 수정하지 않았다.

## 미리보기 사용과 남은 경계

[작동 미리보기 다운로드](https://github.com/HyungwonPark/ai-company/actions/runs/35106364788/artifacts/10450287665)의 `AI-Company-preview.html`을 내려받아 압축을 풀고 브라우저에서 연다. 서버·로그인 없이 동작하며 외부 리소스와 운영 API를 요청하지 않는다. 상단에서 A/B/C와 Light/Black을 비교한다. `프로젝트 → 새 프로젝트 → 이름·목표 → PM과 시작 → 명세 저장 → 새 계획 요청 → 계획 검토 → 계획 확정`을 직접 눌러볼 수 있다. 실제 모델 응답·실행·승인 대신 예시 상태만 바뀐다.

[재생성 명령과 조작 설명](../../src/ai_company/web/workspace-preview/README.md)을 남겼다. 다운로드 파일의 보관 기한은 30일이며 원본 소스와 생성기는 Git에 보존된다.

이번 완료 범위는 **구조 비교·작동 미리보기·한국어/모바일/조작 검수·초안 PR**이다. 실제 API 연결과 제품 화면 교체는 하지 않았다. 실제 연결 시 기존 PR #13의 하네스 버전, 명세·계획·승인 digest, 읽기용 번역 참조, 세션/CSRF, 예산·적격성·CI 출처 규칙을 그대로 사용해야 한다. 예시 `model.js`를 운영 계약의 대체물로 사용하지 않는다.

운영 배포·병합·프로젝트 생성·계획 확정·PR #10 승인에 대한 요청을 전송하지 않았다. 기존 웹·worker·커플 서비스·큐·기록은 이 작업에서 변경하지 않았다. APK 직접 입력/확정, 서명키 외부 보관/복원은 별도 사용자 확인 항목으로 남는다. 이번 디자인 검수를 기존 실사용 목표의 완료로 소급하지 않는다.
