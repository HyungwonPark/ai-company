## 적용과 필수 검사

사전 대조 후 고정 소스에서 설치한 제품 파일 113개의 일치를 확인했다. PM·조정기를 정상 종료하고 SQLite 온라인 백업과 상태 파일·설정 백업을 비공개로 보관했다. 승인된 웹 이미지와 PM·조정기 실행 경로만 변경했다.

첫 시도에서는 미등록 Host에 대한 프록시의 빈 `200` 응답을 검사기가 실패로 판정하여 승인된 복구를 1회 실행했다. 기존 운영도 동일한 응답을 주며 실제 관리 서버는 잘못된 Host를 `403`으로 거부함을 확인했다. 프록시의 무내용 응답과 관리 서버의 Host 검사를 구분해 같은 후보를 재적용했고 최종 검사는 통과했다. 제품 변경이나 보호 검사 해제는 없었다.

공개 HTTPS·HTTP 리디렉션·익명 API 거부·Origin 거부·관리 서버 Host 거부·정적 파일 일치를 확인했다. 비밀번호 로그인, Secure/HttpOnly/SameSite 쿠키, 인증 읽기와 CSRF 거부는 실제 배포 이미지의 네트워크 격리 임시 상태에서 검증했다. 실제 마스터의 로그인 성공을 대신 주장하지 않는다.

새 worker의 실제 실행 경로·heartbeat·기존 설정 digest와 OS 잠금·단일 프로세스를 확인했다. 번역 worker와 커플 컨테이너는 교체하지 않았고, 기존 타이머 가동 및 기록 보존을 대조했다. 상세 백업·명령·검사·복구 기록은 서버 비공개 인수인계 묶음에 남겼다.

## 사용자 확인

기존 [서명 APK 0.1.1](https://github.com/HyungwonPark/ai-company/releases/download/android-v0.1.1/ai-company-0.1.1.apk)을 그대로 사용한다. 접속 주소는 **https://hyungwon.cloud/** 이다.

1. APK를 닫고 AI Company 아이콘으로 실행한다. 로그인 화면이면 기존 `edward` 계정으로 로그인한다.
2. 실제 목록의 프로젝트를 선택하고 하단 **진행**을 누른다.
3. 실행을 선택해 역할·전달선을 누르고 같은 실행의 보고·승인을 읽는다. 승인 결정은 누르지 않는다.
4. 뒤로가기, Light·Black 전환, 앱 종료 후 재실행을 확인한다.

실기기 조작·실제 로그인·서비스워커 갱신은 **미검증**이다. 서명키 외부 보관·복원도 별도 사용자 확인으로 유지한다. 사용자 조작을 대신하거나 새 개발 실행을 시작하지 않았다.
