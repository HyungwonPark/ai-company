# PR #21 모바일 진입·적용·복구안

2026-09-17. 공개 검토용 문서다. 사용자가 승인한 공개 범위인 구성 요약, 변경 버전, 검증 결과, 적용·복구 절차만 담는다. 운영 사본, 접속 설정, 원문 대화·승인, 상세 설치 파일은 서버 비공개 준비 묶음에 보존한다. **문서 게시는 운영 배포·병합 승인이 아니다.**

## 긴 이름 오류와 검증

고정 Archify 컴파일러는 첫 번째 열의 상자 폭으로 왼쪽 여백을 확보한다. 앞 열이 비어 있거나 뒤 열의 긴 역할 상자가 더 넓으면 왼쪽 경계를 벗어났다. 기존 후보에서 운영 사본 3건과 24·48자 단일 역할로 `layout/constraint`를 재현했다.

어댑터가 비어 있는 앞 열을 정리하고, 모든 후속 상자의 왼쪽 범위를 포함하도록 첫 열 여백을 확보한다. 역할 이름과 입력 JSON, ID 매핑, 계획 digest·실행 결속은 그대로다. upstream 컴파일러·무결성 검사·품질 기준을 수정하거나 끄지 않았다. 생성기 버전을 2로 올려 과거 파일과 분리한다. 모바일의 축소 그림은 개요이며, 아래 역할·관계 목록에서 원문 전체를 읽는다.

기존 역할명 최대 100자 계약은 유지한다. 고정 그림의 자기 이관은 선 대신 원본 관계 목록에 남는 기존 한계도 유지한다. 일부 보고 원문의 영문 상태값·증거 링크 이름은 남아 있으므로 전체 한국어화 완료로 보고하지 않는다.

## 승인 이후 적용 순서

1. **기준 대조:** 제품 커밋·이미지 ID·소스 묶음과 현재 웹·PM·조정기 버전, 설정·카탈로그·서비스 정의를 비공개 manifest와 비교한다. 인증 세션의 정상 갱신과 실행 계약의 변경을 구분한다. 코드·설정·실행 범위가 달라졌다면 영향부터 검토하며 자동으로 덮어쓰지 않는다.
2. **정상 종료:** 새 배정을 시작하지 않도록 PM·조정기를 정상 종료한다. 진행 중인 자식이 있으면 기존 종료 시간과 재개 계약을 따른다. 강제 종료로 제한 결과를 누락시키거나 중복 worker를 띄우지 않는다. 웹 교체 전에 기존 요청이 마칠 시간을 둔다. 번역 worker·기존 타이머·커플 서비스는 유지한다.
3. **백업:** 기존 이미지·서비스/웹 설정, 현재 DB의 SQLite 온라인 백업, 상태 파일과 그림 디렉터리를 비공개로 보관하고 해시를 기록한다. DB/WAL을 임의로 파일 복사해 일관성 없는 백업을 만들지 않는다. 실행 중인 번역 기록이 계속 생길 수 있으므로 백업은 감사·복구 판단 자료이며 과거 DB로 덮어쓰기 위한 것이 아니다.
4. **준비물 확인:** 새 worker 설치본의 파일·잠긴 의존성·Python 버전을 검증한다. 기존 번역 worker와 Claude 연결에 필요한 설치본은 보존한다. 단일 worker 잠금과 기존 환경·카탈로그를 유지한다.
5. **웹 교체:** 검토한 웹 설정에서 이미지 ID만 변경한다. 해당 웹 서비스만 교체하며 Compose 전체 종료나 Caddy 재설정을 하지 않는다. 기존 상태/카탈로그 연결과 네트워크·인증·격리 제한을 유지한다. Node는 새 이미지 안에서만 추가된다.
6. **웹 확인:** 60초 안에 healthy, HTTPS 루트·로그인 화면·정적 파일 일치, 익명 API 거부와 Host·Origin·CSRF 보호를 확인한다. 원문·계획·후보 승인과 실행별 보고 연결을 확인하며 계정 암호나 승인을 대신 변경하지 않는다. 새 파생 표만 추가됐는지 검사한다.
7. **worker 교체:** PM·조정기 서비스의 실행 경로만 새 설치본으로 바꾸고 서비스 정의를 다시 읽힌 뒤 시작한다. 20초 내 신선한 heartbeat, 단일 소유권, 기존 설정 digest·카탈로그 일치를 확인한다. ECC 전달은 비활성 상태로 유지한다. 이미 저장된 작업은 기존 계약 안에서만 재개한다.
8. **사용자 안내:** 운영 버전·커플 서비스·기록·타이머를 대조한 뒤 아래 APK 조작을 요청한다. 마스터 대신 프로젝트·계획 확정·후보 수용을 만들지 않는다. 추가 모델 연결·ECC 활성화·병합은 하지 않는다.

서비스워커는 기존 v6에서 후보 v8로 변경된다. 공개 shell만 캐시하고 API·쓰기 요청은 캐시하지 않는 정책을 유지한다. 네트워크 우선으로 새 파일을 받는 것이 기대 동작이다. 기본 진입 브라우저 검사는 service worker를 차단하므로 v6→v8 전환을 입증하지 않는다. 기존 열린 화면의 활성화 지연과 앱 재실행 시 실제 갱신은 운영 적용 후 휴대폰 확인 항목이다. 자동 `skipWaiting`, 로그인 정보 삭제나 앱 데이터 초기화로 갱신을 강제하지 않는다.

### 실패 판정과 되돌리기

이미지·정적 파일·카탈로그 불일치, 위 시간 안에 건강 상태/heartbeat 미확인, 재시작 반복·중복 worker, 인증 경계 회귀, 그림 실패·원문 누락, 다른 실행의 보고/승인 표시, 기존 원장의 예기치 않은 변경이면 적용 실패다.

1. 새 배정을 멈추고 자식 종료를 확인한다. 현재 로그·DB/WAL·파일을 보존한다.
2. 이번에 적용한 파일과 해시가 여전히 일치하는 경우에만 웹 이미지를 위 복구 ID로, PM·조정기 서비스 정의를 기존 설치본으로 돌린다. 다른 변경이 끼어 있으면 덮어쓰지 않는다. 번역·Caddy·타이머는 복구 대상이 아니다.
3. **DB와 사용량·승인·번역 기록을 과거 백업으로 되돌리지 않는다.** 새 파생 표와 생성 파일·실패 영수증도 지우지 않는다.
4. 새 요청·명세·계획·실행이 생겼다면 기존 버전의 읽기 호환성과 실행 호환성을 따로 판정한다. 새 계약이 있거나 판단이 불명확하면 구 worker를 자동 재시작하지 않는다. 호환되는 관리·보고 화면과 기록을 유지하고 자동 배정만 중단한다.
5. 구 웹의 로그인·읽기 상태와 버전을 확인한 후, 기존 계약으로 안전하게 재개할 수 있다고 확인된 경우에만 구 PM·조정기를 시작한다. 서비스워커/API 응답을 확인하고 실패 사실을 기록한다.

## 적용 승인 대상

검증을 마친 위 **웹 이미지 1개 + PM·조정기 worker 1개 + 파생 테이블 2개 초기화**가 실제 변경 범위다. 이번 공개 문서 작성·빌드·사본 검증 과정에서는 운영을 변경하지 않았다. 사용자에게 정확한 후보와 검증 결과를 한 번에 제시한 뒤 운영 적용 승인을 받는다.
