## 확인한 원인과 수정

[이전 시험](claude-dispatcher-2026-09-16.md)의 작업은 `unit` 검사를 요구했지만 검수 입력의 `verification_digest`는 null이고 검사 기록도 없었다. 모델은 이를 누락된 근거로 지적했다. 또한 항상 존재하는 `dirty_digest`를 수정 여부처럼 해석했다. 출력에는 4,096토큰 도달에 따른 native 이어쓰기 메시지가 두 번 기록됐고 최종 보고 전에 비용 중단이 발생했다. 이를 올바른 검수 PASS로 고치거나 이전 실행을 재승인하지 않았다.

- 새 `cli_configuration_v2` 인계에는 실행기가 읽은 Git 상태를 `repository_state`로 추가한다. HEAD와 원래 snapshot digest에 묶으며, `dirty_digest`의 값이나 존재 여부로 clean을 추측하지 않는다. 기존 snapshot 형식·명세·정책 digest와 과거 인계 원문은 바꾸지 않는다.
- 파일 도구를 쓰는 검수 지시에서 실행기 관측과 검수자가 직접 읽은 소스를 구분한다. 저장소가 깨끗하다는 사실만으로 코드나 검사를 통과시키지 않는다.
- 비용·작업 횟수·보고 형식 제한으로 실패한 새 실행은 해당 native 종료 원인에 맞는 짧은 한글 사유를 기록한다. 다른 세션이나 모델 텍스트를 원인 근거로 채택하지 않는다. 기존 실패 분류·비용·예약 없음은 유지한다.
- 종합 보고는 영속 예약 대기와 운영자가 확인해야 하는 중단을 구분한다. BLOCKED·종료 확인 필요·컨텍스트 이관 필요를 단순한 예약 대기로 안내하지 않으며, 다른 역할의 완료·진행은 그대로 표시한다. 읽기용 집계만 바뀌고 원본 실행·계획·승인은 변경하지 않는다.
