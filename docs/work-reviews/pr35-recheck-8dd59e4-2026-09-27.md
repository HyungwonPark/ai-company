- 정산 직전에는 같은 장부 트랜잭션 안에서 고정한 계정 제한·사용량을 다시 대조합니다. 그 직전에 추가된 인증 차단을 정산이 덮어쓰지 않는 회귀를 확인했습니다.
- 중단 후 재진입과 계정 해제 직전에도 제한을 대조하고 조건부 갱신합니다. 이전 R35-1의 미래 시각 삭제 경계는 막혔습니다.
- 신규 통합 검사는 실제 Automation·Dispatcher·SessionQueue·공용 장부를 사용합니다. 첫 질문→답변→후속 호출 중단→복구→새 worker의 같은 job/session 시도 2→계획 저장→별도 계획 검수→`proposed`를 확인합니다.
- 정산·DB 준비·guard 해제·계정 해제 후 중단, 두 Dispatcher의 동시 취득도 검사합니다. E2가 `reviewing`이면 평가 진행 함수가 거부하고 `proposed`일 때 허용합니다.

이 통합 검사는 외부 executor의 응답과 종료 관측을 합성합니다. 실제 제품의 생성·회수·정산·계획 채택 메서드를 대체한 검사는 아닙니다. 실제 모델의 판단 품질·운영 적용·마스터 직접 확정을 검증한 것은 아닙니다.

## R35-1b — 정산 후 추가된 대기가 만료돼도 재개할 수 없음 · P2

### 재현

제출한 원래 fixture·복구 코드·SQLite 장부를 사용했습니다. 사용자 systemd가 없는 Work 환경 때문에 서비스 생존 관측 두 참조를 대체했고, 기다리는 대신 현재 시각만 모의했습니다.

1. 정상 증거로 복구 계획을 고정하고 정산 직후 중단합니다. 원래 시도는 `SETTLED`, 복구 단계는 `settled`입니다.
2. 같은 계정의 `resume_at`에 현재보다 1시간 뒤를 넣습니다.
3. 만료 전 기존 계획을 적용하면 `account restriction changed since the frozen decision`으로 차단됩니다. 이 차단은 올바릅니다.
4. 계정·예약·정산 자료를 바꾸지 않고 시간만 만료 이후로 옮겨도 같은 오류로 거부됩니다.
5. 새 진단도 `hold_unknown`입니다. 새 digest로는 저장된 기존 복구 계획을 교체해 진행할 경로가 없습니다.

| 결과 | 관측 |
| --- | --- |
| 만료 전·후 기존 계획 적용 | 모두 같은 계정 상태 변경 오류 |
| 만료 후 새 진단 | `hold_unknown` |
| 복구 단계 | `settled` 유지 |
| 원정산 | 1건, 행 전체 불변 |
| 계정 누적 호출 | 8건 유지, 중복 정산 없음 |

[재현 스크립트](repros/pr35-expired-wait-after-settlement-8dd59e4.py)를 대상 HEAD에서 `PYTHONPATH=src:. python <스크립트 경로>`로 실행할 수 있습니다.

**이것은 상태를 주입한 합성 경계 검사입니다. 실제 운영 E2에서 이 상태가 생겼거나 정상 API 호출 순서가 이를 만들었다는 주장은 아닙니다.** 앞선 지시에서 요구한 변경된 대기 조건 보존과 허용 시각 이후 동일 작업 재개를 함께 만족하지 못하는 가용성 결함입니다.

### 원인과 수정 범위

`timeout_recovery.py`의 재진입은 최초 계획의 `account_rows`와 현재 값을 완전히 비교합니다. 추가된 시각이 만료돼도 값 자체는 달라 계속 거부합니다. 새 `diagnose`는 최초 UNKNOWN 예약을 전제로 하므로 이미 정산된 복구를 위한 새 판정을 만들지 못합니다. 저장된 계획을 읽는 적용 경로에도 갱신된 제한 조건을 다시 검토해 고정하는 절차가 없습니다.

기존 계획의 불일치 거부를 단순 삭제하지 마세요. **원정산에 결합된 최초 증거를 보존하면서, 중단된 복구의 현재 제한을 다시 검토할 수 있는 경로**를 추가합니다. 최초 증거·정산과 새 재개 판정을 구분해 연결하고, 기존 계획·digest·정산 행을 덮어쓰지 않습니다.

수용 기준은 다음과 같습니다.

- 정산 후 새 미래 대기, 계정 해제 직전 새 미래 대기를 각각 보존하고 만료 전 호출을 막습니다.
- 만료 후 동일 예약·job·session·원문·저장소·종료·장부·예산을 재대조해 해당 복구만 진행할 수 있어야 합니다. 운영 적용이 필요한 판단을 자동 승인으로 만들지 않습니다.
- 재검토 중 다시 미래 시각이 추가되거나 인증 차단·참조 불일치·다른 불확실한 실행이 있으면 계속 막습니다. 시각 경과만으로 다른 차단을 해제하지 않습니다.
- 원정산은 한 번, 사용량도 한 번이며 대기시간을 실행 예산에 더하지 않습니다. 기존 복구·새 재개 판정의 계보와 단계별 중단 복구가 남아야 합니다.
- 제품 통합 검사에서 이 **정산 이후** 입력을 다루고, 만료 후 같은 job/session 시도 2와 계획 1건을 확인합니다. 최초 진단 전에 시각을 넣는 기존 검사는 유지합니다.
