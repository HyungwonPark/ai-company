## R29-1 · P2 · 검수 대상 읽기 근거가 없어도 PASS

[runner의 summarize와 프롬프트](https://github.com/HyungwonPark/ai-company/blob/6ab5db8fd919360d9a6ba8c62787c3be05e644f6/scripts/review_pr_with_claude.py)를 확인했다. 프롬프트는 패치 본문 대신 pr.diff의 경로를 전달한다. 하지만 summarize는 모델·설정·종료 조건과 첫 줄 판정만 만족하면, 읽기 도구 호출과 하위 검수 근거가 전혀 없어도 review_passed=true로 판정한다.

[재현](repros/pr29-empty-review-pass-6ab5db8.py)을 실행한 결과:

```text
review_passed: true
completion_verified: true
tools_used: []
verdict: PASS
```

이는 제출된 실제 Claude가 아무것도 읽지 않았다는 주장이 아니다. 실제 보고에는 전체 패치·변경 파일을 읽었다고 되어 있다. 문제는 다음 호출에서 같은 누락을 검수기가 막지 못한다는 것이다. 기존 단위검사도 이 빈 도구 응답을 성공으로 취급한다.

수용 조건:

1. 프로세스 정상 종료, 대상 입력 전달/열람 확인, 모델 내용 판정을 분리한다.
2. 정확한 HEAD·패치 해시와 결합된 입력 전달 또는 직접/하위 검수의 읽기 근거가 없으면 검수 PASS로 내보내지 않는다.
3. 단순히 Read가 한 번 호출됐다는 이유로 합격시키지 않는다. 실패·권한 거부·무관한 파일·일부 잘린 자료를 완전 검수 근거로 세지 않는다. 정상 Workflow/Task 하위 검수도 근거가 연결되면 인정할 수 있다.
4. 검토 범위·제외 파일·이유를 명시한다. 필수 자료가 미검토면 INCOMPLETE로 남긴다. binary 등 직접 의미 검수가 불가능한 항목은 사전에 정한 대체 근거/제외 정책을 적용하며 모든 저장소 파일을 무조건 읽는 요구로 확장하지 않는다.
5. 빈 도구/미전달 PASS, 무관·실패 읽기, 잘못된 HEAD 근거는 차단하고, 유효한 직접/하위 검수 근거를 가진 정상 사례는 허용하는 회귀를 제출한다. 입력을 전달했다는 사실이 모델의 이해 품질까지 보장하지는 않는다.

## R29-2 · P2 · 동시 retry-unstarted가 같은 HEAD 호출 슬롯을 중복 예약

reserve_attempt는 기존 facts 읽기 → 디렉터리 이름 변경 → 새 디렉터리 생성 사이를 잠그지 않는다. 두 재시도가 같은 closed 기록을 먼저 읽으면, 첫 재시도가 새 디렉터리를 만들고 prompt_delivery_started를 기록한 뒤에도 두 번째 재시도가 그 활성 디렉터리를 unstarted 보관본으로 이동시킬 수 있다.

[모델·네트워크 없는 동시성 재현](repros/pr29-retry-race-6ab5db8.py)을 독립 검수와 주 검수에서 실행했다. 두 예약이 모두 성공했고, 이미 전달 시작이 기록된 첫 시도가 unstarted 이름으로 이동했다. 일반 최초 실행의 mkdir 배타성이 이 재시도 경계를 보호하지는 못한다.

수용 조건:

1. PR/HEAD 시도 상태를 읽고 이전 미시작 시도를 보관한 뒤 새 시도를 예약하는 전체를 원자적으로 보호한다. 보관되는 디렉터리 안의 잠금만 이동시켜 보호가 끊기지 않게 한다.
2. 잠금 획득 뒤 현재 기록을 다시 검증하고 이미 시작한 시도·활성 시도를 이동하거나 슬롯을 다시 주지 않는다.
3. 두 동시 재시도 중 하나만 새 호출 권리를 얻는다. 다른 쪽은 활성/중복 상태로 종료하며 첫 기록을 보존한다.
4. 중단 후에도 불확실한 기존 호출을 미시작으로 되돌리지 않는다. 기존 무전달 종료의 단일 재시도는 가능해야 한다.
5. 동시 재시도, 재시도와 최초 실행 경합, 전달 시작 후 거부, 정상 미시작 재시도의 회귀를 모델 호출 없이 검증한다.

## 확인 범위 설명 보완

현재 binding_unchanged는 종료 후 로컬 HEAD·작업 트리·원격 HEAD를 재확인한다. CI 상태는 시작 전에 확인하며 종료 후 재조회하지 않는다. 이 차이를 보고 문구에 반영한다. 최종 제출 때에는 정확한 HEAD의 필수 CI를 다시 조회해 붙이고, 검수기 PASS만으로 CI 유지나 병합 준비를 추정하지 않는다. 이번 두 재현과 별개의 새 기능 요구로 넓히지 않는다.

무시 파일·비밀이 섞인 작업 공간 전체를 검수한 것으로 주장하지 않는다. 신뢰한 검수기는 저장소 밖 두 파일의 해시를 확인한 설치본을 사용한다. 후보 PR의 코드가 설치본을 자동 대체하지 않도록 기존 경계를 유지한다. 비공개 원시 이벤트·설정·인증 정보를 GitHub에 올리지 않는다.
