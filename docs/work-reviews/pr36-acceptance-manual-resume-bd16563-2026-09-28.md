## 서버에 넘길 한 묶음 작업

1. 기존 적용안을 **수동 재개용**으로 갱신한다. 검수 전용 timer의 설치·enable·start와 5분 반복 실행은 적용 범위에서 제외한다. 기존 quota timer 일정은 보존한다.
2. 새로 불필요한 제품 기능을 만들지 않는다. 검증된 고정 대상 확인·체크포인트·장부·중복 방지를 그대로 사용하는 **수동 1회 명령**을 준비한다. tick 보조 코드를 한 번 실행하는 방법을 사용한다면 READY에서 실제 호출하는 명령임을 표시하고, 읽기 전용 점검 명령과 구분한다.
3. 설치가 필요한 신뢰 코드만 목록·해시로 고정하고, 현 예약 정산/해당 계정 상태 조정과 함께 **타이머를 뺀 구체적 적용·복구안**을 준비한다. 이미 유효하게 승인된 범위는 재사용하고, 기존 한 파일 복원 승인을 새로운 모든 설치·정산의 포괄 승인으로 확대하지 않는다. 필요한 추가 승인 범위는 준비 후 한 번만 확인한다.
4. 수동 명령에는 PR/HEAD/base/전체 패치/원래 시도/이전 예약 연결을 유지한다. 승인·설치 검증·이전 종료/정산·회복 시각·현재 제한 확인이 끝나고 사용자가 재개를 요청하면 **새 검수 시도 한 건**을 실행한다. 같은 Claude 세션을 그대로 되살리는 것으로 설명하지 않는다.
5. 다시 한도에 걸리면 원문·사용량·검토 진행·남은 범위를 보존하고 종료한다. 다음 관측 회복 시각과 재개 조건을 보고하고 새 사용자 요청을 기다린다. 이 지시로 반복 호출이나 장시간 sleep을 예약하지 않는다.
6. 완료 시 실제 Claude Opus 5.5·Ultracode 적용 근거, 전체 검토 범위, 최종 PASS/REVISE, 종료·한 번의 정산을 제출한다. Workflow 사용과 전체 Workflow 결과 수집을 구분한다. PR #35와 후속 PR #36의 검수 대상·판정을 섞지 않는다.

**이 문서는 수동 운영 방식 선택과 비운영 수정 수용이다.** 신뢰 경로 교체·미정산 장부 쓰기·계정 해제·현재 즉시 호출을 실행하거나 승인한 문서가 아니다. 기존 운영 승인이 새 패키지/정산 범위를 이미 포함하는지는 서버의 실제 승인 기록과 대조한다. 이번 준비에는 마스터의 APK 조작을 요구하지 않는다.
