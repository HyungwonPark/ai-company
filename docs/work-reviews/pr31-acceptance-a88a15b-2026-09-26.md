## 서버 Codex의 다음 작업

다음 단계는 **운영 연결에 실제 사용할 파일 기반 릴리스와 적용·복구 자료의 고정**이다. 기존 기능을 다시 설계하거나 같은 지적을 반복 수정하지 않는다. 아래 비운영 준비·읽기 전용 대조를 먼저 끝내고, 실제 전환만 구체적 범위로 승인 요청한다.

1. `a88a15bb05438330bcb5c321af905005eb1e695e`의 깨끗한 소스에서 별도 릴리스 후보를 준비한다. 고정 의존성으로 실행 환경을 만들고 실제 배치될 파일 목록·SHA-256, 코드 커밋, 실행 경로를 기록한다. 운영 릴리스 포인터·유닛·신뢰 검수기 설치본은 아직 바꾸지 않는다. 기존 운영 형태는 파일 기반이며 새 웹 이미지 체계는 필요하지 않다.
2. 두 worker의 현재 유닛·설정·카탈로그 경로와 후보를 읽기 전용으로 대조한다. 비공개 설정의 계정 참조·공용 장부 경로·기존 execution catalog가 일치하는지 확인한다. 비밀값은 출력하거나 GitHub에 올리지 않는다.
3. 일관된 비공개 사본에서 기존 사용량·실행시간·비용 미확인 표시·한도 회복 상태·활성 또는 미정산 호출을 대조한다. 과거 PR 검수 시도도 원본 기록을 유지하며 포함한다. 새 장부 초기화 입력과 되돌리기 기준을 준비하고 격리 사본에서 전환을 예행한다. 운영 장부 생성·호출 차단 설정 적용·서비스 정지는 승인 전 수행하지 않는다.
4. 변경 전후 파일, 두 유닛, 기존 카탈로그 유지, 백업 대상, 실제 적용 명령, 확인 항목, 중단·복구 조건을 하나의 비공개 적용 기록에 고정한다. 공개 문서에는 비밀정보와 비공개 운영 세부를 제외한 범위·후보 식별자·검증 결과만 올린다. 읽기 시점 이후 달라질 수 있는 사용량·활성 호출은 실제 전환 직전에 다시 대조하도록 명시한다.
5. 준비 완료 보고와 함께 **고정한 worker 릴리스·서비스 유닛 2개·비공개 설정·신규 공용 장부·신뢰 경로 검수기의 운영 연결**에 대해서만 승인 요청한다. 코드 검수 수용을 배포 승인으로 사용하지 않는다.

이미 준비한 자료가 있으면 정확한 후보·실제 설치 파일과 대조해 재사용한다. 변경 없는 UI나 전체 설계를 다시 만들지 않는다. 승인받을 최종 결과를 구체적으로 제시하는 데 필요한 준비를 끝낸 뒤 질문한다.

## 승인 후 이어갈 검증

이 절은 후속 순서이며 지금 운영 변경을 승인하는 문구가 아니다.

- 승인된 전환 동안 진행 중 호출 종료·정산과 계정 상태를 확인한다. 불확실하면 전환을 중단한다.
- 같은 코드와 공용 장부를 사용하는 PM·조정기와 번역 worker, 신뢰 검수기의 연결을 확인한다. 구형 호출 경로가 공유 예약을 우회하지 않도록 금지 또는 전환한 사실을 기록한다.
- 이 운영 전환 근거와 한도 회복이 확인된 다음, 격리 상태 디렉터리에서 고정 E1–E6 실제 Astra PM 행동 평가를 수행한다. 전체 호출 24회·실제 실행시간 1800초·자동 수정 2회·호스트 병렬 2개의 기존 조건을 유지한다. 대기시간은 실행시간에 합산하지 않는다.
- 원시 응답과 별도 내용 검수를 함께 제출한다. 명세 질문·문제 지적·마스터 결정 존중·스킬 추천의 판단 품질을 코드 검사와 구별한다. 평가 실행기가 마스터 계획 확정을 대신하지 않는다.
- Claude PR 검수는 정확한 HEAD/패치·기존 시도 종료·한도 회복·공용 정산 조건을 갖춘 신뢰 설치본에서만 재개한다. 기존 USD·턴 상한 제거와 30분 종료·동일 HEAD 중복 방지를 유지한다. PM의 동일 session 재개와 `--no-session-persistence` 검수기의 새 시도를 혼동하지 않는다. 실제 Workflow 호출과 전체 결과 반영 여부도 구별한다.
