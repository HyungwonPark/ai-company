## 권고하는 다음 한정 작업

[후보의 적용·복구안](https://github.com/HyungwonPark/ai-company/blob/e659fc66cadfb5af77f85327314671b46a0383e0/docs/work-reviews/pr35-timeout-review-diagnostics-candidate-2026-09-28.md)을 기준으로 다음을 준비했다. 신뢰 경로의 새 패키지 설치는 저장소 운영 지침과 기존 적용안에서 별도 승인 대상으로 둔 범위다. 이 문서 게시를 사용자 승인으로 해석하지 않는다. 같은 대상·해시·범위에 대한 승인이 이미 있으면 재승인받지 않는다.

1. 적용 직전 고정 후보·패키지·현재 설치 4파일·전환 기록·원본 해시·현재 예약/계정·실행 중복을 비공개 명세와 대조한다. 설치 파일을 사용하는 검수 프로세스가 실행 중이거나 안전한 교체 여부가 불확실하면 교체 전에 근거를 확인한다. 새 후보나 원본 불일치가 있으면 해당 차이를 보고한다.
2. 승인된 동일 묶음에서 runner·claude_control·tick 및 전환 기록을 비공개 백업하고, 세 파일을 일관된 버전으로 교체한 뒤 대응 전환 해시와 네 파일 전체를 검증한다. shared_calls는 동일 해시를 확인해 보존한다. DB·웹·worker·타이머 설정은 변경하지 않는다.
3. 모델을 호출하지 않는 설치·해시·기록 검사만 수행한다. tick 명령·추가 검수·시험 호출·새 예약은 포함하지 않는다. 현재 UNKNOWN에서 READY가 되어야 한다는 조건을 만들거나 상태를 강제로 바꾸지 않는다.
4. 설치 검증 실패가 새 예약 전에 발생하면 백업한 신뢰 코드·전환 기록을 복구한다. 현재 장부·정산 사실·원문을 보존하고 과거 DB를 덮어쓰지 않는다. 승인된 묶음은 설치·검증·필요한 복구·보고까지 단계별 재확인 없이 처리한다.
5. 이미 확인한 timeout 원문 전체 재분석을 반복하지 말고, 아직 없는 종료·하위 작업·총사용량 증거를 확보할 수 있는 기존 기록과 출처를 확인한다. 수집 가능한 추가 근거가 없으면 그 한계와 부족한 항목을 명시한다. 다른 실제 모델 호출을 증거 수집 수단으로 쓰지 않는다.
6. 제출은 변경 파일·전후 해시·백업 위치·검증 결과·추가 모델/tick/새 예약 0건, 현 예약의 확보/미확보 증거, 정산과 이후 재개에 필요한 남은 조건으로 정리한다. 비공개 식별자·원문은 공개 PR에 올리지 않는다.

## 현재 timeout 정산과 재호출의 별도 경계

기존 수동 검수 요청에 포함된 종료·증거 기반 정산·보고 승인은 유지한다. 기존 지원 경로와 그 범위 안에서 정산 조건이 입증되면 같은 처리를 다시 승인받을 필요는 없다. 다만 이번 한정 설치가 계정 해제·새로운 timeout 복구 절차·실제 검수 재호출을 추가 승인하지는 않는다.

종료와 모든 하위 실행의 종료가 확인되지 않으면 정산·계정 해제를 진행하지 않는다. 종료가 입증됐지만 총비용을 확정할 수 없다면 관측 부분 비용과 비용 미확정을 구분하며, 지원되는 신뢰 경로에서 비용 null/미확정 표시·계정 UNKNOWN을 보존하는 정산 가능 여부를 판단한다. 단순히 프로세스가 나중에 보이지 않거나 주 호출 비용만 있다는 사실로 종료·전체 정산을 확정하지 않는다.

이 후보는 현재 timeout 예약에 대한 일반 재개 예외를 새로 추가하지 않았다. 기존 `--resume-quota`는 공급자 한도 거절 증거에 한정되며 timeout을 quota로 바꾸어 사용하지 않는다. 계정 상태만 바꾸면 같은 HEAD 재호출이 허용된다고 가정하지 않는다. 지원 경로가 없다면 원본·계보·중복 방지를 유지하는 구체적인 사후 처리/재개안을 검토 가능한 상태로 준비한다. 새 절차가 필요한 부분만 추가 확인 대상으로 제시한다.

실제 Claude 검수는 [공통 완료 조건](pr-completion-review-policy.md)과 별도 수동 요청을 계속 따른다. PR #35의 실제 검수와 PR #37 코드의 독립 검수를 구분한다. 문서 게시·모의 검사·설치 검증은 둘 중 어느 검수의 PASS도 아니다.
