## 원문과 검수 시점

최초 게시한 명세 2개와 b31fb87 검수 파일은 Work에서 작성한 원문을 그대로 게시한 것입니다. fd18508 후속 검수와 4ffd4e7 재검수는 각각 새 파일로 추가했습니다. 원문의 날짜·검수 범위·미실시 항목을 보존했습니다. 원문 안의 “GitHub 게시를 실행하지 않는다”는 작성 당시의 범위 기록입니다. 이번 사용자의 별도 지시로 이 디렉터리의 문서 게시를 진행했습니다. 이 게시가 제품 구현·운영 적용·병합 승인을 뜻하지는 않습니다.

[PR #22](https://github.com/HyungwonPark/ai-company/pull/22)에 이미 올라간 [재설계 보충 명세](https://github.com/HyungwonPark/ai-company/blob/b31fb876a79b2548de908e295fc376bb5e451554/docs/product-experience/workspace-remodeling-spec-2026-09-23.md)는 대화로 전달받은 내용을 서버에서 정리한 별도 문서입니다. 당시 서버가 Work 원문을 읽었다는 의미로 바꾸지 않습니다. 이제 위 링크의 원문을 직접 읽고 차이와 적용 여부를 대조할 수 있습니다.

최초 PR #22 검수 대상은 `b31fb876a79b2548de908e295fc376bb5e451554`입니다. 최초 게시 준비 중 확인한 PR head는 `3c3c1988a5b04dcfcd7d5aacbd39fbb836bb4d95`이며, 두 커밋 사이 변경은 공개 미리보기 ZIP·해시 기록·안내 README입니다. 시안 JS·HTML·CSS의 추가 변경은 없습니다. 이후 커밋은 다시 대조하고, 과거 지적을 현재 결함으로 자동 간주하지 마세요.

검수 문서에 적힌 소스 검토·JS 상태 재현·CI 조회와 실제 브라우저·초보 사용자·APK 검증을 구별합니다. 이번 문서 게시로 새로운 화면 검증을 수행한 것은 아닙니다.

최신 검수 대상은 `4ffd4e702ea2f125569c3f410328a57d3976fc84`입니다. F1·F2 해결을 확인했고 이후 마스터가 순서형을 선택했습니다. 후속 PR #24의 연결 계획도 검수했으며, 현재 실행 범위는 야간 명세의 A~E 비운영 구현·통합 검수·후보 준비입니다. 코드·독립 상태 재현·원격 CI·직접 읽은 대표 캡처와 아직 수행하지 않은 조작 범위는 각 검수 문서에 구분했습니다. 이후 커밋은 새로 대조합니다.

## 서버 Codex에 전달할 지시

> 야간 구현·통합 검수 지시와 PR #24의 7522748 계획을 읽고 A·B→C→D→E까지 비운영 후보를 구현·검수·수정·패키징해 주세요. 단계마다 사용자 확인을 기다리지 않고, 막힌 가지는 기록한 뒤 가능한 독립 작업을 계속합니다. 같은 최종 제품 커밋의 CI·독립 검수·미리보기·해시·적용/복구안과 전체 목표 대응표를 제출합니다. 기존 한도·권한을 지키고 운영 교체·병합·PR #10 pending 변경·서명키 작업은 하지 않습니다.

저장소의 기존 지침과 최신 사용자 승인 범위를 함께 적용합니다. 문서끼리 충돌하면 출처와 변경 시점을 밝히고, 오래된 설명을 근거로 권한을 넓히지 않습니다.
