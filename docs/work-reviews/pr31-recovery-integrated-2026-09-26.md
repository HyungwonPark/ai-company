## 적용·복구 경계

2026-09-26 KST 조회에서 사용자 유닛의 PM·조정기와 quota 타이머는 `active`, 번역 worker는 `inactive`였다. 이 조회는 모델 호출 준비나 번역 복구를 뜻하지 않는다. 운영 웹·커플 서비스는 이번 코드 후보의 교체 대상이 아니다. 격리 예행에서는 후보 CLI와 설정 검사가 통과했지만 Claude 계정 그룹 `UNKNOWN` 때문에 번역 호출은 `waiting`이었다. 구형 번역 릴리스의 무호출 기동 검사는 현재 후보와 달리 지원되지 않고 공용 CLI 버전도 불일치한다. 완전한 구형 번역 복구는 검증되지 않았다.

실제 전환 전에는 설치된 릴리스, worker 유닛 2개, 비공개 설정의 해시, 전용 CLI 경로·해시, 카탈로그, 기존 사용량·대기 작업, quota 가드와 타이머 일정을 다시 대조한다. 새 제품 후보의 릴리스·전용 CLI 설정은 과거 `a88a15b` 고정 승인과 다른 범위다. 후보와 검사를 고정한 후 한 번의 통합 운영 승인으로만 적용한다. 웹·커플 서비스·전역 CLI·PR #10의 `pending`·기존 기록은 유지하고 병합하지 않는다.

승인을 받으면 다음 **하나의 운영 전환**으로 수행한다.

1. 현재 릴리스·두 worker 유닛·quota 유닛/타이머·비공개 설정·카탈로그·기존 대기 작업·공유 사용량을 새로 대조하고, 동일 권한에서 DB 일관 사본과 파일 해시를 남긴다. 최종 릴리스의 소스·실제 import 코드와 전용 CLI를 다시 검사한다. 예상한 `UNKNOWN` 대기와 아직 설치 전인 가드 외에 새 차이나 차단이 있으면 시작하지 않는다.
2. 기존 호출의 종료를 확인한 뒤 quota 타이머를 짧게 멈추고, 구형 호출을 막는 가드와 quota 서비스 유닛을 고정 해시로 설치한다. 타이머 **일정 파일은 그대로** 둔다. 비공개 공유 장부와 계정 귀속 정보를 승인된 사본으로 점검해 연결하되, 미확인 Claude 그룹은 `UNKNOWN`으로 유지한다.
3. `0e34d24` 릴리스·PM/조정기와 번역 worker 유닛·서비스 전용 CLI 경로/SHA 환경·신뢰 PR 검수기 파일을 고정 후보로 교체한다. 전역 CLI와 웹은 바꾸지 않는다. 유닛을 다시 로드하고 각각 단일 실행으로 시작한 뒤 타이머를 재개한다.
4. 로딩된 quota `ExecStart`와 설치 해시, 타이머 일정, 두 worker heartbeat, 번역 `call_readiness`, 공유 예약·기존 사용량·기록, 관리 인증과 웹·커플 서비스 상태를 검사한다. 계정 `UNKNOWN`에 따른 **번역 호출 대기**는 정상적인 안전 차단이며, 서비스 `active`만으로 번역 모델 처리 성공이라 판단하지 않는다. 검증된 계정 상태와 용량이 확인되기 전에는 Claude 호출을 시작하지 않는다.

**실패 판정·복구:** 코드/설정/CLI/로드된 유닛 해시 불일치, DB·장부 무결성 실패, 중복 worker, 예상 밖의 모델 호출 또는 기록 변경이 있으면 신규 실행을 중지한다. 새 장부의 예약·결과가 **0건**이면 백업한 구형 PM 설정으로 돌아가되 번역은 중지 상태로 유지하고 quota 가드는 남긴다. 이 안전 중지 경로는 현재의 PM 가동·번역 중지·타이머 유지 상태와 대조해 준비했지만, 구형 번역 전체 복구가 아니다. 새 예약·결과가 생겼으면 구형 호출 경로를 다시 켜지 않고 현재 DB·장부·원시 증거를 보존해 조정한다. 어떤 경우에도 운영 DB를 과거 사본으로 덮어쓰지 않는다.

적용 중 새 공용 장부 예약·결과가 없다면 검증된 복구 후보로 정상 종료·복원한다. 구형 번역 릴리스는 현재 공용 CLI와 호환되지 않으므로 파일 원복만으로 서비스 복구를 선언하지 않는다. 새 호출 사실이 생기면 새 호출을 멈추고 현 DB·장부·원시 증거를 보존해 조정하며 과거 백업으로 덮어쓰지 않는다. quota 타이머의 일정은 유지하고 구형 호출 경로는 가드로 차단한다.
