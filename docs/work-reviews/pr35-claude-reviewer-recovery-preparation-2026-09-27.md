## B · 격리 후보와 검사

기존 승인 릴리스의 `shared_calls.py`를 저장소 밖 비공개 후보에 복원하고, 설치된 나머지 두 파일을 그대로 복사했다. 후보 해시는 `runner.py` `2ac4bd2d2fc9a11e1f22fde8e409e9d857c2475161846fcd51e6bfebb16315d6`, `claude_control.py` `b7284bf8e4ac115d25ee972e166f5ffd4fc9b43df3660e17ec961cc6b7832b2d`, `shared_calls.py` `5c95d46e304e6553e1e74847fca3805b373ea168723b984dec504f7ce959739f`이다. 세 값은 기존 전환 기록과 일치하며, 후보에서 원래 기록을 이용한 전환 검사는 통과했다. 기록의 해시를 고치거나 신뢰 검사를 끄지 않았다.

실제 장부의 일관된 비공개 사본에서 스키마·무결성, Claude `UNKNOWN` 예약 거부를 확인했다. 별도 합성 장부에서 동일 ID 중복 예약, 같은 계정 동시 예약 거부, 호스트 2슬롯, 종료·정산 1회, 다른 계정의 `UNKNOWN` 보존을 확인했다. 제품의 공용 장부·PR 검수 관련 단위 검사 31개도 통과했다. 운영 장부, 설치본, worker, 계정 상태는 수정하지 않았다.

## C · 실제 검수 대기와 한정 적용 범위

실제 `claude-opus-5-5`·`ultracode` 검수는 **미실행**이다. 설치본 신뢰 검사 실패와 등록 Claude 계정의 `UNKNOWN`이 남아 있으므로 PR #35의 새 예약·프롬프트 전달·모델 호출은 0건이다. 요청 옵션 수용, 실제 적용 설정, Workflow 사용, 모델 판정도 미검증이다. 최종 제품 HEAD의 기존 Python·Journey·Console CI는 통과했지만, 이 문서가 추가된 최종 PR HEAD의 CI는 별도로 확인한다.

실제 호출 전에 필요한 **추가 운영 변경은 아래 두 가지로 한정**한다.

1. 신뢰 검수 경로의 `shared_calls.py` **한 파일만** 위 승인 릴리스 해시의 후보로 원자 교체한다. 현재 파일을 별도 비공개 위치에 보관하고, 나머지 두 파일과 기존 전환 기록은 유지한다. 교체 뒤 실제 설치 경로에서 기존 기록·장부의 전환 검사를 다시 통과해야 한다.
2. 사용자 계정 귀속 확인, 기존 대화형 세션의 호출 활동, 미종결 Claude 예약·과거 검수 종료, 현재 계정 상태를 다시 대조한 뒤 **등록 Claude 그룹만** `UNKNOWN`에서 검수 가능한 상태로 조정한다. 기존 사용량·정산·과거 검수·Codex 계정은 그대로 둔다. 공급자 잔여 한도는 인증 성공만으로 확정하지 않는다.

이 두 변경은 이번 비운영 준비에 포함하지 않았으며, 기존 승인 범위에 자동 포함된다고 해석하지 않는다. 적용 전 파일·전환 기록·장부·최종 PR HEAD/CI가 이 기록과 다르면 중단한다. 설치 검증이 실패하고 새 예약 전이면 보관한 파일만 되돌리고 계정은 차단 상태로 유지한다. 새 예약 후에는 과거 DB로 복원하거나 시도를 재사용하지 않고 현재 장부·종료·정산을 보존해 원인을 확인한다. 조건을 충족하고 한정 변경이 승인되면 기존 PR 검수 절차로 최종 HEAD 전체 패치를 한 번 검수한다.

## D · 보존과 제출 범위

비공개 후보·원본 장부 사본·계정 확인 기록·상세 복구 절차는 서버 비공개 경로에 있다. 이 공개 문서에는 인증 값, 계정 참조, 운영 DB 원문을 넣지 않았다. 과거 E2 `hold_unknown`, E1 PASS, 누적 사용량·정산, PM·번역 worker의 현재 중지 상태, quota 가드 타이머, 웹·커플 서비스, PR #10 `pending`을 유지한다. worker 재시작, 운영 E2/E3~E6 호출, 운영 배포, 병합은 수행하지 않았다.
