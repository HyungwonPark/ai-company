## 모의 흐름과 남은 실제 검증

격리 SQLite·Git clone·fixture executor에서 `질문 → 마스터 답변의 모의 입력 → 새 명세 → 별도 세션 계획 검수 → 테스트의 명시적 확정 → 두 역할 배정`을 실행했다. 확정 이전 run은 0건이었다. review 실패·사용량 대기·재시작·중복 답변·다른 계획의 review 재사용을 거부했다. 이 테스트의 “마스터 확정”은 테스트 클라이언트가 호출한 것이며 실제 마스터 UI 조작이 아니다.

실제 Astra PM·reviewer 모델 호출과 PM 판단 품질 비교는 현재 pilot 운영 허용 범위 밖의 소스 변경을 대상으로 하므로 하지 않았다. UI 실기기·APK·운영 적용 역시 미검증이다. 로컬 Chrome은 사용자 네임스페이스 제한으로 격리 실행이 실패했고, 샌드박스를 끄지 않았다. 원격 CI의 격리 Chrome 결과는 최종 커밋 기준으로 별도 대조한다.

## 후속 적용·복구안 — 미승인

적용 후보는 웹과 PM·조정기 worker의 **같은 제품 커밋**이며, 새 SQLite 테이블 `management_message_submissions` 하나와 새 plan/request JSON 필드를 사용한다. 번역 worker·기존 커플 서비스·기존 타이머와 큐·PR #10 pending은 변경 대상이 아니다.

1. 적용 직전 운영 제품·이미지 digest, 대기 PM 요청/검토/실행, DB 스키마와 사용량을 비공개 경로에 고정한다. SQLite 온라인 백업과 기존 웹·worker 이미지 참조를 준비한다.
2. 구 worker가 새 v2 요청을 v1로 처리하지 않도록 먼저 PM·조정기의 **새 작업 시작만 중지**하고, 기존 실행 사실·세션 결과를 대조한다. 웹과 worker를 동일 후보로 바꾼 뒤 worker 한 인스턴스만 재개한다. DB 초기화는 테이블 추가만 수행하며 기존 행을 수정하지 않는다.
3. 로그인·기존 기록·계획 digest·답변 저장·사용량/큐·한 worker·새 계약 준비 차단을 확인한다. 실제 모델 검증은 허용된 파일·예산·후보 정책에 맞는 별도 작은 프로젝트에서만 한다.
4. 새 v2 요청/계획이 **전혀 없을 때만** 이전 worker와 웹 이미지를 복귀시킬 수 있다. v2 기록이 생성된 후 필수 검사에 실패하면 자동 신규 배정을 멈추고, 관리·보고 읽기 화면과 DB/세션 기록을 보존한다. 구 worker를 새 요청에 다시 연결하거나 DB를 백업으로 덮어쓰지 않는다. 수정 후보와 호환성 검사를 새로 마련한다.

이 문서는 적용 허가가 아니다. 배포 후보 이미지 digest와 실제 운영 현재값 대조, 모델 예산/적격성·혼합 버전 복구 검토가 끝나야 별도 적용 결정을 요청할 수 있다.
