# PR #35 시간 초과 검수의 진단과 비운영 보완

기준 제품 `9cb3d24` · 대상 PR #35 `1d54d3a0ea5a21c7c2dc588f824c6567231829b4` · 2026-09-28

## 판정

이번 Claude 검수는 **주 호출 성공 후 Workflow가 끝나지 않아 30분에 중단**됐다. PASS/REVISE가 없고 새 예약·연결 계정은 UNKNOWN이다. 기존 원문·체크포인트·사용량·승인 상태를 바꾸지 않았으며 모델을 다시 호출하지 않았다. 아래 후보는 다음 시도의 증적 수집과 완료 판정을 보완한다. 현 예약의 정산·계정 해제·운영 설치는 이 후보에 포함되지 않는다.

## 저장 원문의 시간선과 사용량

| 단계 | 확인한 사실 |
| --- | --- |
| 시작 | 16:45:37 KST 시작, 16:45:38에 Opus 5.5·`xhigh`·Ultracode 적용 응답을 받은 후 프롬프트 전달 |
| 주 호출 | 최상위 응답에서 13개 파일의 성공 Read와 11개 파일의 HEAD·패치 바인딩 진행 선언을 관측. 단일 `result`는 `success`, 관측 비용 USD 4.4571232 |
| 후속 작업 | `result` 전에 Workflow 작업 1개 시작. 이후 진행 이벤트 245개, 마지막 `usage.total_tokens` 648,470. 완료 알림·작업 목록 비움·두 번째 결과·종료 후 설정 응답은 없음 |
| 종료 | 약 1,802초 후 제한 종료. relay의 `closed` 사실이 없고 하위 작업의 종료 증거가 부족해 새 예약·계정은 UNKNOWN·미정산 |

USD 4.4571232는 **부모 결과의 관측값**이다. Workflow의 토큰 카운터가 부모 사용량을 포함하는지, 추가 비용이 얼마인지는 저장 원문만으로 확정할 수 없다. 둘을 합산하거나 이 값을 총비용으로 정산하지 않는다. 검수기·CLI 프로세스가 나중에 보이지 않는 사실만으로 하위 실행의 정상 종료를 입증하지 않는다.

진행 선언 11개는 최상위 assistant 텍스트에 있고 해당 파일의 성공 Read보다 뒤에 있다. 모두 HEAD·패치와 일치하지만, 이번 실행에는 그 선언에 대응하는 **중간 설정 응답이 없으므로 완료 인정은 0/13**이다. 이전의 잠정 분석도 최종 지적으로 승격하지 않는다. 비공개 원문·정확한 식별자·복제 진단은 서버의 `TIMEOUT-DIAGNOSIS-20260928.md`에 보존했다.

## 확인된 코드 경계와 보완

1. 기존 영수증은 실제 `timeout`을 나중의 `review_scope_unverified`로 덮었다. 새 영수증은 실행 중단 사유와 검수 부족 사유를 별도로 보존하며, 호환 필드 `incomplete_reason`에는 우선 실행 중단 사유를 남긴다. 과거 영수증은 고치지 않는다.
2. Claude Code 2.1.282의 저장된 정상 Workflow 기록에서는 작업 시작 2건과 완료 알림 2건이 **단일 최종 결과보다 먼저** 왔고 종료 후 설정 조회도 있었다. 검수기는 이 확인된 순서에서만 `workflow_complete`를 인정한다. 미완료·중복·다른 세션·결과 뒤 진행·잘못된 작업 식별자는 거부한다. 이번 timeout 기록은 계속 거부된다. 다른 성공 이벤트 형태는 실제 증거 전까지 열지 않는다.
3. 새 시도에서 최상위 `REVIEW_PROGRESS_JSON`이 나오면 relay가 해당 시점의 설정을 따로 조회한다. 성공 Read, 같은 HEAD·패치, Opus 응답, 시작·중간 적용값의 일치를 모두 확인한 파일만 **부분 완료**로 기록한다. 최종 PASS에는 기존 종료 후 설정과 최종 범위·판정이 그대로 필요하다. 이번 과거 기록에 중간 응답을 소급 추가하지 않는다.
4. 신뢰 tick의 고정 해시를 새 runner·relay와 맞췄다. 공용 장부 코드와 기존 quota 복구 계약은 바꾸지 않았다.

## 재현과 검증

- 최초 실패: 정상 Workflow 단일 결과가 거부됨, 중간 설정이 있어도 부분 완료 0개, timeout이 검수 부족 사유로 덮임. 각각 회귀 검사로 고정한 뒤 수정 후 통과했다.
- 실제 저장 원문 무호출 재생: 이번 timeout은 여전히 미완료·0/13이고 기존 체크포인트와 동일하다. 정상 완료 기록은 `workflow_complete`로 분류된다. 이번 원문에 **합성 중간 설정 응답만** 붙인 비교에서는 11/13 부분 완료가 되지만, 이는 실제 완료나 과거 기록 수정의 근거가 아니다.
- 미완료 작업, 잘못된 세션·모델·설정·HEAD, 실패/누락 Read, 중복·충돌 설정 응답은 부분 완료 또는 최종 완료로 인정하지 않는다.
- 임시 장부에서 종료가 별도로 입증된 timeout을 `reconciliation`·비용 `null`로 정산하면 1회만 사용량을 반영하고 계정 UNKNOWN과 비용 미확정 표시를 유지한다. 같은 정산에 다른 비용을 재기록하면 거부한다. **이 시험은 현 예약의 종료 증거가 아니다.**
- 관련 Claude 검사 45개 통과. 전체 Python 검사는 이 격리 셸에서 727개 중 35개 오류·5개 실패·5개 건너뜀으로 종료했다. 오류의 다수는 로컬 HTTP 바인딩 권한 거부이며, 실패는 이번 변경과 무관한 PM timeout 복구 검사에 집중됐다. 따라서 전체 회귀 통과로 기록하지 않고 최종 커밋의 CI를 별도로 확인한다. 독립 Claude 검수도 아직 미확인이다.

PR #35의 실제 Claude 최종 검수와 이 새 코드 후보의 독립 Claude 검수는 모두 미완료다. 이 후보의 검사 성공을 어느 쪽의 최종 검수 PASS로 대체하지 않는다.
