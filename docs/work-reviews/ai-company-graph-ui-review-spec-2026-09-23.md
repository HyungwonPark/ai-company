# AI Company 그래프 UI 수정·검수 명세

작성일: 2026-09-23 · 버전: 1.0

## 1. 목적과 작업 경계

사용자가 처음 열었을 때 역할 배치를 읽을 수 있고, 전달선을 따라갈 수 있으며, 설명과 상세가 의도치 않게 닫히지 않는 그래프를 만든다.

- Work에서는 검수·수정 명세를 담당한다. 제품 구현과 실제 브라우저 검증은 서버 Codex가 담당한다.
- 기존 그래프를 기준으로 개선한다. 이번 작업에서 ComfyUI 도입, 그래프 도구 전면 교체, 실행 엔진 교체를 하지 않는다.
- 운영 배포·병합·DB 변경·서비스 재시작·모델 호출·권한 확대를 이 명세로 승인하지 않는다.
- 기존 PR 변경, 커플 서비스, 운영 기록·큐·타이머, PR #10의 pending 상태를 보존한다.
- AI 로그인/API 연결과 모델 목록은 별도 후속 항목이다. 이번 UI 수정의 완료 조건에 섞지 않는다.

## 2. 확인 기준과 증거 수준

검수 기준은 PR #21의 `f901f7861a0ff08c4fdaab6444211a1d84a20c9a`, 제품 기준은 `2087eccae3f946bc6d676904462a9b2acabd8521`이다. 이는 검수에 사용한 고정 기준이며 현재 원격 최신 커밋이라는 뜻은 아니다. 작업 시작 시 서버의 현재 브랜치·커밋·미커밋 변경을 확인하고 차이를 보고한다. 기존 변경을 덮어쓰거나 이 기준으로 강제 되돌리지 않는다.

### 확인한 사실

- 최초 화면 상태에 `pan={x:0,y:0}`이 설정되고, 첫 표시에는 폭 변경용 중앙 조정이 적용되지 않는다.
- 자기 이관·수정 반환·상향 연결은 전체 노드군 오른쪽 외곽을 기준으로 경유 지점을 배정한다.
- ‘맞춤’은 노드뿐 아니라 선과 이름표의 전체 경계를 사용한다. 긴 세로 배치도 축소에 영향을 준다.
- ‘조작’ 도움말은 다시 그릴 때 만들어지는 `details`이며 펼침 상태 저장 대상에서 빠져 있다. 상세 패널에는 별도의 상태 저장 코드가 있으므로, 두 문제를 동일하다고 단정하지 않는다.
- 공개 예시로 PC·모바일 배치의 경로 계산 6건과 정적 렌더링·문법 검사를 실행했다.
- 기본 실행 예시의 자기 이관 선 길이는 PC 기준 985px·581px였다. 경로 계산은 충돌 문제를 반환하지 않았다. 따라서 계산 성공만으로 가독성 합격을 판정할 수 없다.

### 미확인 사항

- Work 브라우저의 로컬 파일 URL 제한으로 실제 자동 클릭·드래그 검증은 수행하지 못했다. 다른 경로로 제한을 우회하지 않았다.
- 대화에 제공한 검수 화면은 제품 그래프 코드와 공개 예시를 사용한다. 실제 운영 API·모델 호출·승인과 연결하지 않았다.
- 운영 갱신, APK 실기기 조작, 서비스워커 갱신은 이번 검수에서 확인하지 않았다.

## 3. 수정 요구

### G1. 첫 배치와 확대 비율

1. 저장된 화면 위치가 없는 새 실행은 주요 역할 노드군을 표시 영역의 가로 중앙에 배치한다. 멀리 우회하는 선의 끝점을 중앙 계산 기준으로 삼지 않는다.
2. 기본 화면은 역할명을 읽는 것이 우선이다. 긴 전체 실행을 한 화면에 넣기 위해 무조건 축소하지 않는다. 기본 진입과 사용자가 누르는 ‘전체 보기’를 구분한다.
3. 최초 위쪽에는 PM과 첫 역할 묶음이 보이게 한다. 긴 실행의 아래쪽은 화면 이동으로 확인할 수 있게 한다.
4. ‘맞춤’이 전체 내용을 보여 주는 기능이라면 이름을 ‘전체 보기’로 명확히 한다. 현재 기능과 결과를 확인한 뒤 의미가 맞게 변경한다.
5. 사용자가 이동·확대한 뒤에는 같은 실행의 데이터 갱신 때문에 위치와 확대 비율을 초기화하지 않는다. 화면 폭 전환 시 선택 대상이 사라지지 않게 한다. 다른 실행을 처음 열 때는 기본 배치를 사용하고, 이미 열었던 실행으로 돌아가면 해당 실행의 화면 상태를 복원한다. 실행 ID가 다른 기록의 선택·상세를 재사용하지 않는다.
6. 기본 화면의 역할명은 화면상 14px 이상을 목표 수용값으로 사용한다. 제품의 현재 값이라는 뜻이 아니다. 공간이 부족하면 역할명 줄바꿈·단계 접기·선택 집중을 검토하고 글자를 더 줄이는 것으로 해결하지 않는다.

합격 기준: 저장 상태가 없는 동일 예시에서 노드군 가로 중심과 표시 영역 중심의 차이가 8 CSS px 이내다. 기본 상태에서 PM·첫 역할의 이름을 읽을 수 있고 잘리지 않는다. 이 수치는 이번 수정의 제안 수용 기준이다. 이미 사용자가 조정한 배치에는 중앙 정렬을 강요하지 않는다.

### G2. 선의 길이·방향·선택

1. 자기 이관은 해당 역할 가까이에서 닫히는 작은 고리 또는 이관 표시로 표현한다. 역할 자체가 바뀐 것처럼 보이게 하지 않는다. 원본 관계와 상세 근거는 유지한다.
2. 수정 반환·결과 보고선은 관련 노드 주변의 짧은 경로를 우선한다. 전체 그래프 오른쪽 외곽 우회를 모든 경우에 강제하지 않는다.
3. 주된 개발→검사→검수 흐름과 반환·이관 관계를 구별한다. 관계를 숨기는 방식을 쓴다면 숨겨진 관계 수와 전체 표시 수단을 제공한다. 실제 관계를 삭제하거나 바꾸지 않는다.
4. 선택한 선의 출발 역할·도착 역할·방향을 강조한다. 가까운 선과 이름표를 눌러도 정확한 관계가 선택돼야 한다.
5. 노드 관통, 화살표 끝 가림, 이름표 겹침을 기본 예시에서 해소한다. 복잡한 예외는 목록에서도 같은 관계를 선택할 수 있어야 한다.
6. 기존 1px 왕복 안정성을 보존한다. 유효한 경로는 유지하고 장애물 충돌 등 재탐색이 필요한 조건에서만 바꾼다.

합격 기준: 동일 예시·동일 배치의 전후 경로 길이, 꺾임 수, 노드 관통, 이름표 겹침을 비교한다. 자기 이관과 불필요한 외곽 우회가 실제로 줄어야 한다. 경로 계산의 오류 없음만으로 가독성 PASS를 표시하지 않는다. 모든 교차를 0으로 만들었다고 근거 없이 주장하지 않는다.

### G3. 도움말과 상세 유지

1. ‘조작’은 ‘사용법’으로 바꾼다. 노드 선택, 선 선택, 화면 이동, 노드 이동을 짧고 구체적으로 설명한다.
2. ‘사용법’ 펼침 상태를 선택·이동 모드 전환·목록 전환·데이터 갱신·테마 전환·화면 폭 변경 후에도 유지한다. 사용자가 닫을 때 닫힌다. 도움말 펼침은 같은 페이지의 사용자 설정으로 관리하되, 실행별 상세 선택과 섞지 않는다.
3. 노드·선 상세는 도움말과 별도 상태로 관리한다. 같은 대상을 보고 있는 동안 펼친 항목·스크롤 위치를 유지한다.
4. 선택 대상이 새 응답에서 없어진 경우, 조용히 패널을 닫거나 다른 대상으로 바꾸지 않는다. 현재 응답에서 확인되지 않는다는 안내를 제공한다.
5. 모바일 상세에서 닫기 버튼과 제목이 보이고, 닫은 뒤 기존 선택 위치로 돌아갈 수 있게 한다. 도움말 유지와 모바일 상세 닫기는 각각 테스트한다.

합격 기준: 도움말 펼침→노드 선택→이동 모드 전환→목록/그래프 전환→실제 앱의 데이터 갱신 경로에서 상태가 유지된다. 문구만 바꾸고 상태 문제를 남기면 미완료다.

## 4. 검증 행렬

Light·Black 각각에서 화면 폭 320·390·1440px을 확인한다. 브라우저 프레임 폭 검사와 실제 APK 검증은 별도 결과로 기록한다.

| 항목 | 재현·증거 | 합격 조건 |
| --- | --- | --- |
| 첫 배치 | 저장 상태 없는 진입, 표시 영역·노드 경계 측정 | 가로 중심 기준 충족, 첫 역할 가독성 확보 |
| 전체 보기 | 기본→전체 보기→확대 | 기능 의미 일치, 확대·이동으로 복귀 가능 |
| 카메라 유지 | 이동·확대→동일 실행 갱신 | 불필요한 초기화 없음 |
| 도움말 유지 | 펼침→선택·모드 전환·앱 갱신 | 펼침 상태 보존 |
| 상세 유지 | 선·노드 선택→갱신→닫기 | 선택·스크롤·키보드 초점 보존 |
| 관계 정확성 | 선·이름표·목록에서 같은 관계 선택 | 출발·도착·관계 ID 일치 |
| 경로 안정성 | 드래그 시작 후 동일 동작 안에서 1px 왕복 | 불필요한 큰 경로 이동 없음 |
| 경로 재탐색 | 다른 노드를 경로에 이동 | 충돌 감지와 재탐색, 불필요한 경로 변경 없음 |
| 키보드 | Tab·Enter·Space·Escape·방향키 | 초점 가시성, 선택 및 복귀 가능 |
| 같은 실행 | 보고·승인 링크와 뒤로가기 | 실행 ID와 문서 참조 유지 |

주의: 현재 드래그 시작 임계값은 4px이다. 정지 상태에서 1px만 움직여 아무 변화가 없는 것을 안정성 검증으로 세지 않는다. 먼저 임계값을 넘겨 드래그를 시작한 뒤 같은 동작에서 1px 왕복한다. 경로 함수 단위 검사와 실제 포인터 동작 검사를 구분한다.

예시는 기존 계획·실행 2종에 더해 긴 역할명, 반환 여러 개, 자기 이관, 같은 행 관계, 일부 이력 누락을 포함한다. 기본 예시와 추가 예시를 임의로 교체해 전후 비교를 유리하게 만들지 않는다.

## 5. Work 검수용 인수인계

서버에서 수정 전·후를 동일 데이터로 비교할 수 있는 묶음을 준비한다.

- 기준 커밋, 후보 커밋, 제품 코드 해시, 예시 데이터 해시를 기록한다.
- 원래 제품 렌더러를 사용한 독립 실행 미리보기를 제공한다. 검수용으로 따로 그린 그래프를 실제 제품 수정 결과처럼 제출하지 않는다.
- 기본 진입, 전체 보기, 선 선택, 사용법 유지의 전후 캡처와 실제 조작 기록을 제출한다.
- 결과를 단위 검사 / 브라우저 조작 / 실제 앱 갱신 / APK 실기기 / 운영 적용으로 나누고 PASS·FAIL·미실시를 명시한다.
- 미리보기에는 예시 자료·운영 연결 없음 표시를 둔다. 운영 DB·토큰·키·사용자 입력 원문·서버 내부 정보를 포함하지 않는다.
- Work에서 접근할 검수 주소가 필요하면 기존에 승인된 비운영 검수 경로의 사용 가능 여부를 먼저 확인한다. 새 공개 서비스 개방이나 운영 프록시 변경을 임의로 하지 않는다. 로컬 파일 URL 제한을 우회하지 않는다.
- 사용자 실기기 확인이나 운영 적용 승인이 필요하면 개발 미완료와 구분해 해당 단계만 대기시킨다.

## 6. 서버 Codex에 전달할 지시

이 명세에 따라 그래프 UI를 수정하고 검증해 주세요. 먼저 현재 코드·브랜치·미커밋 변경과 기존 지침을 읽고, 고정 기준과 현재 코드의 차이를 확인하세요. 확인된 결함의 실패 검사를 먼저 만들고 G1~G3를 순서대로 수정하세요. 기존 1px 왕복 안정성, 정확한 선 선택, 같은 실행의 보고·승인 연결을 보존하세요.

완료 보고에는 ‘수정된 것 / 실제 조작으로 검증한 것 / 미검증 / 별도 승인 대기’를 구분하세요. 테스트 개수나 CI 성공만으로 시각적 검수 완료를 선언하지 마세요. 배포·병합·운영 서비스·DB·승인 상태 변경은 포함하지 않습니다. 서버 접근 권한이나 브라우저 사용이 차단되면 해당 검증을 미실시로 남기고 새로운 권한을 임의로 얻지 마세요.
