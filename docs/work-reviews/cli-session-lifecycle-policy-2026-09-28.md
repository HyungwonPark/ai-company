# CLI 세션 유지·요약·전환과 서버 인수인계 명세

기준일: 2026-09-28 KST · 사용자와 Work PM의 대화 명세 · v1.0

## 목적과 확정한 방향

**실행은 기존 CLI를 활용하고, 같은 작업에서는 세션을 재사용하되, 목표와 공식 상태는 세션 밖에 보존한다. 잘 만들어야 할 것은 오래 살아 있는 세션이 아니라 세션이 바뀌어도 목표와 작업이 이어지는 프로젝트다.**

현재 프로젝트에서 서버 CLI가 실용적인 이유는 이미 갖춰진 개발 도구·작업 공간·검사·인증 연결을 재사용하고 같은 작업의 재탐색과 재설명을 줄일 수 있기 때문이다. 이는 우리 프로젝트의 구현 선택이며 CLI가 API보다 본질적으로 저렴하다는 판정이 아니다. API 기반 시스템도 상태 보존과 검색을 구현할 수 있다.

대화 기록은 자동 RAG가 아니다. 외부 자료에서 필요한 근거를 찾아 주입하는 검색 기능과, 세션 기록을 다시 전달하거나 요약하는 기능을 구분한다. 기록이 쌓인다는 이유로 토큰이 자동 감소하지 않으며, 새 대화가 과거 세션과 모든 파일을 자동 검색한다고 가정하지 않는다.

작은 작업의 단일 개발 역할 허용·독립 작업만 병렬화·규칙 기반 상태 관리·필수 독립 검수 유지에 대한 결정은 [역할 선택·후속 구현 명세](adaptive-orchestration-policy-2026-09-28.md)에 둔다. 이번 문서는 그 결정을 바꾸거나 새 프레임워크 도입을 지시하지 않는다.

## 재시작이 의미하는 것

| 동작 | 문맥과 비용에 대한 판단 |
| --- | --- |
| 서버·터미널·CLI 프로세스 재시작 후 같은 대화 resume | 저장된 대화 기록을 복원하므로 이것만으로 입력 문맥이 짧아지지 않는다. 재시작 자체를 절약 수단으로 삼지 않는다. |
| 새 개발 대화 | 이전 대화 기록을 이어 붙이지 않을 수 있어 문맥을 줄일 여지가 있다. 대신 지침·도구·인계 입력과 재조사 비용이 들며 총비용 감소는 측정해야 한다. |
| compact/문맥 요약 | 같은 작업의 핵심을 유지하며 앞선 기록을 줄인다. 요약 자체의 모델 사용과 정보 누락·재조사 비용을 고려한다. 매번 수동 실행하지 않는다. |
| fork | 새 대화 ID라도 기존 기록을 복제하는 방식이면 문맥 절약과 같지 않다. |
| 표시 사용량 초기화 | 세션 화면의 합계가 0이 되어도 계정 사용량·구독 한도·예약·정산 의무가 초기화되는 것은 아니다. |

명령은 설치된 CLI 버전과 실행 방식에 맞춰 확인한다. Codex 대화형 CLI의 `/new`, `/resume`, `/compact`, `/status`와 Claude의 `/clear`, `/compact` 등은 설명용 예시이며 이번 문서를 읽는 즉시 실행할 명령이 아니다. 대화형 명령을 제품의 비대화형 실행기에 그대로 전달하지 않는다. 프로세스 생성 코드의 `start_new_session=True` 같은 OS 세션 설정도 모델의 새 대화와 구분한다.

반복 입력에는 공급자·모델·요청 내용에 따라 프롬프트 캐시가 적용될 수 있다. 프로세스 재시작이나 새 대화 ID만으로 캐시가 반드시 사라진다고 단정하지 않는다. 반대로 요약 등으로 입력 앞부분이 바뀌면 재사용 범위가 달라질 수 있다. 입력 토큰 수·캐시 토큰 수·실제 비용·구독 한도는 다른 지표다. API 가격표를 구독 한도 절약률로 환산하지 않는다.

## 개발 대화의 전환 기준

- 같은 버그·후속 수정·같은 완료 조건을 처리하는 동안은 현재 개발 대화를 우선 유지한다.
- 관련 작업이 계속되지만 긴 기록 때문에 문맥이 부족하면 필요한 목표와 근거를 외부에 먼저 남기고 지원되는 요약을 고려한다. 요약 전에 미저장 상태와 빠지면 안 되는 판단을 확인한다.
- 현재 작업을 마쳤고 다음 목표가 충분히 다르면 짧은 인계 기록으로 새 개발 대화를 시작할 수 있다. PR #36 복구·검수 완료 후 단일 개발 역할 지원에 착수하는 시점이 후보이며, 지금 즉시 재시작하라는 뜻은 아니다.
- 시간·턴 수·서버 가동 시간만으로 주기적 재시작을 강제하지 않는다. 현재 문맥, 다음 목표와 인계 비용을 보고 판단한다. 현재 서버 문맥을 직접 확인하지 않았으므로 절약 효과나 즉시 전환 필요성을 확정하지 않는다.
- 새 대화로 옮겨도 브랜치·미커밋 변경·작업 ID·승인·검수 대상·예약·계보를 바꾸지 않는다. 대화 전환만을 위해 강제 커밋·stash·reset·프로세스 종료를 수행하지 않는다.

## 서로 다른 세션의 경계

| 대상 | 적용 규칙 |
| --- | --- |
| 서버 Codex의 일반 개발 대화 | 위 유지·요약·새 대화 기준을 적용한다. 개발 설정은 [효율 지침](server-codex-efficiency-policy.md)을 따른다. |
| 제품이 장부로 관리하는 실행 세션 | 기존 상태 전이·소유권·실행 종료·체크포인트·정산 조건을 따른다. 개발 대화 정리 정책으로 강제 초기화하지 않는다. |
| 현재 PR #35 Claude 검수와 PR #36 복구 실행기 | [고정 후보의 한정 적용·수동 재개 절차](pr36-acceptance-7ab7681-2026-09-28.md)를 따른다. 제품 일반 세션 규칙과 전용 검수기의 재시도 계보를 임의로 통합하지 않는다. |

PR #35 `1d54d3a0ea5a21c7c2dc588f824c6567231829b4`의 `sessions.py`는 문맥 소진으로 인한 `NEEDS_CONTEXT_HANDOFF`에서 실행 종료 등을 확인한 뒤 새 세션을 예약한다. 한도 대기는 별도 경로다. 전용 검수기의 `--resume-quota`는 고정 패치·체크포인트에 묶인 후속 시도 절차이므로 모든 재개가 같은 세션 ID여야 한다는 규칙도 새로 만들지 않는다.

새 세션·프로세스 재시작·시간 경과만으로 UNKNOWN을 해제하지 않는다. 현재 PR #35 검수는 회복 예상 시각이 지나도 기존 증거·정산·수동 재개 조건을 따른다. 기존 quota 타이머의 승인된 동작은 변경하지 않는다. 원본 증거와 기존 장부를 보존하며 문서 요약을 새로운 정산 근거로 삼지 않는다.

## 세션 밖에 보존할 인계 기록

기존 비공개 RUNBOOK·작업 기록의 적절한 위치에 짧은 인계 항목을 남긴다. 새 상태 DB를 만들지 않는다. 장부·Git·검수 원문 등 해당 사실의 공식 원천을 연결하고, 인계 문서는 관측 시각이 있는 요약으로 취급한다. 새 대화는 인계와 현재 원천 상태를 대조한 뒤 작업을 이어간다.

| 항목 | 남길 내용 |
| --- | --- |
| 목표 | 사용자가 승인한 목표·이번 범위·완료 조건 |
| 코드 | 저장소·브랜치·HEAD·worktree·미커밋 변경의 위치와 보존 상태 |
| 진행 | 끝난 일과 그 근거·미해결 항목·검증한 것·아직 확인하지 못한 것 |
| 실행 상태 | 관련 프로세스·세션·예약·장부 상태·차단 원인과 원천 기록 위치 |
| 권한 | 승인된 대상·범위·근거와 아직 필요한 별도 요청 |
| 다음 행동 | 다음 한 묶음과 완료 조건·현재 적용할 문서의 고정 커밋/경로 |
| 출처 | 작성 시각·기준 후보·검사/검수/로그 경로·필요한 해시 |

목표 결정·원문 로그·검수 패치·승인·영수증·체크포인트를 삭제하거나 요약으로 덮어쓰지 않는다. 인계 전문에 과거 대화와 정상 로그를 모두 복제하지 않는다. 비공개 식별자·인증 정보·운영 원문은 공개 GitHub에 올리지 않는다.

## 효율을 판단할 방법

**같은 모델·같은 시작 코드·같은 완료 조건에서 검수 통과 작업 한 건당 비용, 소요 시간, 재수정 횟수와 사람의 개입량을 비교한다.** 모델·effort·CLI 버전·작업 범위·캐시 조건이 다르면 차이를 기록하고 세션 방식만의 효과로 단정하지 않는다.

기존 로그에서 가능한 범위로 입력·캐시·출력 사용량과 계획·개발·하위 에이전트·독립 검수·요약·재조사·실패·재개를 포함한 작업 전체 사용량을 기록한다. 일부 세션 화면만으로 모든 사용량을 확인했다고 보고하지 않는다. 알 수 없는 값은 미확인으로 남긴다. 모델 작업 시간·한도 대기·승인 대기를 구분하며, 정상 목표 결정/승인과 인계 누락·복구를 위한 사람의 개입도 나눠 기록한다.

현재 비교 실측은 없으며 몇 퍼센트 저렴하다는 결론을 내리지 않는다. 우선 정상 업무에서 기준선을 쌓고, 비교 실험이 필요하면 별도 범위와 동일 조건을 정한다. 이번 점검을 위해 모델을 시험 호출하거나 새 대시보드·라우터·비용 시스템을 만들지 않는다.
