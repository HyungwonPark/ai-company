# PR #29 Claude 검수기 후속 검증

이번 후보는 운영 worker가 아닌, PR HEAD를 읽기 전용으로 검사하는 로컬 Claude Code 검수기와 릴레이를 수정한다. PM 응답의 내용 검수와 PR 코드 검수는 별개의 판정이다. 별도 초안 PR #30은 실제 Astra PM 행동 평가의 입력·판정 기준만 고정하며, 실제 PM 응답을 얻거나 내용 검수를 통과한 것으로 취급하지 않는다.

## R29-1: 검수 입력의 출처와 전달

수정 전에는 모델이 도구를 한 번도 사용하지 않아도 형식상 `판정: PASS`를 반환하면 통과할 수 있었다. 또한 `gh pr diff` 응답이 일부로 잘려도 그 응답 자체의 해시만 기록했으므로, PR의 전체 변경 범위인지 증명하지 못했다.

검수기는 GitHub API에서 PR의 기준 커밋과 HEAD를 확인한 뒤 로컬 Git의 merge-base부터 HEAD까지 전체 패치를 생성한다. 패치가 비어 있거나, 바이너리 변경을 포함하거나, 인라인 전달 상한을 넘으면 모델 호출 전에 중단한다. 패치와 최종 프롬프트의 SHA-256을 별도로 고정하고, 릴레이가 정확한 프롬프트를 CLI에 전달한 사건을 남긴다. 성공 판정에는 이 전달 증거, 실행 완료, 동일 HEAD·패치 해시를 명시한 검토 범위, 미검토 항목 없음이 모두 필요하다. 검수 전후에 PR HEAD와 기준 커밋의 변경도 확인한다. 모델이 선언한 검토 범위는 판단 증거이며, 실제 내용의 정확성을 기계적으로 보장하지는 않는다.

회귀 검사에는 빈 도구 사용 결과, 다른 HEAD, 관계없는 읽기·실패한 읽기, 정상 직접 전달·하위 작업, 잘린 GitHub 패치 대신 두 파일을 모두 포함하는 로컬 Git 패치가 포함된다.

## R29-2: 중복 예약과 재시도

수정 전에는 두 `--retry-unstarted` 실행이 같은 종료 사실을 보고 각각 예약할 수 있었다. 릴레이 종료 후 첫 runner가 보고서를 기록하기 전에 두 번째 실행이 디렉터리를 옮기면 첫 보고서가 새 시도에 섞이는 현상도 독립 검수에서 재현했다.

예약 잠금은 이동 대상 디렉터리 밖의 안정된 경로에 두고, 최초 예약부터 보고서·영수증 작성 완료까지 유지한다. 잠금 아래에서 종료 및 프롬프트 전달 여부를 다시 검사한다. 모델 호출 가능성이 있는 기록은 재시도하지 않는다. 최초 예약과 재시도, 동시 재시도, 릴레이 종료 후 보고서 기록 중 재시도 경계를 검사한다.

## 적용과 복구

코드·격리 검사·최종 HEAD CI·독립 검수 후, 저장소 밖의 기존 신뢰 검수기 두 파일을 해시 대조하여 갱신하고 최종 HEAD에 대해 한 번 실행한다. 검수 결과는 비공개 로컬 디렉터리에 저장한다. 적용은 운영 서비스·DB·기존 실행·승인 기록을 바꾸지 않는다. 설치나 단일 검수에 실패하면 이전 신뢰 검수기 파일을 복원하고 해당 시도의 원시 증거를 보존한다. 프롬프트 전달이 시작된 같은 HEAD는 재호출하지 않는다. 30분 실행 제한과 권한 제한은 유지하며, 별도 1달러·턴 상한은 두지 않는다.

실제 Astra PM 행동 평가, 마스터 조작, 운영 배포, 병합, PR #10 승인 변경은 이번 완료 판정에 포함하지 않는다.
