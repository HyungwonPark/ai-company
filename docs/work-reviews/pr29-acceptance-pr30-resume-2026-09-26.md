## 다음 개발 B — PR 검수의 제한 대기와 안전한 재개

- 검수 작업은 repo·PR·base·HEAD·patch·검수 정책 버전에 결합하고, 개별 attempt 기록은 불변으로 보존한다.
- 완료 PASS, 완료 REVISE, 공급자 제한으로 명확히 종료한 대기, 실행/결과 미확인을 구분한다.
- 프롬프트 전달 후 제한이어도 공급자 오류 분류·프로세스/하위 작업 종료·원시 사건이 확인된 경우에만 WAITING_QUOTA로 둔다. 단순 오류 문구 검색이나 성공 결과 없는 종료만으로 재시도 자격을 만들지 않는다.
- 공용 cooldown 해제와 계정/호스트 예약을 원자적으로 획득한 한 worker만 재개한다. 이전 시도와 새 시도를 연결하고 같은 HEAD 동시 호출을 막는다.
- 동일 세션 재개는 CLI 지원과 세션 상태를 확인한 경우에 우선한다. 현재 검수기는 no-session-persistence를 사용하므로 세션 재개 가능성을 가정하지 않는다. 재개가 불가능하면 종료가 확인된 제한 실패에 한해 새 시도로 연결하는 정책과 근거를 명시한다.
- 결과 미확인·살아 있는 하위 작업·손상된 영수증은 NEEDS_RECONCILIATION으로 남긴다. 잠금 파일·시도 디렉터리 삭제나 빈 커밋으로 새 HEAD를 만들어 우회하지 않는다.

- 재시작·동시 재개·늦은 완료·중복 정산·제한과 인증 실패의 구분을 모의 검증한다.

5. 실제 Astra E1~E6, 독립 내용 검수, 고정 후보의 Claude 코드 검수를 각각 구분해 제출한다. 공급자 제한이면 영속 대기와 재개 근거를 보고하며 완료로 표시하지 않는다.
6. 같은 후보를 제공하는 시험 UI와 접속 안내가 검증된 다음에만 마스터 직접 조작을 요청한다. 현재 운영 APK에 새 후보가 적용됐다고 가정하지 않는다.
