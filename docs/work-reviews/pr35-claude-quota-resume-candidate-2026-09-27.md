## 한정 적용안과 복구

이번 문서와 PR 게시는 운영 변경 승인이 아니다. 적용 전 고정 HEAD·패키지 해시, PR #35의 원격 HEAD/CI, 현재 설치 3파일·전환 기록, 원본 2결과·종료·회복 시각, 단일 예약/계정 상태, worker 2개 중지/자동 시작 해제, 기존 quota timer·웹·커플 서비스 상태를 다시 대조한다. 하나라도 달라지면 중단한다.

추가 승인이 필요한 운영 변경은 **한 묶음**이다.

1. 검토한 패키지의 `runner.py`, `claude_control.py`, `shared_calls.py`, `tick.py`만 신뢰 경로에 원자 설치하고, 같은 코드 해시와 기존 장부 경로를 가리키는 전환 기록을 갱신한다. 기존 파일·기록을 별도 비공개 백업으로 보존한다. 전역 CLI는 바꾸지 않는다.
2. 원본 종료·누적 사용량·현재 제한이 사전 대조와 같을 때만 현재 Claude 검수 예약을 **정확히 한 번** 정산하고, 해당 정산에 연결된 UNKNOWN만 회복 시각을 가진 COOLDOWN으로 조정한다. 새로운 제한·예약·사용량 차이가 있으면 쓰지 않고 UNKNOWN을 유지한다. 과거 E2 UNKNOWN은 건드리지 않는다.
3. 해당 PR/head/base/패치와 비공개 체크포인트·장부·계정에 묶인 manifest를 만들고 전용 user timer 하나를 설치·활성화한다. 설치 직후에는 아직 회복 전이면 `WAITING_QUOTA`, 조건 불일치면 `NEEDS_RECONCILIATION`이어야 하며, 그 상태에서 새 호출이 0건인지 확인한다. 회복 이후에도 전제 조건과 기존 승인된 검수 범위가 유지될 때에만 남은 검수 한 건을 재개한다.

실패 시 전용 timer를 먼저 중지·해제하고 활성 프로세스·예약·장부를 확인한다. **새 예약 전**이라면 신뢰 경로와 전환 기록만 보관한 이전 버전으로 되돌리고, 현재 장부의 정산·계정 제한은 유지한다. **새 예약 후**에는 DB를 과거 백업으로 덮어쓰지 않는다. 전용 timer를 중지하고 현재 체크포인트·장부를 보존해 재조사한다. PM·번역 worker는 계속 inactive/disabled로, 기존 quota timer 일정은 그대로 둔다.

실제 적용 전까지 현재 상태는 `종료·정산 확인 필요`이며, 2026-09-28 02:00 KST는 **가장 이른 다음 점검 시각**일 뿐이다. Claude 최종 검수 결과와 운영 자동 재개는 아직 미완료다.
