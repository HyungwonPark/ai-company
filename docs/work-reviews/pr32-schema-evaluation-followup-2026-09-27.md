## 통합 운영 적용·실제 평가 승인안

**이 절은 준비된 후속 승인안이며 이번 PR의 운영 적용 권한이 아니다.** 변경 대상은 고정 제품 릴리스 포인터, PM·조정기 및 번역 worker **두 유닛의 재활성화**, 새 코드에 맞춰 재검증할 비공개 공용 호출 채택 증빙, 그리고 기존 E1~E6 평가의 후속 revision이다. 웹 이미지·커플 서비스·quota 가드 코드와 타이머 일정·전역 CLI·계정 상태·예산·PR #10 승인·기존 DB 행·병합은 변경 대상이 아니다. DB 스키마 변경도 없다.

1. 적용 직전 설치 릴리스·두 유닛·비공개 설정/카탈로그·전용 CLI·quota 가드·타이머·기존 대기 작업과 공용 장부를 고정 후보에 대조한다. 기존 여섯 건의 SETTLED 및 미정산 0건을 확인하고 DB/장부의 일관 사본과 파일 해시를 남긴다. 차이가 있으면 적용하지 않는다.
2. 현재 중지된 두 worker를 유지한 채 릴리스 포인터만 고정 후보로 교체한다. 새 코드의 실제 import·네 전송 파일 해시·무호출 기동 검사를 다시 수행하고, 모든 모델 호출 경로가 같은 장부를 쓰는 새 채택 증빙을 고정한다. 확인이 끝나면 두 유닛을 각 1개 프로세스로 활성화한다. 시작 전 대기 목록에 승인 범위 밖의 작업이 있으면 신규 호출을 막고 보고한다.
3. 새 시험 revision은 이전 평가 루트를 명시적으로 가리키고 기존 **최대 24호출·실행 1800초·자동 수정 2회**에서 여섯 건과 실제 소요 시간을 차감한다. E1의 PM 제안 호출 **한 건만** 먼저 실행한다. 전송 스키마 수용, 내부 계약, 저장 계획, 종료·정산을 확인하기 전에는 계획 검수나 E2~E6으로 넘어가지 않는다. 성공 시 같은 승인 범위와 잔여 예산 안에서 E1 후속 검수와 E2~E6을 진행하고, 내용 판정은 별도로 기록한다. 한도·공통 요청 오류·인증/미정산에서는 추가 호출 없이 각 대기 상태를 유지한다.
4. 필수 해시·단일 worker·인증/장부·기록 보존 검사가 실패하거나 뜻밖의 호출이 시작되면 worker를 중지한다. **새 예약이 0건**이면 이전 릴리스 포인터를 복구하되 두 worker는 중지·자동 시작 해제 상태로 둔다. **새 예약이 생겼다면** 구형 호출 경로를 켜지 않고 현재 DB·장부·체크포인트·원시 증거를 보존해 조정한다. 어느 경우에도 과거 DB 백업으로 덮어쓰지 않는다. quota 가드와 타이머·관리 웹·커플 서비스는 유지한다.

마스터의 앱 목표 입력·계획 확정은 이 평가가 대신하지 않는다. 첫 PM 호출 성공도 전체 E1이나 PM 판단 품질의 합격은 아니다.
