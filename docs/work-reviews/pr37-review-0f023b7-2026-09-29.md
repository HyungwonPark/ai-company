## R37-1 · 중간 설정 실패가 전후 설정 성공으로 우회됨 — P1

위치: [runner 249~252행](https://github.com/HyungwonPark/ai-company/blob/0f023b727f1ed1a3b557c845a44fcf3862de3666/scripts/review_pr_with_claude.py#L249-L252).

합성 입력에 정상 before, 성공 Read, 바인딩된 진행 선언, 해당 `progress-1`의 `effort=medium`, 정상 after를 넣었다. 해당 중간 증거는 검증되지 않았지만 전역 `observed_configuration.verified`가 참이어서 해당 선언을 완료로 인정한다.

기대: `reviewed_files=[]`. 실제: `reviewed_files=['a.py']`, `scope_verified=true`, 중간 검증 목록은 비어 있다. 시점별 설정이 실패했다는 명시적 증거를 최종 전후 설정 성공이 덮으므로 검토 범위 완료 판정의 신뢰성이 깨진다.

**수정 기준:** 해당 선언의 중간 설정 실패·충돌이 있으면 전후 설정 성공으로 인정하지 않는다. 중간 증거가 없는 기존 기록의 호환 처리와, 새 시도의 명시적인 실패 증거를 구분한다. 실패/충돌 뒤 정상 after가 와도 완료 인정되지 않는 검사를 추가한다. 과거 원문이나 체크포인트를 소급 수정하지 않는다.

**수정 기준:** 선언 인식·길이/형식 필터·번호 생성 규칙을 양쪽에서 일치시키고 선언과 응답의 연결을 명확히 한다. 이벤트 식별자나 해시 연결도 선택할 수 있으며 별도 계수의 우연한 일치에 의존하지 않는다. 긴 선언·형식 오류·자식 출력·응답 지연/순서 변화에서 다른 선언의 설정을 쓰지 않는 회귀 검사를 추가한다.

R37-1·2 재현: [중간 설정 증거 재현](repros/pr37-progress-evidence-0f023b7.py). 합성 이벤트만 사용하며 실제 timeout 기록의 완료를 다시 계산하는 도구가 아니다.

## R37-3 · 정상 Workflow 결과와 완료 재확인 경로가 불일치함 — P1

위치: [runner 425~431행](https://github.com/HyungwonPark/ai-company/blob/0f023b727f1ed1a3b557c845a44fcf3862de3666/scripts/review_pr_with_claude.py#L425-L431), [tick 98~102행](https://github.com/HyungwonPark/ai-company/blob/0f023b727f1ed1a3b557c845a44fcf3862de3666/scripts/review_claude_quota_tick.py#L98-L102).

새 요약기는 `workflow_complete`를 허용하지만 `completed_review_verified()`는 여전히 저장된 종류가 `single`인 경우만 허용한다. 종료·전후 설정·전체 검토 범위·정산이 갖춰진 임시 증거에서 다음을 재현했다.

| 항목 | 실제 재현값 |
| --- | --- |
| 원문 해석 | workflow_complete |
| 요약 PASS / 전체 범위 / 하위 종료 | 모두 true |
| 임시 예약 | SETTLED |
| 완료 재확인 | false |
| tick 검사 함수 | NEEDS_RECONCILIATION |

같은 원문에서 **임시 파생 기록의 종류만 잘못된 single로 바꾸면** 완료 재확인이 true, tick이 DONE으로 바뀐다. 제품 코드·실제 기록은 변경하지 않았다.

**수정 기준:** 원문을 재생해 얻은 종류와 저장된 종류의 일치를 확인하면서 정상 `workflow_complete`를 수용한다. 문자열 허용 목록만 늘리고 원문과의 비교를 빠뜨리지 않는다. 정상 Workflow의 영수증 → 정산 → 완료 재확인 → tick DONE과, 종류 불일치 거부를 통합 검사한다. 기존 single·quota·중단·미정산 거부도 유지한다.

재현: [Workflow 완료 재확인 재현](repros/pr37-workflow-completion-0f023b7.py). 임시 디렉터리와 임시 SQLite만 사용하고 검사 함수만 호출한다. 실제 tick 실행·모델·운영 장부에 접근하지 않는다.
