## 판정

PR #33의 B~E 비운영 구현·검증 범위를 수용한다. 앞선 PM 스키마 네 지점, 공통 요청 오류 뒤 평가 연속 호출, 후속 평가에서 선행 6건의 누적 예산이 빠지는 문제를 이번 후보에서 해결로 기록한다. 검수 범위에서 추가 제품 차단 결함은 발견하지 못했다.

**운영 적용은 아래 복구 조건을 포함한 명시적 마스터 승인 후 진행하도록 권고한다. 이 문서 자체는 운영 승인이나 실제 Astra 평가 PASS가 아니다.** 기존 PR #31·#32 회귀 해결과 PR #10 pending을 보존한다.

서버는 앞서 승인된 자동 시작 해제를 적용해 두 worker가 inactive/disabled이고 quota 타이머는 활성이라고 보고했다. Work는 서버 유닛·비공개 장부·현재 운영 상태를 직접 조회하지 않았다.

## 운영 문서 보완 1건: 실패한 새 호출 뒤에도 disabled 유지

[제출 적용·복구안](https://github.com/HyungwonPark/ai-company/blob/27d7cc44506436e3dc8285096670f43789820d5c/docs/work-reviews/pr32-schema-evaluation-followup-2026-09-27.md)의 4단계는 **새 예약 0건** 분기에만 중지·자동 시작 해제를 명시한다. 새 예약이 생긴 분기는 중지·기록 보존만 명시한다. 실제 비공개 명령은 읽지 못했으므로 이미 잘못 설정됐다고 단정할 수는 없다.

두 유닛을 재활성화하는 적용안인 만큼 모든 실패 복구 분기에 아래 조건을 명시한다.

> E1 호출·전송 계약·종료/정산 검증 실패, 공통 요청 오류, 설치/장부/단일 실행 검증 실패 또는 뜻밖의 호출이 발생하면 새 예약 유무와 관계없이 PM·번역 두 worker를 중지하고 자동 시작을 해제한다. inactive/disabled를 확인한다. 새 예약 유무는 릴리스 포인터 복구 가능 여부만 결정한다. 현 DB·공용 장부·체크포인트·종료 근거와 quota 가드 타이머는 보존한다.

예상된 한도 대기는 기존 영속 대기/첫 호출 상한을 유지하며 임의 재호출하지 않는다. PM 내용 검수의 정상적인 REVISE를 기반시설 오류와 혼동하지 않는다. 미확인 종료는 종료 완료로 만들지 말고 신규 호출을 막은 채 조정 대기로 남긴다.

**이 조건은 제품 코드 전면 재수정 사유가 아니다.** 서버는 지시서·비공개 복구 명령에 반영하고 읽기 전용 상태 대조/격리 복구 검증을 준비한다. 동일 제품 해시를 유지하는 운영 절차 보완이라면 같은 제품 코드의 전체 회귀나 Work 수용을 처음부터 다시 반복하지 않는다. 제품 코드나 실제 적용 범위가 달라지면 변경분을 별도로 대조한다.

## 마스터 승인에 포함할 통합 범위

승인 후보는 다음과 같이 한정한다.

- 제품 `364a5145d4eb00815937cdf696680143038c3751`, archive SHA-256 `2b10135f0bec80fcc8d188241830e68e8d5e0c1103a3e9f5454189fcb72e3331`의 릴리스 적용.

- 사전 점검 후 PM·번역 worker 두 유닛의 재활성화. 실제 활성 프로세스 각각 1개와 기존 작업의 승인 범위를 확인.
- 기존 평가 6건의 정산·누적 사용량을 포함하는 후속 revision 생성 및 E1 PM 호출 총 1회 검증.

- 위 실패 복구 조건에 따른 두 worker 중지·자동 시작 해제와 기록 보존.

서버는 적용 직전 파일/해시·실제 import·네 report 스키마·전용 CLI·유닛·장부/미정산·기존 대기 작업을 대조한다. 승인 범위 밖 대기 작업이 있거나 상태가 달라졌으면 신규 호출을 막고 차이를 보고한다. 최초 PM 한 호출 검증과 후속 단계의 한도는 평가 root를 바꿔 초기화하지 않는다.

Claude UNKNOWN 차단은 그대로 유지한다. 번역 프로세스가 active라고 실제 번역 준비가 끝났다고 보고하지 않는다. 웹 이미지·커플 서비스·quota 가드 코드/타이머 일정·전역 CLI·DB 스키마·PR #10 pending·서명키·병합은 이번 변경 대상이 아니다.

마스터가 이 통합 범위를 명시 승인하면 같은 범위의 적용→E1 확인→후속 평가마다 승인을 다시 묻지 않는다. 현재 문서 게시만으로 서비스나 모델을 재시작하지 않는다.
