## A. 번역 실행 계약과 기존 작업 보존

1. 설정 검증·CLI 준비 검사·실제 호출이 **같은 실행 파일과 호환 근거**를 보도록 정리한다. 전역 Claude CLI를 설치·업데이트·다운그레이드하거나 공용 PATH를 바꾸지 않는다.
2. 우선 현재 `2.1.283`을 비운영에서 조사해 필요한 옵션·입출력 이벤트 계약을 확인하고, 검증된 조합만 명시적으로 허용한다. 호환을 입증할 수 없다면 서비스 전용 경로의 검증된 `2.1.270` 고정 후보를 준비하는 등 기술적 대안을 스스로 선택해 근거를 남긴다. 이 선택만으로 마스터에게 질문하지 않는다. 실제 운영 설치 여부는 아래 승인 경계를 따른다.
3. 버전 검사를 삭제하거나 모든 상위 버전을 허용하는 방식으로 우회하지 않는다. 모델 식별, 빈 도구/MCP 목록, 도구 호출 거부, 결과 형식·보호 문자열 검사, 종료 확인·예약·정산을 보존한다. 도움말과 모의 출력 확인을 실제 모델 실행 근거로 표시하지 않는다.
4. 요청한 모델 버전과 관측한 CLI 버전·실행 파일을 구별한다. 명령을 만드는 파일과 검증한 파일이 달라지면 실행하지 않는다. 미검증 CLI 변경을 감지했을 때 명확한 대기 이유를 남긴다.
5. `2.1.270`으로 저장한 기존 작업을 `2.1.283`으로 실행했던 것처럼 덮어쓰지 않는다. 기존 작업 ID·원문·승인 원문·결과·재시도 횟수·누적 예산·설정 digest를 보존한다. 새 설정 때문에 기존 문서가 대량 재번역되거나 같은 작업이 이중 호출되지 않게 전환 정책과 근거를 구현한다.
6. 호환되지 않는 기존 작업은 명시적으로 대기시킨다. 실제 실행 설정 전환이 필요한 경우 이전 기록을 보존하고 허용된 새 설정과 연결한 이력을 남긴다. 이미 끝난 작업을 단순 버전 변경만으로 다시 호출하지 않는다.

## B. 서비스가 살아 있는 상태와 실제 번역 가능 상태

1. 프로세스 기동·heartbeat와 모델 호출 준비 상태를 분리한다. 유효한 설정에서 CLI 미검증·계정 미확인·사용량 제한이 있으면 모델 호출을 막으면서 원인과 다음 조건을 관측할 수 있어야 한다.
2. 설정 형식 오류, DB 손상, 실행 여부가 불확실한 자식 프로세스 등을 정상 대기로 숨기지 않는다. 시작 실패는 원인을 남기고 재시작 폭주를 막는다. 정상 준비 대기는 `active`만으로 처리 가능하다고 표시하지 않는다.
3. 기존 상태 조회 경로에 “서비스 실행 중 / 번역 대기 / 계정 확인 필요”처럼 상태와 이유를 구별해 제공한다. CLI 버전 불일치를 빈 도구 목록 미확인이라는 다른 이유로만 표시하지 않는다. 계정 식별값·토큰·내부 경로는 공개 상태에서 가린다.
4. 검증된 실행 환경으로 돌아오거나 신뢰한 절차로 계정 상태가 해결되면, 기존 대기 작업을 그 원인에 맞게 재평가한다. `UNKNOWN`을 임의로 `AVAILABLE`로 바꾸지 않는다. 원인 해결 전 호출 0회, 해결 후 공용 예약을 거친 허용된 작업 1회만 실행되도록 한다.
5. 기존 `blocked` 작업 중 어떤 이유가 자동 재평가 대상인지 명시한다. 인증 실패·원문/계획 변경·보호 검사 실패까지 일괄 재시도하지 않는다. 계정 대기와 CLI 대기가 겹친 경우도 검사한다.

이 묶음은 기존 heartbeat·상태 API와 인계 자료를 활용한다. 공개 웹 전체 개편이나 화면 배포는 추가하지 않는다. **서비스 기동 복구**와 **실제 번역 처리 복구**를 별도로 판정한다.

## C. 시작 전에 확인하는 적용·복구 묶음

1. 실제 worker 권한·환경 변수·Python 3.13 릴리스·CLI 경로로, 운영 DB 사본과 격리 상태를 사용하는 사전 점검을 만든다. 기본 점검은 실제 모델 호출·운영 DB 쓰기·운영 서비스 제어 없이 끝나야 한다.
2. 코드/의존성/CLI 경로와 버전·필수 옵션·비공개 설정 구조·카탈로그·공용 장부·가드·단일 실행 소유권을 대조하고 준비/대기/차단 이유를 구분한다. 이 결과만으로 모델 판단이나 전체 기능을 PASS 처리하지 않는다.
3. quota 가드의 소스·실행 경로·해시와 빈 큐·대기·누락·손상 검사를 같은 후보에 묶는다. 구형 호출 차단과 기존 대기 작업의 보존·이후 재개 경로를 확인한다. 타이머 일정은 유지한다.
4. **되돌릴 대상도 실제로 기동 가능한지 검사한다.** 이전 코드가 현재 공용 CLI와 맞지 않으면 그 사실을 복구안에 드러내고, 검증된 서비스 전용 런타임 또는 호출을 차단한 안정된 상태 등 실행 가능한 복구 후보를 준비한다. 단순 파일 원복을 서비스 복구 완료로 쓰지 않는다.
5. 운영 상태가 준비 이후 달라지면 먼저 원인을 대조한다. 새 예약·결과가 없는 단계만 이전 릴리스·유닛·설정 복원을 사용한다. 새 호출 사실이 생기면 호출을 멈추고 현 DB·장부를 보존해 조정한다.

같은 버전·실행 경로 검사가 번역 설정, 호출기, worker 시작, 재시도, 배포 스크립트에 중복돼 있는지도 함께 대조한다. 같은 원인의 관련 누락은 이번 묶음에서 수정하되 다른 공급자나 제품 기능의 전면 개편으로 넓히지 않는다.

실제 모델이 필요한 근거와 모의 검증을 구별한다. 공용 장부 전환 전의 실제 Claude PR 검수 재호출은 하지 않고, 당시 가능한 독립 정적 검수와 CI를 명시한다. 기존 평가의 호출 24회·실제 실행 1800초·수정 2회 제한과 PR 검수기의 30분 종료·중복 호출 방지를 바꾸지 않는다. PR 검수기의 제거된 USD·턴 상한을 복원하지 않으며 번역의 기존 보호·예산을 이번 범위에서 임의 변경하지 않는다.

## E. 계정 확인과 실제 PM 평가까지 이어질 준비

- 비밀정보를 출력하지 않는 기존 공식 인증 확인 경로와 저장된 증거로 현재 계정 참조를 대조한다. 과거 로그인 계정이 같았다는 증거가 없으면 불확실성을 보존한다. 마스터 확인이 필요한 사실만 최종 입력 목록에 묶고, 비밀번호·토큰을 요청하지 않는다.
- E1–E6 고정 입력·제품 기준·정확한 설정·예산·원시 응답 보관·독립 내용 검수 양식을 준비한다. 호출하지 않는 준비 모드와 모의 실행을 끝낸다.
- 운영 연결·공용 장부 전환·대상 계정과 한도 조건이 충족되고 실제 평가 권한이 유효하면 기존 지시의 Astra 평가를 이어간다. Claude가 미확인인 동안 가능한 경로와 멈춰야 하는 경로를 구별하되 필수 독립 검수자를 임의 대체하지 않는다.

- 마스터의 APK 목표 입력·계획 확정은 대리 수행하지 않는다. 실제 사용 가능한 시점의 진입 위치·프로젝트·확인 기준을 준비하고, 미배포 화면을 현재 앱에서 찾으라고 안내하지 않는다.

## F. 제출 형태와 승인 경계

기존 PR #31의 수용·장애 기록을 보존하고 그 위에 **후속 초안 PR 하나**로 A~E의 실행 가능한 결과를 통합한다. 구현·검사와 적용 자료를 같은 후보에 고정한다. 새 제품 커밋·문서 HEAD·서버 릴리스 해시·CLI 경로/버전/호환 근거·설정 전환·가드·복구 후보를 구별해 적는다.

운영 승인에 관해서는 다음을 지킨다.

- 서버에 남아 있는 실제 마스터 승인 원문과 적용 대상을 확인한다. 이번 “한 번에 넓게 작업” 요청을 전역 CLI 변경·계정 차단 해제·임의 배포 권한으로 해석하지 않는다.
- **기존 승인 범위와 조건 안에 명확히 포함된 작업은 같은 승인을 다시 묻지 않는다.**
- 기존 승인이 a88a15b와 고정 파일로 제한됐다면 새 제품 후보나 서비스 전용 CLI의 실제 운영 배치는 별도 대상이다. 그 경우도 A~F의 가능한 준비를 전부 마친 뒤 **번역 복구·PR #31 재연결·후속 검증을 묶은 구체적 적용안 한 번**으로 확인한다. 버전 선택·개별 파일·개별 검사마다 확인을 요청하지 않는다.
- 실제 전환 전 차이가 발견되면 정해진 중단 조건을 적용한다. 승인되지 않은 새 범위로 우회하지 않는다.
