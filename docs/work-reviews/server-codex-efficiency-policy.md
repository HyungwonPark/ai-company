# 서버 Codex 개발 효율 공통 지침

작성: 2026-09-28 KST · Work PM · 사용자 요청 반영

## 적용 범위와 기본값

ai-company를 구축하는 **서버 Codex 개발 작업**에 적용한다. 제품 안의 Astra PM·최종 검수자·개발 역할 카탈로그를 변경하는 지시가 아니다. 실제 Claude 검수, 승인, 격리, 공용 장부와 복구 조건은 유지한다.

| 작업 | 기본 선택 | 운용 기준 |
| --- | --- | --- |
| 일반 구현·버그 수정·통합 | GPT-6 Sol / High | 서버 개발 기본값 |
| 명확한 문서·문구·단순 화면 수정 | Sol / Medium 또는 사용 가능한 Luna | 범위가 분명하고 영향이 작을 때 선택 |
| 동시성·권한·장부 정산·중단 복구의 어려운 경계 | Sol / Extra High | 해당 분석·검수 구간만 높이고 일반 작업은 High로 복귀 |
| PR 완료 전 독립 검수 | Claude Opus 5.5 / Ultracode | 기존 필수 검수 정책과 실제 적용 증거 유지 |

High는 이번 프로젝트의 개발 기본값이지 공급자 기본값이라는 뜻이 아니다. 상향할 때에는 해결할 불확실성을 한 줄로 남기고 이미 허용된 개발 범위 안에서 진행한다. 모델·effort 전환 수단이 없는 세션에서는 변경했다고 보고하지 말고 사용자가 선택할 정확한 값을 안내한다. 전역 설정이나 운영 worker의 모델을 임의로 바꾸지 않는다.

현재 대화에서 확인된 것은 서버가 Sol Extra High를 사용한다는 사용자 보고다. 이 지침 게시만으로 실행 중인 세션의 모델이 변경되지는 않는다. 절약 목적의 개발 세션은 지원되는 경우 Standard 속도를 기본으로 하고 Fast를 자동 선택하지 않는다.

## 한 번에 맡길 작업

**하나의 완료 목표를 조사 → 관련 결함 수정 → 통합 검사 → 지적 일괄 보완 → 최종 검수 → 문서·패키지까지 묶는다.**

**사용자의 2026-09-28 추가 지시에 따라, 한 번의 지시에서 처리하는 관련 범위를 조금 더 넓힌다.** 작은 수정마다 대화를 끝내고 다음 지시를 기다리는 대신, 같은 원인·완료 조건의 결함과 인접 경계 확인을 묶어 검토 가능한 결과까지 완료한다. Work PM의 지시 작성과 서버 Codex의 실행에 함께 적용한다.

- 시작할 때 목표·묶을 작업·완료 조건·승인 범위를 짧게 고정한다. 이미 허용된 같은 묶음의 조사·수정·검사·지적 보완·문서화·패키징은 단계별 착수 확인 없이 진행한다.
- 공통 범위의 지적을 모아 한 번에 수정하고 후보가 안정화된 뒤 최종 검사·문서·패키지를 만든다. 파일별·사소한 변경별로 전체 검수와 패키징을 반복하지 않는다.
- 이번 묶음의 예시는 **R36-4 수정 + 원본 보존·정산→수동 재개 통합 검사 + 관련 지적 보완 + 최종 CI + 새 패키지·적용/복구안**이다. 운영 설치·장부 변경·실제 재호출은 별도 허용 조건을 따른다.
- 새 범위나 승인되지 않은 운영 변경이 필요하면 기존 범위의 준비를 먼저 마치고, 검토 가능한 변경·영향·복구안을 모아 필요한 확인을 한 번 요청한다. 작업을 묶는 원칙이 승인 범위를 넓히지는 않는다.
- 한 번의 지시가 호출 한 번이나 일정 비율의 토큰 절약을 보장하지는 않는다. 효과는 사용량과 재작업 횟수로 확인한다.

- 공통 원인이나 완료 조건이 있는 작업은 하나의 후보에서 처리한다. 파일마다 별도 지시·전체 검수·패키지를 만들지 않는다.
- 서로 무관한 기능을 큰 PR 하나에 몰아넣지 않는다. 병렬 작업은 담당 파일·출력·통합 담당자를 나눈다.
- 승인된 범위의 구현·검사·수정·패키징을 단계별 착수 확인 없이 완료한다. 새로운 운영 변경은 구체적인 적용·복구안까지 준비하고 필요한 승인만 한 번 요청한다.
- 해결된 지적은 재현 조건이나 관련 코드가 바뀌지 않았다면 다시 전면 조사하지 않는다. 새 증거가 있을 때 해당 경계부터 확인한다.
- 현재 PR #36의 닫힌 R36-1~3을 이 절약 지침 때문에 다시 구현하지 않는다.

## 작업 특성에 따른 역할 선택

사용자와 합의한 [역할 선택·후속 구현 지침](adaptive-orchestration-policy-2026-09-28.md)을 적용한다. 작은 수정·순차 의존 변경은 개발 담당자 한 명이 끝까지 맡을 수 있어야 하고, 입출력·담당 경로·통합 방법이 분명한 독립 작업만 병렬로 나눈다. 역할 등록 수와 매 작업의 실제 호출 수를 구분하며, 개발 담당자 한 명이어도 기존 필수 독립 검수는 유지한다.

현재 제품 계약의 최소 2개 독립 역할 제약은 후속 PR에서 보완할 사항이다. 지침 게시만으로 제품이 단일 역할 계획을 지원한다고 보고하지 않는다. 현재 PR #35/#36의 고정 후보와 복구·승인·수동 호출 조건을 보존한다.

상태·종료·대기·중복·정산·CI처럼 규칙으로 확인할 수 있는 일에 별도 모델 역할이나 정기 호출을 추가하지 않는다. 같은 목표의 작업 범위는 묶되 인수인계에는 현재 목적·완료 조건·산출물·미해결 항목·증거 위치를 우선 전달한다. 기존 장부·체크포인트 기능을 다시 만들지 않는다.

## 문맥·도구·스킬

매번 전체 과거 보고를 읽거나 붙이지 않는다. 작업 시작 입력은 아래 정보로 충분히 구성하고, 판단에 필요한 원문만 추가로 읽는다.

1. 이번 목표와 완료 조건.
2. 작업 브랜치·기준 SHA·현재 변경.
3. 미해결 지적과 재현/검증 파일.
4. 승인된 작업과 확인이 필요한 변경.
5. 보존할 상태 및 다음 행동.
6. 관련 원문 링크.

공통 지침·현재 지시·관련 소스를 우선 읽고 역사 문서는 필요할 때 참조한다. 원문·로그·승인 근거는 삭제하지 않고 경로와 해시로 연결한다. 요약이 원문이나 실제 검수 대상 패치를 대체해서는 안 된다.

독립 조회를 묶고 검색은 필요한 경로와 범위부터 한다. 로그 전문을 매번 문맥에 넣지 말고 결과·실패 부분·원문 위치를 남긴다. 정상 검사 수백 줄을 반복 출력하지 않는다. 하위 에이전트에는 담당 질문과 필요한 자료를 주며 같은 저장소 전면 조사를 중복 배정하지 않는다. 해당 작업에 필요한 스킬만 적용하고 기존 필수 스킬 지침은 지킨다.

## 검사와 Claude 검수

- 개발 중에는 변경과 관련한 의미 있는 검사부터 실행한다. 최종 후보에는 저장소가 요구하는 전체 회귀·CI를 수행한다.
- 이미 통과한 검사 재실행은 코드/설정 변경, 구체적인 잔여 위험 또는 필수 gate가 있을 때 한다. 보안·정산·재개·중복 방지 검사를 절약 이유로 생략하지 않는다.
- 후보를 안정화한 뒤 [PR 완료 전 Claude 검수 공통 지침](pr-completion-review-policy.md)에 따라 실제 독립 검수를 받는다. 고정 HEAD·base·전체 패치와 검토 범위를 유지한다.
- 지적은 관련 범위 안에서 모아 수정하고 수정 후보를 재검수한다. 이전 PASS를 새 코드에 붙이지 않는다. 문서 게시 커밋과 실제 검수 코드 커밋도 구분한다.
- 같은 HEAD의 불필요한 중복 호출을 막는다. 정당한 수정 검수·중단 재개에는 기존 장부·계보·권한 조건을 적용한다.
- 현재 Claude PR 검수는 [수동 재개 지시](pr36-acceptance-manual-resume-bd16563-2026-09-28.md)를 따른다. 전용 자동 재개 timer는 활성화하지 않는다. 제품 자체의 자동 한도 대기·이관 목표는 보존한다.

## 결과와 사용량 확인

보고는 변경점·검증·남은 차단·다음 행동과 근거 링크 중심으로 작성한다. 기존 로그나 사용량 화면으로 확인할 수 있는 범위에서 작업 묶음별 모델/effort, 사용량, 재작업 여부를 비교한다. 공유 계정의 전체 한도 감소를 해당 작업의 사용량으로 단정하지 않는다. 실측이 없으면 절약률을 만들어 적지 않는다.

한 번의 지시로 묶는다고 호출이나 토큰 사용이 한 번으로 줄지는 않는다. 임의의 달러·턴 상한을 다시 도입하지 않으며, 기존 실행 시간·공용 장부·예산은 유지한다. 이번 범위에서 새 비용 대시보드·과금 체계·모델 라우터를 개발하지 않는다.

작업별 효율은 수용 여부·관측 사용량·시간·재검수·사용자 개입으로 비교한다. 목표 결정·정상 승인과 상태 오류·인수인계 누락 때문에 필요한 복구 개입을 구분한다. 미관측 사용량을 0으로 채우지 않고 실패·중단 비용도 보존한다. 비교 가능한 기준선이 없으면 이번 기록부터 기준선을 만든다.

## 서버 반영

현재 작업 브랜치의 AGENTS.md에 이 지침이 연결되어 있는지 확인하고, 없으면 **짧은 요약과 고정 문서 링크**를 다음 허용된 비운영 변경에 반영한다. 과거 운영 코드·고정 패키지를 문서 연결만을 위해 바꾸지 않는다. 지침 전문을 여러 파일에 복제하지 않는다.

이 정책은 사용자와 Work PM의 프로젝트 운영 선택이다. 공식 문서는 높은 추론량의 시간·토큰 증가, 작업에 따른 모델 선택, 문맥과 도구 결과의 사용량 영향을 설명한다. 절약 효과의 수치는 아직 측정하지 않았다.
