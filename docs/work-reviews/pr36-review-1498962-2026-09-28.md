## R36-4 · 사후 정산과 원본 interpretation의 비교 충돌

위치: `scripts/review_pr_with_claude.py`의 `effective_receipt`와 `quota_resume_verified`(특히 589~592행).

현재 형식의 미정산 시도는 원본 `receipt.json`과 `interpretation.json`의 정산 이벤트가 모두 `null`이다. 저장 증거로 정산한 뒤 `reconciliation.json`을 추가하면 `effective_receipt`는 새 정산 이벤트를 반환한다. 그러나 재개 검사는 이를 변경하지 않아야 하는 원본 `interpretation.json`의 `null`과 직접 비교해 `False`로 끝난다. 이벤트·체크포인트 해시가 있는 이번 형식에서 발생하며, 해당 해시가 없는 과거 가져오기 경로의 성공 검사는 이 문제를 잡지 못한다.

이는 이번 커밋에서 새로 만든 분기라는 뜻은 아니다. 이번 서버 보고의 **UNKNOWN → 증거 기반 정산 → 원본 보존 → 수동 재개** 경로를 완료하기 위해 필요한 기존 결함 보완이다. 비공개 실제 장부에서 재현했다고 주장하지 않는다.

재현: [합성 기록·임시 장부 진단](repros/pr36-reconciliation-resume-1498962.py). 실제 실행기 함수와 공용 장부로 다음을 확인했다.

```text
previous_checkpoint_preserves_legacy: True
input_delivery_verified: True
terminal_children_stopped: True
reservation: SETTLED
account: COOLDOWN
quota_resume_verified: False
tick_inspect: NEEDS_RECONCILIATION
original_records_unchanged: True
```

원인 분리용으로 **임시 합성** interpretation의 정산 이벤트만 새 값으로 바꾸면 True/READY로 바뀐다. 이는 운영 복구 방법이 아니며 원본 수정은 금지한다. 기존 사후 정산 검사는 receipt의 events/checkpoint 해시를 지운 과거 형식을 사용해 이 비교 분기를 통과하지 않는다. 외부 모델 호출·운영 쓰기는 없다.

## 서버 일괄 작업 지시

1. 기존 PR #36에서 R36-4만 최소 수정한다. 원본 receipt·interpretation·checkpoint·이벤트와 이전 PASS/실패 판정은 그대로 둔다. 원본끼리의 연결 검증과 별도 사후 정산 증거·실제 장부의 연결 검증을 구분한다. 비교를 무조건 생략하거나 원본 정산 이벤트를 덮어쓰지 않는다.
2. 현재 형식의 UNKNOWN 시도 생성 → 증거 기반 한 번 정산 → reconciliation 추가 → 변경 없는 원본/구버전 체크포인트 재생 → 수동 재개 허용 조건 확인을 **실제 runner·tick·임시 장부를 연결한 모의 검사**로 완료한다. 모델 실행부만 모의 처리하고, 정상 재개 시 한 번의 새 예약, 재정산 시 중복 비용 없음, 원본 해시 보존을 확인한다.
3. reconciliation의 출처 해시·예약·이벤트·reset 불일치, 미정산/UNKNOWN 잔존, 다른 제한·더 늦은 대기, 원본 interpretation/체크포인트 불일치에서는 재개되지 않아야 한다. 이번 합성 실패를 먼저 재현하고 수정 후 통과 및 관련 회귀를 남긴다.
4. 좁은 독립 검수·최종 후보 필수 CI 후 **신뢰 코드 4파일의 새 설치 패키지, 전체/파일별 SHA-256, 변경 전후 해시, 고정 대상/예약을 담은 비공개 manifest, 적용·복구안**까지 한 묶음으로 준비한다. `1498962`용 패키지는 제출 시점에도 미고정이고, 이전 `bd16563` 패키지는 이번 수정의 설치 후보가 아니다.
5. 서버에만 있는 이번 원문을 읽기 전용으로 재생하고, 현재 장부의 복제본에서 위 정산·재개 조건을 확인한다. 비공개 증거는 원문 경로와 해시로 연결한다. 잠정 지적 6개는 다음 검수 인수인계 자료로 보존하되 완료 범위·최종 판정으로 승격하지 않는다.

[개발 효율 공통 지침](server-codex-efficiency-policy.md)을 적용한다. 기본 Sol High, 어려운 정산/복구 경계에서만 필요할 때 추론을 높인다. 닫힌 R36-1~3 재구현, 무관한 기능·전체 과거 기록의 반복 조사, 단계마다 별도 패키징은 하지 않는다.
