## F1. 자유 목표에서 예시 체험으로 전환되지 않음 — P2

위치: [preview.js 159~165행](https://github.com/HyungwonPark/ai-company/blob/fd1850870038b1162051d5ce644b8e1a78a68628/docs/previews/task-workspace/preview.js#L159), 특히 `if ($('#new-form'))` 분기입니다.

재현 순서:

1. 새 프로젝트에서 이름과 자유 목표를 직접 입력합니다.
2. **PM과 시작**을 눌러 목표 보관 화면으로 갑니다.
3. 새로고침하지 않고 **로그인 예시로 체험**을 누릅니다.
4. 화면이 예시 계획으로 전환되지 않습니다. 새로고침한 뒤 같은 버튼을 누르면 전환됩니다.

원인: 새 프로젝트 대화상자를 닫아도 내부 `#new-form`은 DOM에 남습니다. 화면 밖에 남은 폼의 존재만 검사하므로 숨은 입력과 `draft`를 변경하고 조기 반환합니다. 생성된 프로젝트의 `created.goal`·`created.example`은 바뀌지 않습니다.

실제 소스의 Node VM 재현 요약:

```json
{
  "dialogOpen": false,
  "draftExampleAfterClick": true,
  "createdExampleAfterClick": false,
  "createdGoalChanged": false,
  "worksAfterReload": true
}
```

이는 최소 DOM 대역에서의 코드·상태 재현입니다. 브라우저 포인터 조작 결과로 보고하지 않습니다.

수정 방향: 현재 열린 새 프로젝트 입력에서의 선택과, 이미 생성된 프로젝트의 예시 전환을 구별하십시오. 닫힌 폼의 존재를 현재 조작 맥락으로 사용하지 마세요. 자유 목표의 원문 보존 정책은 유지합니다.

수용 기준:

- 위 순서가 새로고침 없이 작동하고 계획 화면·생성된 프로젝트·저장된 상태가 같은 목표를 가리킵니다.
- 전환 후 새로고침해도 선택이 유지되고, 사용자의 명시적 계획 확정 전에는 실행이 0건입니다.
- 두 배치에서 실제 브라우저로 확인합니다. 새 프로젝트 대화상자 내부의 기존 예시 선택도 유지합니다.

기존 [자유 목표 검사](https://github.com/HyungwonPark/ai-company/blob/fd1850870038b1162051d5ce644b8e1a78a68628/tests/ui/task_workspace_review.cjs#L59)는 임의 목표가 자동으로 로그인 계획으로 바뀌지 않는지만 확인합니다. 그 직후 사용자가 명시적으로 예시 전환 버튼을 누르는 경로를 추가해야 합니다.

## F2. 검수 중 결과 화면이 이전 개발 단계를 보고함 — P2

위치: [preview.js의 result() 121~124행](https://github.com/HyungwonPark/ai-company/blob/fd1850870038b1162051d5ce644b8e1a78a68628/docs/previews/task-workspace/preview.js#L121). 업무 상태를 만드는 [tasks() 44~54행](https://github.com/HyungwonPark/ai-company/blob/fd1850870038b1162051d5ce644b8e1a78a68628/docs/previews/task-workspace/preview.js#L44)과 결과 집계의 분기가 서로 다릅니다.

재현 순서:

1. 새 프로젝트에서 로그인 예시 목표를 선택하고 계획을 직접 확정합니다.
2. **한도 대기 재생 → 담당 이관 재생 → 결과 전달 재생**을 누릅니다.
3. 진행 화면과 결과 화면을 비교합니다.

이때 `flow.playback === 'checks'`이며, 진행 화면의 두 선행 업무는 완료이고 통합 업무는 검수 중입니다. 하지만 결과는 다음과 같이 표시합니다.

| 항목 | 현재 결과 화면 | 같은 단계에 맞는 안내 방향 |
| --- | --- | --- |
| 완료 | 계획 확정 · 역할별 업무 배정 | 화면 개발·검사 작성 완료, 결과 전달 |
| 남은 일 | 개발·검사 결과 수집과 같은 후보 검수 | 같은 후보의 검사·독립 검수·최종 검수 |
| 차단 | 개발 이관 후 진행 중 | 해당 정상 예시에서는 차단 없음 |

Node VM에서 실제 `tasks()`와 `result()` 반환값으로 확인했습니다. 레이아웃이나 실기기 표시를 검증한 것은 아닙니다.

수정 방향: `parallel / waiting / handoff / checks / review` 단계에서 진행·결과·다음 행동이 같은 상태를 설명하게 만드십시오. 단계만 정상으로 맞추기 위해 실제 대기·실패 시나리오를 무조건 “차단 없음”으로 바꾸지는 마세요.

수용 기준:

- 정상 `checks`에서 선행 업무 완료와 통합 검수 중 상태를 같은 프로젝트·실행으로 보고합니다.
- 각 단계의 완료·남은 일·차단·다음 행동을 비교합니다.
- 대기·실패·이전 실행·결정 후의 기존 분리와 pending 보존을 유지합니다.
