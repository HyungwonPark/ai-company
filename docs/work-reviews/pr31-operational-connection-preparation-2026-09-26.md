추가 운영 경계가 확인됐다. 기존 quota 타이머는 계속 켜져 있지만, 연결 대상인 구형 session worker는 공용 장부를 사용하지 않는다. 이 경로를 둔 채 운영 연결을 완료했다고 표시할 수 없다. 타이머 일정은 유지하고 구형 모델 호출만 차단하는 작은 `quota.service` 가드를 준비했다. 격리 사본에서 빈 큐·대기 작업·누락·손상 상태를 검사했고, 이상 상태에서는 모델을 호출하지 않는다. 이 서비스 변경과 전환 중 타이머의 짧은 일시 정지·재개는 원래 제안된 **두 worker 유닛 범위에 추가**되므로 별도 승인 범위에 명시한다.

과거 Claude PR 검수 기록에는 당시 계정 참조가 저장되지 않았다. 현재 번역 실행기와 검수 실행기는 같은 사용자 인증 디렉터리를 사용하지만, 과거 로그인 계정이 한 번도 달라지지 않았다는 직접 증거는 없다. 운영 초기화 입력에서는 이 그룹을 미확인 상태로 잠가 두었다. 계정 귀속을 검토해 확정하거나 미확인 상태의 호출 차단을 수용하기 전에는 Claude 검수·번역·대체 호출을 시작하지 않는다.

## 적용·복구 경계

운영 승인 뒤에도 적용 직전 유닛·설정·카탈로그·설치본 해시와 살아 있는 호출을 새로 대조한다. 다르면 교체를 중단하고 새 후보를 고정한다. DB는 일관된 비공개 사본을 남기되 과거 백업으로 덮어쓰지 않는다. 관련 호출을 정상 종료한 뒤 구형 타이머 경로 차단, 새 장부 초기화, 릴리스·두 worker 유닛·비공개 설정·신뢰 검수기 교체 순서로 적용한다. 서비스 단일 실행·인증·기존 기록·카탈로그·타이머·웹과 커플 서비스 상태를 확인한다.

새 장부에 예약이나 결과가 **없을 때만** 이전 릴리스·유닛·설정으로 되돌릴 수 있다. 새 호출 사실이 생긴 뒤에는 새 실행을 멈추고 DB·장부·증거를 보존하여 조정한다. 구형 worker를 무조건 다시 켜거나 DB를 과거로 복원하지 않는다.

현재 상태는 **비운영 준비 완료, 운영 승인 및 계정 귀속 판단 대기**다. PR #31은 초안이며 병합하지 않았다. 실제 Astra 평가, Claude 최종 PR 검수 재호출, 마스터 직접 조작, 운영 적용은 수행하지 않았다. 기존 웹·커플 서비스·기록·타이머와 PR #10의 `pending`을 유지한다.
