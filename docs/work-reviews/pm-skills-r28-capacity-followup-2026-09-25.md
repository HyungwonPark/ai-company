## 최초 실패와 수정

`6e8d8a3`에서 새 회귀 검사를 먼저 실행했다. 승인 지침 3개가 있는 역할에 공개 후보가 추가될 때 `build_selection`의 최대 3개 검사가 실패했고, 예외 복구가 다른 역할의 정상 후보도 지웠다. 승인 지침 2개에 후보 2개를 제안하면 한 후보가 탈락한 이유도 남지 않았다. 반면 승인 지침 0개·2개에 후보 1개를 추가하는 기본 경로는 최초 검사에서도 통과했다.

제품·검사 커밋 `f48848b7de46fb2d266981dedec603976e05cd5e`는 후보를 역할별 상한 검사 **전에** 걸러낸다. 승인된 3개는 그대로 유지하고, 추가하지 못한 후보 ID와 부족 역량을 해당 역할의 이유로 저장한다. 2개에서 한 자리만 남아 있으면 첫 공개 후보만 추가하고 다음 후보의 제외 이유를 남긴다. 다른 역할의 정상 추천과 역할별 상태는 유지한다. 필수 지침이 부족한 역할은 여전히 실행할 수 없다. 실제 조회 오류로 후보가 제거되는 별도 경계에서는 목록과 상태를 함께 갱신한다.

| 회귀 경계 | 수정 후 결과 |
| --- | --- |
| 승인 지침 0개 | 맞는 공개 후보 1개를 `검토 전`으로 표시 |
| 승인 지침 2개·공개 후보 2개 | 기존 2개와 후보 1개만 유지, 나머지 후보와 이유 기록 |
| 승인 지침 3개·필수 역량 부족 | 기존 3개 유지, 공개 후보 제외·이유 표시, 실행 차단 유지 |
| 0·2·3개 역할과 빈 역할 혼합 | 다른 역할의 후보 보존, 상한 역할만 `limit_reached`, 전체를 조회 실패로 표시하지 않음 |
| 잘못된 공개 후보 자료 | 실제 실패로 제거한 후보 목록과 `lookup_failed` 상태·이유 일치 |

관련 Python 검사는 `tests/test_skill_automation.py`, 화면 계약 검사는 `tests/ui/pm_skills_ui_checks.mjs`에 있다. 기존 v2 확정 실행의 재시작 복구와 R27-1, R28-1~5 회귀를 포함한 로컬 전체 Python 검사는 **529개 통과, 3개 건너뜀**이다. Node 역할 지침·매니저 계약 검사가 통과했다. 독립 검수에서는 최초 보완안의 실제 조회 오류 상태와 빈 역할의 혼합 상태 표시가 어긋나는 경계를 추가로 찾아 수정했고, 다시 검수했을 때 차단 결함을 찾지 못했다.

## 적용·복구안 — 승인 요청 아님

향후 적용 대상은 같은 후보의 **웹 1개와 PM·조정기 worker 1개**다. 새 DB 테이블이나 기존 계획·승인·실행 기록의 재작성은 필요 없다. 배포 직전 운영 커밋·이미지·대기 요청·예산·기존 기록을 비공개로 대조하고, DB 온라인 백업과 이전 두 이미지를 보관한다. 새 배정을 멈춘 뒤 두 서비스를 함께 교체하여 승인 지침 3개·혼합 역할 표시, 기존 실행 복구, 로그인, 단일 worker, 기록 보존을 확인한다. 필수 검사 실패 시 새 계약의 요청이 생기기 전에는 이전 웹·worker 이미지를 함께 복원한다. 새 기록이 생겼다면 새 실행만 중단하고 관리·보고 화면과 DB·큐를 보존한 채 호환 수정한다. DB와 운영 기록을 과거 백업으로 덮어쓰지 않는다.
