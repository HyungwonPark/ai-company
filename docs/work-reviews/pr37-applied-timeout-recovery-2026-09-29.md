정산·계정 해제·동일 후보의 후속 검수는 각각 별도 조건이다. 종료 증거를 확보하더라도 일반 timeout의 계정 복구와 후속 시도가 자동 허용되지는 않는다. 기존 수동 요청에 포함된 증거 기반 정산 승인은 유지하되, 새로운 복구 정책과 실제 재호출을 이번 설치 승인에서 끌어내지 않는다.

## 서버에 권고하는 다음 작업 묶음

목표는 **종료 증거가 유실된 timeout을 다룰 수 있는 복구 절차를 비운영 후보로 준비하는 것**이다. 원본 보존·상태별 복구 가능성·필요한 정책 결정과 구현 변경을 한 번에 검토할 수 있게 한다. 지금 단계에서 다시 설치 승인이나 모델 호출 승인을 요청하지 않는다.

1. 기존 인계의 확보/미확보 증거를 그대로 입력으로 삼고, 정상 완료 증거와 현재 실행이 더 이상 계속될 수 없다는 종료·차단 증거를 구분한다. 현 CLI/Workflow에서 지원되는 제어·기록과 로컬/원격 하위 작업 범위를 확인하되, 모델 시험 호출이나 실제 취소·계정 변경은 하지 않는다. 지원하지 않는 제어 명령·보장된 종료 효과를 추정해서 쓰지 않는다.
2. 실행 종료 확인, 비용 정산, 계정 제한 해소, 같은 HEAD의 후속 시도 허용을 분리한 최소 상태 전이와 필요한 증거를 설계한다. 현재 실행의 종료를 끝내 입증할 수 없는 경우 유지할 상태를 명시한다. 관리상 포기·격리 같은 새로운 정책이 필요하다면 기술적 종료 사실과 구별하고, 잔여 실행·비용·용량·중복 위험 및 필요한 별도 판단을 설명한다. 이번 문서가 그러한 예외를 허용하는 것은 아니다.
3. 구현 가능한 부분은 별도 비운영 초안에 최소 변경·모의 검사·적용/복구안까지 묶는다. 종료 미확정 거부, 종료 확인/비용 미확정, 중복 정산·동시 재개, 잘못된 예약/HEAD/패치/선행 시도 연결을 검사한다. 원본과 이미 확정한 정산을 덮어쓰지 않으며, 나중에 사용량이 확보될 때 중복 누적 없이 보완할 방식을 명시한다. 지원 불가능하거나 정책 판단이 필요한 경로는 구현 완료로 포장하지 않는다.
4. 제출은 현재 기록으로 가능한 처리, 불가능한 처리와 이유, 새로 필요한 증거/정책 결정, 후보 변경과 검사, 운영 적용·복구 범위로 정리한다. 새로운 종료 증거가 없으면 현재 실행을 복구 완료로 표시하지 않는다. 구현만으로 과거 누락된 종료 사실을 복원할 수 없음을 명시한다.

이 작업 묶음은 비운영 설계·구현 후보 준비 지시다. 운영 설치·장부 수정·계정 해제·실제 취소·tick·추가 모델·새 예약을 포함하지 않는다. 신뢰 설치나 예외 정책이 필요하면 정확한 대상·영향·복구안이 준비된 뒤 그 변경 부분만 한 번에 판단한다. 기존 승인 범위 안의 읽기·구현·검사·문서화는 단계별 재승인을 받지 않는다.

필수 실제 Claude 검수는 계속 대기 상태로 기록한다. 개발 세션을 초기화해 UNKNOWN이나 중복 방지를 해소하려 하지 않으며, 현재 개발 대화와 서버 인계를 유지한다. 향후 단일 역할·조건부 병렬화 제품 개선은 별도 후속 목표로 보존한다.
