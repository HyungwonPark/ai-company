## 다음 묶음 — 검수 준비부터 가능한 실제 검수까지

### A. 두 차단의 읽기 전용 대조

- Claude UNKNOWN의 실제 사유를 확인합니다. 계정 귀속 미확인, 미종결/미정산 호출, 남은 공급자 제한을 구분하고 등록 참조·그룹·기존 검수 기록의 연결을 대조합니다. 로그인 성공만으로 모든 UNKNOWN을 해제하지 않습니다.
- 설치된 `runner.py`·`claude_control.py`·`shared_calls.py`와 전환 기록의 예상 해시·원래 승인 커밋·현재 파일의 출처·변경 시점을 대조합니다. 일치/불일치와 확인 불가 항목을 구분합니다.
- 사용자 확인이 실제로 필요한 계정 정보가 있다면 먼저 확인 가능한 자료를 정리한 뒤, 비밀값을 요구하지 않는 최소한의 확인 항목만 구체적으로 제시합니다. 인증 파일·토큰·전체 환경변수는 게시하지 않습니다.
- Claude 계정 문제와 과거 Codex E2의 불확실 실행을 별도로 추적합니다. 한쪽 확인으로 다른 쪽 예약이나 계정까지 해제하지 않습니다. 기존 공유 계정·호스트 용량은 그대로 대조합니다.

### B. 신뢰 검수기 복구 또는 갱신안 준비

- 확인된 출처를 바탕으로 이전 승인된 파일 세트를 복구할지, 새로 검토한 세트를 배치할지 선택하고 이유를 기록합니다. 무조건 최신 파일을 복사하지 않습니다.
- 저장소 밖 별도 후보 경로에 파일 세트와 해시를 고정하고 실제 장부 형식·호출자 연결·중복 예약·종료·정산 검사를 운영 사본 또는 합성 자료로 검증합니다. 운영 장부는 수정하지 않습니다.
- 전환 기록의 해시만 현재 파일에 맞춰 바꾸거나 일치 검사를 끄지 않습니다. 새 전환 기록이 필요하면 실제 설치·연결 검증을 근거로 만들고 기존 기록을 보존합니다. 후보 코드가 자신의 신뢰 설치본을 자동 교체하게 하지 않습니다.
- 변경할 파일·등록 계정 상태·전환 기록, 적용 전 확인값, 실패 시 파일 복구와 현재 장부 보존을 한 적용안으로 고정합니다. worker·웹·전역 CLI 변경이 불필요하면 범위에 넣지 않습니다.

### C. 기존 승인 대조 후 실제 Claude 검수

PR 검수 호출 자체는 이미 허용된 공통 절차입니다. 현재 계정·장부·설치 상태가 허용 조건을 충족하면 새 착수 승인을 반복하지 않고 검수합니다. 반면 계정 상태 쓰기·신뢰 설치본 교체·전환 기록 갱신이 기존 승인을 벗어나면 B의 구체적인 변경만 묶어 한 번 확인합니다. 준비 전 막연한 전체 운영 승인을 묻지 않습니다.

실제 호출 전 최종 HEAD·base·전체 패치·CI와 과거 시도의 종료·정산·중복 조건을 다시 고정합니다. 사용자 요청대로 `claude-opus-5-5`·`ultracode`의 실제 적용 근거와 검토 범위·판정을 확인합니다. REVISE이면 해당 지적 수정·CI·새 후보 검수를 같은 범위에서 이어갑니다. Workflow 호출 여부와 결과 반영은 별도로 기록합니다.

호출 조건을 충족하지 못하면 **Claude 검수 대기**와 정확한 차단 사유·재개 조건으로 제출합니다. 다른 계정·새 trial·빈 커밋으로 우회하거나 정적 검수로 PASS를 대신하지 않습니다. 검수기 복구를 이유로 제품 기능이나 시간 제한을 확대하지 않습니다.
