## 조사·추천 결과의 의미

- 로컬에서 승인된 문서 지침이 필요한 역량을 충족하면 먼저 재사용한다. 필요한 역량이 없으면 스킬 0개가 정상이다.
- 공개 검색은 서버가 허용한 일반 기술어만 GitHub 공개 저장소 메타데이터에 전달한다. 개인 목표 전문·코드·비밀정보는 검색어로 받지 않는다. 저장소 검색 결과는 스킬 후보가 아니며 고정 커밋의 실제 `SKILL.md`·참조·라이선스 파일을 별도로 확인한다.
- 외부 후보는 프로젝트 전체 최대 6개, 역할별 추천은 최대 3개다. `no_additional_skill`, `not_found`, `lookup_failed`, `review_pending`, `approved_document`를 구분한다. 공개 조회의 요청 수·경과 시간·확인 시각을 반환해 상위 작업의 영속 예산과 캐시에 연결한다. 호출자에게 누적 제한 검사를 맡기는 경계는 함수 호출 전에 유지해야 한다.
- 공식 문서는 `agentskills.io`, `docs.github.com`, Anthropic·OpenAI 공식 호스트만 HTTPS로 크기와 시간을 제한해 읽는다. 조회한 문서는 출처·해시를 남겨도 승인된 스킬이 되지 않는다.
- 로컬 문서 지침은 독립적으로 고정한 묶음 해시가 맞고, 라이선스·제공자·실행기·의존성 판단이 끝난 경우에만 `approved_document`가 된다. 전달 직전에 모든 파일을 다시 읽어 해시를 대조한다. 바뀐 내용, 링크 경유 파일, 비문서 참조, 도구 의존성은 자동 전달하지 않는다.

## 검증 범위

`uv run --frozen python -m unittest tests.test_skill_catalog -v`는 고정 해시 재검사, 파일 변경·심볼릭 링크·호환성 거부, 미고정·내부 URL 거부, 공개 조회 실패와 검색 결과 없음의 구분, 설치 스킬 우선순위와 0개 추천을 검사한다. 공개 조회 기록은 실제 GitHub 원문을 읽은 결과다. 단위 검사에서는 네트워크를 모의한다. 실제 PM의 추천 판단, 역할별 전달, 모델의 지침 준수, Work PM 수용과 운영 적용은 아직 검증되지 않았다.

후속 통합용 `skill_selection.py`는 서버 소유 설정의 설치 경로·기대 묶음 해시를 다시 검사해 신뢰 카탈로그를 만든다. 선택 자료에는 역할당 최대 3개 항목, 출처·버전·파일 해시·선택 여부·요구사항 링크와 전체 digest를 고정한다. 공개 후보는 화면에 추천할 수 있지만 검토·호환성·문서 전달 조건을 통과하기 전에는 선택할 수 없다. 전달 직전에는 선택 digest와 서버 카탈로그의 고정 항목을 대조하고 해당 역할의 승인 문서만 다시 읽는다. 이 단계가 반환하는 것은 **전달 준비 자료**이며 모델 프로세스가 실제로 받았거나 지침을 따랐다는 영수증이 아니다.

`SkillResearchStore`는 별도 SQLite에 조사 정책·누적 검색/파일 조회/예약 바이트/시간과 조회별 결과를 보존한다. 네트워크 전에 예산을 예약하고, 같은 조회 ID는 저장된 결과를 재사용한다. 중단으로 결과가 저장되지 않은 조회는 `lookup_pending`으로 보고해 임의 중복 호출을 피한다. 검색·조회·시간 상한은 기존 더 작은 프로젝트 예산을 넓히는 근거가 아니며, 상위 조정기가 이 저장소를 같은 프로젝트의 영속 상태와 연결해야 한다. 모델 호출·토큰·비용 상한 값도 조사 정책에 기록되지만 이 모듈은 모델을 호출하지 않으며, 실제 모델 사용량은 기존 공유 계정·프로젝트 예산 장부가 담당한다. 별도 작업 ID를 만들어 그 장부를 초기화하면 안 된다. `tests.test_skill_selection`은 재시작 캐시·중단 후 중복 방지·예산·역할별 해시 대조를 검사한다.
