# PR #36 수동 재개 준비 결과와 한정 적용 범위

작성: 2026-09-28 KST · Work PM

## 판단과 확인 범위

서버가 준비한 **모델 호출 없는 설치·기존 호출 정산 묶음**을 한정 승인할 것을 권고한다. 이 문서는 마스터의 운영 승인을 대신하지 않는다. 사용자의 이번 “지침에 명세” 요청은 개발 효율 지침의 게시로 반영했고, 아래 운영 쓰기의 승인으로 확대하지 않았다.

GitHub에서 PR #36 HEAD가 수용한 `bd165633608db8d682e301eede86b6de640976ac` 그대로임을 다시 확인했다. 패키지는 기존 검수에서 확인한 SHA-256 `e51cc1a05614be952620aaf2b3f40b6b9181cf7cf4b57aa8c2a1722be3946c8d`를 기준으로 한다. R36-1~3 비운영 수용은 유지한다.

비공개 RUNBOOK·manifest·운영 장부·현재 공급자 제한은 이번 Work 검토에서 직접 읽지 못했다. 저장된 API 429 종료·자식 종료·누적 사용량, 복제 검사, 전용 timer 미설치와 현 UNKNOWN은 사용자가 전달한 서버 보고다. 복제 검사에서 READY가 됐다는 사실은 실제 계정 한도 회복이나 Claude 최종 검수 완료의 증거가 아니다.

## 권고하는 승인 묶음 — 모델 호출 없음

1. 위 패키지에 고정된 신뢰 검수기 코드 **4파일**만 설치한다. 현재 파일 및 교체 파일의 경로·해시를 비공개 명세와 대조한다.
2. **그 설치에 대응하는 전환 기록의 파일 해시만** 갱신한다. 불일치 파일을 그대로 신뢰하도록 맞추는 작업이 아니며, 계정·정책·다른 설치본의 신뢰 범위를 넓히지 않는다.
3. PR #35의 이번 미정산 예약 **한 건**을 저장된 종료·자식 종료·누적 사용량 증거로 한 번만 정산한다. 예약 ID와 연결 계정은 비공개 명세의 정확한 값을 사용한다.
4. **그 예약에 연결된 Claude 계정만** 근거 있는 COOLDOWN으로 조정한다. 다른 UNKNOWN 사건이나 더 늦은 대기 시각·새 차단 사유는 지우지 않는다. 시간 경과만으로 READY를 강제하지 않는다.
5. 설치·정산 결과와 현재 대기를 무호출 방식으로 확인한다. 상태 변경이 기존 자동 실행 경로를 통해 검수를 호출하지 않는지도 적용 전 확인한다.

대상·설치 해시·미정산 건·세션 상태가 명세와 다르면 쓰기 전에 중단해 차이를 보고한다. 승인된 범위 안의 파일 복구는 준비한 절차를 사용하되 현 장부를 과거 DB로 덮어쓰지 않는다. 정산 후에는 재실행하더라도 같은 사용량을 중복 정산하지 않는다.

## 나중의 수동 호출

준비 승인이 있어도 tick 명령을 실행하지 않는다. 해당 명령은 READY에서 실제 모델을 호출하는 **실행 명령**이며 읽기 전용 점검이 아니다.

서버 보고의 `2026-09-28 02:00 KST`는 가장 이른 재점검 시각이다. 설치·기존 호출 정산·고정 대상·중복 방지·현재 확인 가능한 제한 정보를 대조하고 **사용자가 별도로 재개를 요청한 뒤** 새 검수 시도 한 건을 실행한다. 제한 회복을 시험한다며 별도 모델 호출을 추가하지 않는다. 실제 호출이 다시 제한되면 원문·사용량·진행·남은 범위를 보존하고 종료한다.

PR #35 대상 `1d54d3a0ea5a21c7c2dc588f824c6567231829b4`와 base·전체 패치·예약 계보를 기존 manifest로 고정한다. 과거 작업의 체크포인트를 이어받는 새 시도이며, 동일 Claude CLI 세션이 살아 돌아온다고 설명하지 않는다. 최종 보고가 없는 13파일의 검수 범위를 임의로 완료 처리하지 않는다.

## 보존과 다음 제출

검수 전용 자동 재개 timer는 설치·활성화하지 않는다. 기존 quota timer, 두 worker inactive/disabled, E1 PASS, 과거 Codex E2 hold_unknown, 기존 Claude 세션·웹·커플 서비스·장부·PR #10 pending을 보존한다. 병합·배포 범위를 추가하지 않는다.

승인 후 준비가 끝나면 **설치/전환 해시, 해당 예약의 한 번 정산, 해당 계정의 대기, 새 모델 호출 0건**만 간결하게 보고하고 수동 요청을 기다린다. 현재 Claude Opus 5.5·Ultracode 최종 검수는 미완료다. 제품 개발 효율은 [공통 지침](server-codex-efficiency-policy.md)을 함께 적용한다.
