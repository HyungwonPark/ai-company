# 작업실 사용자 비교 기록

작성일: 2026-09-24 KST · 상태: 상세 관찰 미기록 / 마스터 기본 방향: 순서형

마스터가 전달한 비교 안내를 바탕으로 새로 작성한 양식입니다. 서버 내부의 기존 양식을 읽거나 복제한 문서는 아닙니다. 마스터는 이후 순서형이 더 나아 보인다는 의견을 주셨습니다. [기본 방향 선택과 다음 작업](journey-layout-decision-2026-09-24.md)에 기록했으며, 아래 상세 관찰란은 아직 채우지 않았습니다. 이 양식 작성은 다음 계획의 선행 조건이 아닙니다.

## 시작 전에

- 비교 날짜: __________
- 기기·브라우저: __________
- 사용한 테마: Light / Black
- 이 시안을 전에 사용했나요? 처음 / 사용한 적 있음
- 실제로 비교한 순서: __________ → __________

처음 비교하는 경우 **한눈형 → 순서형**으로 진행합니다. 이미 시안을 사용했다면 그 사실을 기록하고, 처음 보는 사용자였다고 처리하지 않습니다.

## 진행 방법

1. **한눈형**을 선택하고 **모바일 로그인 정리**를 엽니다. 이전 조작이 남았다면 먼저 비교 메뉴에서 예시를 초기화한 뒤 한눈형과 사용할 테마를 다시 선택합니다.
2. 아래 세 과제를 해 보고 첫 번째 칸에 자신의 말로 적습니다. 모르면 “모르겠음”이라고 적어도 됩니다.
3. 메모는 이 대화나 별도 문서에 보관합니다. **비교 → 예시 초기화**는 해당 시안 탭의 입력·계획·실행·예시 결정을 지웁니다.
4. **순서형**과 처음 사용한 **동일 테마**를 선택합니다. 초기화하면 테마도 기본값으로 돌아가므로 Black을 썼다면 다시 선택합니다. 같은 기기·창 크기에서 같은 프로젝트와 과제를 반복합니다.
5. 두 번째 결과와 마지막 선호를 적습니다. 두 번째 배치가 익숙해진 덕분에 쉬웠다면 함께 기록합니다.

전체 체험용 새 프로젝트를 만들 필요는 없습니다. 이번 비교는 기본 샘플의 진행·대기·승인 탐색에 한정합니다.

| 무엇이 진행 중이고 무엇이 기다리나요? | __________ | __________ |

관찰자가 있다면 버튼 위치나 정답을 먼저 알려 주지 않습니다. 도움을 줬다면 내용과 위치를 적습니다. 한눈형·순서형의 기능이 정상이라는 기존 검사 결과를 사용자의 이해도 답변에 대신 넣지 않습니다.

## 비교 결과

- 더 편한 쪽: 한눈형 / 순서형 / 차이 없음 / 둘 다 어려움 / 아직 판단 어려움
- 그렇게 느낀 이유: __________
- 먼저 고쳤으면 하는 부분 한 가지: __________
- 두 번째 배치가 익숙해져서 쉬워진 영향: 있음 / 없음 / 모르겠음
- 기본 배치에 대한 마스터의 선택: **순서형** — [결정 기록](journey-layout-decision-2026-09-24.md)

기본 방향은 마스터의 위 답변으로 기록했습니다. 전달받지 않은 선택 이유나 과제별 결과는 만들지 않습니다. 한 사람의 평가나 마스터의 익숙한 사용 경험을 모든 초보 사용자의 검증 결과로 일반화하지 않습니다. 초보 사용자 관찰이 없으면 미실시 상태를 유지합니다.

## 짧게 답변하는 양식

```text
기기 / 테마:
한눈형 — 이해한 내용 / 헷갈린 곳:
순서형 — 이해한 내용 / 헷갈린 곳:
더 편한 쪽과 이유:
먼저 고쳤으면 하는 부분:
```

실제 답변은 우선 이 대화로 전달해도 됩니다. 이 공개 문서에는 기본 방향 선택만 기록했습니다. 과제별 답변란은 아직 비어 있으며 상세 관찰 결과 보고서가 아닙니다.

선택된 순서형을 기준으로 제품 연결·기존 그래프 G1~G3 처리 계획을 구체화합니다. 추가 관찰 결과가 오면 필요한 문구·동선을 보완합니다. 이 양식 작성은 운영 배포·병합 승인이나 APK 실기기 검증을 뜻하지 않습니다.
